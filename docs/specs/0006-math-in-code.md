# 0006: コードブロック内の `$` が数式として描画される

- 対応issue: [0006](../issues/0006-math-in-code.md)
- 状態: draft
- 作成日: 2026-09-19

## 目的

いま `` `$x^2$` `` やコードフェンス内の `$x_i$` は、コードとして表示されず
KaTeXで描画される。数式エディタでLaTeXの書き方を説明する文書が書けない。

数式をmarkedの前に退避する順序は設計上の約束なので変えない。退避の**対象から
コード部分を外す**ことで直す。

## 仕様

### 1. 退避の前にコード部分を避ける

`renderMarkdown.ts` の `extractFormulas` を、ソース全体に正規表現をかける形から
**コード領域を飛ばして残りにだけかける**形に変える。

コード領域と見なすのは次の2つ。

| 種類 | 記法 |
|---|---|
| コードフェンス | 行頭の ` ``` ` または `~~~` で始まり、同じ記号で閉じるまで（閉じないまま文書が終わる場合は末尾まで） |
| インラインコード | 1つ以上の連続するバッククォートで始まり、**同じ個数**のバッククォートで閉じるまで |

バッククォートの個数を合わせるのは、`` `` `$x$` `` `` のような入れ子の記法を
取り違えないため。

処理の順序:

1. ソースをコード領域とそれ以外に切り分ける。
2. コード領域**以外**にだけ既存の `MATH_PATTERN` を適用して数式を退避する。
3. 以降は現在と同じ（marked → DOMPurify → 数式の差し戻し）。

コード領域はプレースホルダに置き換えない。markedにそのまま渡す（markedが
コードとして処理する）。数式の番号付けは文書全体を通して連番のままにする。

### 2. 行頭4スペースのインデントコードは対象にしない

Markdownには4スペースのインデントによるコードブロックもあるが、箇条書きの
継続行と見分けるにはリスト構造の解釈が必要で、自前の走査では取り違える。
今回は扱わない。issueに残さず、この仕様の「スコープ外」として記録する。

### 3. 既存の挙動は変えない

次はこれまで通り動く（[0014](0014-unit-tests.md) のテストで固定済み）。

- 通常の本文中の `$...$` と `$$...$$`
- `$100 から $200`（通貨表記を数式にしない）
- `\$` のエスケープ
- `$$` を `$` より先に解釈する
- `_` や `*` を含むLaTeXがMarkdownの強調に壊されない

### 対象ファイル

| ファイル | 変更内容 |
|---|---|
| `src/lib/renderMarkdown.ts` | コード領域を避けて数式を退避する。コード領域の走査はこのファイル内の非公開関数として書く |
| `src/lib/renderMarkdown.test.ts` | 0014で `it.fails()` にしてある2件を通常の `it()` に裏返す。バッククォート3連の中に ``` ` ``` を含む場合、閉じないフェンス、コードの前後に本物の数式がある場合を足す |
| `scripts/verify-ui.mjs` | プレビューの `code` 要素の中に `.katex` がないことの確認を足す |

## 受け入れ基準

- [ ] `` `$x^2$` `` と打つと、プレビューに `$x^2$` がコードの見た目で出る（数式にならない）
- [ ] コードフェンス内の `$x_i$` が、そのままの文字列で出る
- [ ] 閉じていないコードフェンス以降の `$...$` が数式にならない
- [ ] コードブロックの前後にある本物の `$...$` はこれまで通り数式になる
- [ ] `$$...$$` のブロック数式がコードの直後にあっても正しく描画される
- [ ] 0014で書いた既存テスト（通貨・`\$`・`$$`優先・強調・サニタイズ）が全部通ったまま
- [ ] `npm test` が通り、`it.fails()` の項目が残っていない
- [ ] 実機で、プレビューの `code` 要素の中に `.katex` が1つもない
- [ ] `npm run build` と `npm run lint` が通る

## 検討したが採らなかった案

- **markedのlexerでトークン化し、テキストトークンだけを対象にする。** 取りこぼしは
  減るが、トークン列を歩いてテキストを差し替え、再びHTML化する経路が要る。
  markedの内部構造への依存が濃くなり、バージョン更新のたびに壊れうる。
- **コード領域もプレースホルダに退避して後から戻す。** 数式と同じ仕組みで書ける一方、
  戻す位置がサニタイズ後になるため、コード内のHTMLをこちらでエスケープする責任を
  負う。コードはmarkedに任せるほうが安全。
- **数式記法を `$` から変える。** 既存文書と利用者の慣れを壊す。

## スコープ外

- 行頭4スペースのインデントコードブロック（2. の理由）。
- `\(...\)` `\[...\]` などの別記法への対応。
- コードブロックのシンタックスハイライト。
