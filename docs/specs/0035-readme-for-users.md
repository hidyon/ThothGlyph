## 目的

いまのREADMEは28行中17行が開発の手順で、使う人に向けた記述は冒頭の4行しかない。
しかもその4行が「書いたソースはクリップボードにコピーして持ち出す」で止まっており、
0012・0034で入ったファイルの読み書きも、自動保存も、公式の挿入も、検索も、
英語表示も載っていない。**READMEを読んだだけでは何ができるか分からない。**

書き直して、**開いた人が「何ができて、どう書き始めるか」を先に読める**ようにする。
開発の手順は残すが、入口までにして詳細は既存の文書へ送る。

## 現状の実測

- パレットの実データを数えた: **記号7グループ88件・公式12分類60件**。
  タブは記号7つ＋`公式` で**8つ**。
- 現在のコマンドは5つ（`npm run dev` / `npm run build` / `npm test` /
  `npm run lint` / `node scripts/verify-ui.mjs`）。READMEの表は**`npm test` が漏れて4つ**。
- リポジトリ内の文書: [docs/requirements.md](../requirements.md)、
  [architecture.md](../architecture.md)、[functional-spec.md](../functional-spec.md)、

## 仕様

READMEを次の構成にする。**上から3分の2が使う人向け、残りが開発者向け**。

```
[アイコン] # matheditor            … アイコンを添えた見出しと1行の紹介
（3行の要約）                      … 何をする道具か
[スクリーンショット（広い画面）]     … 開いたところが一目で分かる
## できること                      … 機能の一覧（表）
## 書き方                          … 数式の書き方と、パレット・検索・公式の使い方
## 保存と持ち出し                  … 自動保存、.mdの読み書き、コピー
## 表示                            … ダークモード、日本語/English
      [ダーク] [スマートフォン]      … 画像2枚を並べる
## 開発                            … 4行（devcontainerで開く／コマンド1つ／CLAUDE.mdとdocs/へ）
```

### アイコンとスクリーンショット

**アイコン**は既にある `public/favicon.svg`（[0019](0019-app-icon.md) で作った

**スクリーンショットは3枚**を `docs/screenshots/` に置く。

### 日本語表現の見直し（ユーザーの指摘で実施）

書き上げたあと、日本語として分かりやすいかの観点で読み直した。直したのは:

- **事実として破綻していた1箇所**: 「持ち出しは3つ」と書いて、3つ目に
  「ファイルを開く」（＝持ち込み）を並べていた。**外へ持ち出す2つ**と
  **外から持ち込む1つ**に分け、持ち込みには確認が出ることも書いた。
- **体言止めの連続をやめた**（「`$$...$$` で行を変えて。」など）。読点で終わる文が
  続くと、何が主語なのか追えなくなる。
- **主語が落ちていた説明を補った**（「押すとカーソル位置に入る」→
  「ボタンを押すとカーソル位置に挿入される」）。
- **抽象的な動詞を具体例に置き換えた**。「包める記号は選択部分を包む」→
  「選んだ文字が記号の中に入る（`x + 1` を選んで `√` を押すと `\sqrt{x + 1}`）」。
  この例と検索の例（`積分` / `\int`）は、**書いてから実データで確かめた**
  （`insertSnippet` と `searchPalette` を呼んで、7件・16件当たることを見た）。
- **表に見出しを付けた**（空のヘッダ行はGitHubで意味のない空欄になる）。
- 単位を functional-spec に揃えた（記号は「個」、公式は「件」）。
- パレットの件数を固定するテストは、`palette.test.ts` と `formulas.test.ts` の
  末尾に足した。**READMEの数字が実データとずれたら `npm test` が落ちる。**

## 検討したが採らなかった案

- ~~**スクリーンショットを載せる**~~ → **載せることにした**（ユーザーの指示）。
  撮り直しの手間は `scripts/make-screenshots.mjs` で吸収する。
- **READMEのために新しいアイコン画像を作る**。`public/favicon.svg` をそのまま
  参照すれば、直したときに片方だけ古くなることがない（index.html と同じ判断）。
- **英語版READMEを併記する**。画面は英語に対応しているが、リポジトリの文書は
  日本語で書く方針（CLAUDE.md「言語」）。
- **機能の説明をREADMEに厚く書く**。[functional-spec.md](../functional-spec.md) と
  二重になり、片方が必ず古くなる。READMEは1行＋リンクにとどめる。
- **件数をREADMEに書かない**（「たくさんの記号」等でぼかす）。数字がないと
  規模が伝わらない。代わりに**単体テストで数を固定**して、古くなったら落とす。
