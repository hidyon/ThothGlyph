# 0034: .mdファイルの書き出し

- 対応issue: [0034](../issues/0034-file-save.md)
- 状態: implemented
- 作成日: 2026-09-20

## 目的

いま文書を持ち出す手段はクリップボードへのコピーだけで、貼り付け先を開いて
いない場面では使えない。[0012](0012-file-load.md) で読み込めるようになったので、
**書いたものを `.md` ファイルとして保存し、次にその場で開き直せる**ようにして
往復を閉じる。

## 置き場所の実測

0012で「ファイルを開く」を置いたソースペインの見出し行に、もう1つ並べる。
2つ目のボタンをDOMに入れて測った結果（ヘッドレスChromium、高さ667px）:

| 画面幅 | 見出し行の高さ（ソース/プレビュー） | textareaの高さ | 横スクロール |
|---|---|---|---|
| 1440px | 30 / 30px（変化なし） | 488px（変化なし） | なし |
| 600px | 30 / 30px（変化なし） | 227px（変化なし） | なし |
| 375px | 30 / 30px（変化なし） | 207px（変化なし） | なし |
| 360px | 30 / 30px（変化なし） | 207px（変化なし） | なし |

幅360pxでの内訳は、見出し「ソース」37px＋gap 8px＋新しいボタン106px＋gap 8px＋
「ファイルを開く」106px＝**265px / 360px**（余白95px）。英語は
`Source` 49px＋98px＋83px＝**246px**。**0033で下げた基準（360px）を満たす。**

文言の候補も同じ条件で測った。

| 候補 | 日本語 | 英語 |
|---|---|---|
| ファイルに保存 / Save to file | 106px | 98px |
| ダウンロード / Download | 94px | 89px |
| 保存 / Save | 46px | 55px |

`保存` は最も短いが、ツールバーに出ている自動保存の表示（`保存しました 12:34`）と
紛らわしいので採らない。**`ファイルに保存` / `Save to file`** にする。
幅360pxでも上の265pxで収まるため、0033のような短縮は要らない。

## 仕様

### ボタン

ソースペインの見出し行に `ファイルに保存` / `Save to file` を置く。
並びは **`ファイルに保存` → `ファイルを開く`**（左から）。押すと、いま編集中の
ソースが `.md` ファイルとしてダウンロードされる。確認ダイアログは出さない
（読み込みと違い、**何も失わない操作**だから）。

### ファイル名

1. ソースの**先頭の見出し行**（`#` が1〜6個＋空白で始まる最初の行）の文字を使う。
   例: `# 二次方程式の解の公式` → `二次方程式の解の公式.md`
2. 見出しがない、または名前が空になるときは `document.md`。
3. ファイル名に使えない文字（`/ \ : * ? " < > |` と制御文字）は `-` に置き換える。
4. 前後の空白と `.` を落とす（`...md` のような名前を作らない）。
5. 50文字を超えたら50文字で切る（長い見出しがそのままファイル名になると、
   OSによっては保存に失敗する）。

見出しの中のMarkdown記法（`**強調**`、`` `コード` ``、`$数式$`）を
**剥がす処理は入れない**。剥がし方の正しさが別の問題になるため。
ただし3の置き換えはそのあとに効くので、`# **強調**` は `--強調--.md` になる
（`*` はWindowsで使えない）。`$` や `` ` `` はそのまま残る。

3の置き換えの結果が区切り文字（`-`）と空白・`.` だけになるときも
`document.md` にする（`# ///` → `---` は中身のない名前）。

### 書き出す中身

- エディタの内容をそのまま。BOMは付けない。改行は `\n`（[0012](0012-file-load.md) で
  読み込み時に揃えているので、編集中の内容は常に `\n`）。
- 末尾に改行がなければ1つ足す（行指向の道具で開いたときに最終行が欠けないように）。
- MIMEタイプは `text/markdown;charset=utf-8`。

### 断るとき

本文が空白だけのときは書き出さず、`書き出す内容がありません` /
`There is nothing to save` を結果の枠（ツールバー、0012と同じ）に出す。
空のファイルを作っても使い道がなく、保存先を選ぶ手間だけが残る。

### 結果の表示

書き出せたら `<ファイル名> を保存しました` / `Saved <ファイル名>` を
結果の枠に数秒出す（0012の読み込みと同じ枠・同じ消え方）。

### 対象ファイル

- `src/lib/downloadName.ts`（新規） — ソースからファイル名を作る純粋関数
  `fileNameFor(source)`、書き出す中身を整える `contentFor(source)`。
- `src/lib/downloadName.test.ts`（新規） — 上の単体テスト。
- `src/components/Editor.tsx` — 見出し行に2つ目のボタンを足す。
- `src/App.tsx` — Blobを作って `<a download>` で落とし、結果を表示する。
  ブラウザのAPIに触る部分はここに置く（0012と同じ切り分け）。
- `src/lib/messages.ts` — 文言を2言語で足す（ボタン、結果2種）。
- `scripts/verify-ui.mjs` — 区分 `file-save` を新設する（既存の区分は消さない）。
- `docs/` の4文書。

## 未確認の前提

- Playwrightの `page.waitForEvent('download')` で、`suggestedFilename()` と
  保存された中身の両方を読めると考えているが、このプロジェクトで
  ダウンロードを検証するのは初めてなので確かめていない。
  読めなければ、`<a download>` のクリックを横取りして属性とBlobの中身を
  見る形に検証を変える（実装は変えない）。
- `URL.createObjectURL` + `<a download>` はdevcontainerのChromium（ヘッドレス）でも
  ダウンロードイベントを発火させると考えているが、確かめていない。
- ファイル名に日本語を含むダウンロードが、ヘッドレスChromiumで
  そのままの名前になる（エスケープされない）と考えているが、確かめていない。
  崩れる場合は、検証側で名前の比較をゆるめるのではなく、
  **仕様の「ファイル名」を実測に合わせて書き直す**。

## 実装で分かったこと（未確認の前提の答え）

- **`waitForEvent('download')` で名前と中身の両方を読めた。**
  `suggestedFilename()` と `createReadStream()` で検証できる。
- **`<a download>` はヘッドレスChromiumでもダウンロードを発火した。**
- **日本語のファイル名はそのまま出た**（`二次方程式の解の公式.md`）。
  仕様のファイル名規則を書き直す必要はなかった。
- **仕様の中に食い違いが1つあった。** 「使えない文字（`* ...`）を `-` に置き換える」と
  「記法はそのまま残るので `*` が残るのは許容する」を両方書いていた。
  `*` はWindowsで使えないので置き換えるほうを正とし、
  `# **強調**` は `--強調--.md` になる（`$` は残る）。仕様の本文も直した。
- **置き換えの結果が区切り文字だけになる場合**（`# ///` → `---`）を仕様が
  拾えていなかった。中身のない名前なので `document.md` に落とす、と決めて実装した。
- **見出し行のボタンは1つのまとまり（`.pane__actions`）にして右端へ置く。**
  見出しと2つのボタンを並べて `space-between` に任せると、ボタン同士が
  離れて中央に浮いた（幅1440pxのスクリーンショットで発見）。

## 検討したが採らなかった案

- **File System Access API（`showSaveFilePicker`）で上書き保存**。開いたファイルへ
  そのまま書き戻せるが、Safari・Firefoxが対応していない。0012・0034の
  「やらないこと」にも書いてある。
- **ツールバーに置く**。幅360pxで余地がない（0033の実測）。
- **保存前に名前を尋ねる**。ブラウザ側の保存ダイアログ（設定によっては出る）と
  二重になる。まず自動で決めた名前で出し、要否は使ってから判断する。
- **`保存` という短い文言**。ツールバーの自動保存の表示と紛らわしい（上の実測）。
