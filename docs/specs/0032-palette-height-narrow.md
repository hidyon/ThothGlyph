# 0032: 狭い画面でパレットの高さに蓋をする

- 対応issue: [0032](../issues/0032-palette-height-narrow.md)
- 状態: implemented
- 作成日: 2026-09-20

## 目的

狭い画面で、パレットが編集領域を食い潰している。幅375px・高さ667pxで公式タブを
開くと、**textareaに残るのは38px（約1.5行）**しかない。記号や公式を足すたびに
悪くなる構造なので、**件数に依存しない上限**を与える。

## 現状の実測（2026-09-20）

`npm run dev` + ヘッドレスChromiumで、タブを切り替えながら実測した。

| 公式（三角比・最大） | **324px** | 36% | — |
| 公式（ベクトル） | 269px | 30% | 259px |

幅375px × 高さ667px（スマートフォン相当）:

|---|---|---|---|---|

公式タブでは**ページ全体が縦にはみ出す**（`scrollHeight` 692px > 667px）。

内訳（幅375px・公式タブ）: 1段目のタブ行98px（4行）＋ 2段目のタブ行132px（4行）＋
一覧247px（4行）。**高さの2/3をタブが使っている。**

広い画面（幅1440px）は94〜157pxで、issueの「困っていない」どおり。

## 仕様

**幅720px以下**（既存の `@media (max-width: 720px)` と同じ境目。ここで上下2分割に
なりツールバーも詰まる）でのみ、パレットの組み方を変える。広い画面は変えない。

### 1. タブを折り返さず、横スクロールにする

1段目（記号のグループ＋公式）と2段目（公式の12分類）を、どちらも1行に固定する。

- 1段目: `.palette__bar > .palette__tabs` の `display: contents` を狭い画面でやめ、
  `flex` に戻して `flex-wrap: nowrap; overflow-x: auto` にする。
  **検索欄（[0011](0011-palette-search.md)）はタブと同じ行に残す**。タブ側だけが
  スクロールし、検索欄は右端に固定幅で居座る。
- 2段目: `.palette__tabs--sub` も同じく `nowrap` + `overflow-x: auto`。

タブが増えても**行数が増えない**。これが「際限なく伸びない」の中身。

### 2. 記号・公式の一覧に高さの蓋をする

`.palette__items` に `max-height: min(98px, 15vh)` と `overflow-y: auto` を与える。
98pxは記号ボタン2段ぶん（36px × 2 + gap 6px + padding 20px）の実測値。
`15vh` を併記するのは、横向きなど**画面自体が低いとき**に比率で効かせるため。

[0011](0011-palette-search.md) が検索結果に `min(168px, 21vh)` の蓋をしたのと同じ
考え方を、通常の一覧にも広げる（あちらの蓋はそのまま残す）。

入りきらない記号は**縦スクロールでたどれる**。横断検索（0011）もあるので、
「スクロールしないと見えない記号がある」ことが行き止まりにはならない。

### 3. 結果として決まる高さ

タブ1行 + （公式なら）2段目1行 + 一覧の蓋98px。**どのタブ・分類を選んでも
ほぼ同じ高さになり、件数では変わらない。**

## 未確認の前提（実装で確かめた結果）

- **`display: contents` を狭い画面だけ `flex` に戻しても、検索欄がタブと同じ行に残ること**
  → 残った。検索欄は `.palette__bar` の直接の子のままなので、幅375pxでも親は
  `palette__bar` のまま。ただし `.palette__tabs` に `min-width: 0` が要った
  （flexの子は既定で縮まないので、付けないとタブ全体が検索欄を押し出す）。
- **`.palette__items` の蓋が検索結果の蓋と衝突しないこと** → **衝突した。**
  同じ詳細度でこちらが後ろにあるため、そのままだと検索結果まで98pxに縮む。
  `.palette__items:not(.palette__items--results)` で除外し、0011の
  `min(168px, 21vh)` を残した。
- **`align-content: flex-start` が要るか** → 要った。蓋より中身が低いとき、
  ボタンが縦に間延びする。
- **タッチでの横スクロール** → 仕様どおり検証から外した。Chromiumでは
  `scrollWidth > clientWidth` とプログラムからのスクロールで到達できることまでを見た。

## 検討したが採らなかった案

- **狭い画面でパレットを折りたたむ（見出しだけ出して、押すと開く）。** パレットは
  「押して入れる」道具なので、使うたびに開く操作が増える。開いたときの高さは
  結局いまと同じで、**開いている間は同じ問題が起きる**。
- **記号や公式を減らす。** issueの「やらないこと」。[0029](0029-greek-complete.md)・
  [0030](0030-formula-library-more.md)で足したばかり。
- **パレット全体を縦スクロールにする（タブごと巻き取る）。** タブが見えなくなる
  瞬間があり、いまどのグループを見ているか分からなくなる。蓋をするのは一覧だけにする。
- **広い画面でも同じ組み方にする。** 幅1440pxでは94〜157pxで収まっており、
  横スクロールを足すと**見えているものを見えなくする**だけになる。
