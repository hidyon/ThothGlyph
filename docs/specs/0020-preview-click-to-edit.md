# 0020: プレビューでクリックした箇所をパレットで編集する

- 対応issue: [0020](../issues/0020-preview-click-to-edit.md)
- 状態: implemented
- 作成日: 2026-09-22

## 目的

いまプレビューは見るだけで、操作の起点にならない。描画された数式を見て
「この分数を直したい」と思っても、左のソースからその数式を目で探し、カーソルを
移してから編集する必要がある。文書が長いほどこの往復が重い。

このissueのあと、**プレビューの数式をクリックすると、ソースのその数式の中身が
選択された状態になる**。そのままパレットの記号を押せば、0009で決めた
「選択範囲を囲む／直後に挿入する」の規則どおりに編集が入る。プレビューが
ソースへの入口になる。

また、数式1つ1つが「元ソースのどこから来たか」をHTMLに持つようになる。
[0044](../issues/0044-equation-numbers.md)（式の番号と参照）は、この土台の上に
番号とアンカーを載せる。

## 仕様

### 1. 数式に元ソースの位置を持たせる

`renderMarkdown` が数式を差し戻すとき、KaTeXの出力を `<span>` で包み、
**元ソース上の「中身の範囲」**をデータ属性で持たせる。

```html
<span class="math-anchor" data-math-start="123" data-math-end="145">…KaTeXの出力…</span>
```

- `data-math-start` / `data-math-end` は、元ソース（退避前）の文字オフセット。
  `source.slice(start, end)` が**そのままKaTeXへ渡したLaTeX文字列**になる。
  すなわちデリミタ（`$` / `$$`）の内側で、前後の空白・改行を除いた範囲。
- 現在 `extractBlocks` は数式の「元ソースでの開始位置と長さ」を既に数えている
  （`offsets` を作るため）。そこから中身の範囲を出す。`$$` の場合は
  デリミタ2文字ぶん内側に入り、`trim` で落ちた空白の長さを両端から詰める。

入力と出力の例（`source` の先頭からのオフセット）:

| ソース | 数式の中身 | start | end |
|---|---|---|---|
| `あ $x+1$ い` | `x+1` | 3 | 6 |
| `$$\nf(x)=1\n$$` | `f(x)=1` | 3 | 9 |
| `$$ x $$` | `x` | 3 | 4 |

包むのは**サニタイズの後**（パイプラインの7）。ラッパはKaTeXの出力と一緒に
差し戻されるので、DOMPurifyは通らない。属性に入るのは自前で数えた整数2つだけで、
利用者の入力は入らない。

**描画キャッシュのキーは変えない。** ラップはキャッシュされたHTMLの外側で行う
ので、同じLaTeXが別の位置にあってもキャッシュはこれまでどおり効く。

### 2. クリックするとソースのその範囲が選択される

プレビューのクリックを `Preview` が受け、`event.target.closest('.math-anchor')` で
数式を探す。見つかったら `data-math-start` / `data-math-end` を `App` へ渡す。

`App` は:

1. `textarea.focus()` してから `setSelectionRange(start, end)` を呼ぶ。
   **ここではフォーカスを奪う**（0043の検索と違い、他に打ち込む先がない。
   フォーカスが無いとChromiumは選択を描画せず、選ばれたことが画面で分からない）。
2. その範囲がtextareaの表示範囲の外にあるときだけスクロールを寄せる
   （`handleSelectRange` と同じ計算・同じ条件）。**見えているならスクロールしない。**
   寄せるとエディタのscrollが0010の同期を動かし、いま見ている数式が
   プレビューの中で動いてしまうため。
3. クリックされた数式を「選択中」として覚える（下の印）。

選択するのは**中身だけ**で、デリミタは含めない。含めると、囲む記号
（`\sqrt{…}`）を押したときに `\sqrt{$x$}` となり壊れる。中身だけなら
`\sqrt{x}` になり、0009の挙動にそのまま乗る。

クリックの対象は数式だけ。本文・見出し・箇条書き・グラフをクリックしても
何も起きない（ラッパが無いので `closest` が空振りする）。

### 3. 選ばれていることが画面で分かる

- **ソース側**: textareaの選択がブラウザの選択色で描画される
  （フォーカスを奪うので描画される。実測済み）。
- **プレビュー側**: クリックした数式に `math-anchor--active` が付き、
  **輪郭（`outline`）**が出る。色はリンクと同じアクセント色（`--accent`）、
  太さ2px、`outline-offset: 2px`。**`outline` はレイアウトを動かさない**ので、
  数式の位置も行の高さも変わらない。
- 印は**ソースが編集されるまで**残す（`html` が変わったら消す）。
  編集すればオフセットがずれ、どこを指していたかの意味が失われるため。
- **クリックできることを見た目で示す**: `.math-anchor` に `cursor: pointer`、
  ホバーで薄い背景（`--accent` の10%相当。ダークでも同じ規則）。
  こちらもレイアウトは動かさない（背景色だけ）。

### 4. 画面に足す要素はない

ボタン・入力欄・帯を1つも足さない。増えるのは `outline` と背景色だけで、
どちらも既存の要素の内側に描かれる。したがって幅の取り合いは起きない。
ただし**輪郭は数式の外側2pxに出る**ので、ペインの端の数式で横スクロールが
出ないことは検証で確かめる。

## 未確認の前提

- **ブロック数式を `<span>` で包んでも表示が変わらない。**
  実測で `p > span.katex-display` の構造であることを確認済み（`span` の入れ子に
  なるだけ）。ただしダークやフォント到着後の見え方は実装して確かめる。
- **インライン数式の当たり判定が十分な大きさを持つ。** `.katex` の高さは
  行の高さ程度あるはずだが、`\mu` のような背の低い記号で押しにくくないかは
  実装して測る（ボタンの中心が自分に当たるかを見る既存のチェックと同じ手）。
- **`outline` がプレビューの横スクロールを増やさない。** 端にある数式で
  2px外に出るため、幅の狭い画面で確かめる。

### 実装して分かったこと

- **当たり判定は足りなかった。** inline のまま包むと、数式の隙間のクリックが
  親の段落に取られる（Playwrightのhit-target checkが `<p> intercepts pointer
  events` で落ちた）。`display: inline-block` にして解決。
  **レイアウトは動かない**ことを実測した（幅1440px・サンプル文書で、
  段落の上端がすべて同じ、プレビューの高さ1016pxも同じ。ラッパの高さだけ
  19px→28pxに広がり、押しやすくなった）。
- **ブロック数式のラッパは `display: block`** にする（`math-anchor--block`）。
  inline のままだと輪郭が行ボックスに沿って引かれ、式とずれた位置に出る。
- **印を消す場所は効果ではなく `setSource` の側。** `useEffect` で
  `source` を見て消す形はlintが止める（`set-state-in-effect`）。
  `setSource` を包む `updateSource` を唯一の入口にして、そこで消す。
- 幅1440pxで、ダークでもホバーの地（`--accent-soft`）と輪郭が見えることを
  スクリーンショットで確かめた。

## 検討したが採らなかった案

- **プレビュー上で直接編集する（WYSIWYG）** — ソースが唯一の正である構造を
  崩す。issueの「やらないこと」にも挙がっている。
- **数式より細かい粒度（分数の分母まで指す）** — KaTeXの出力から部分式の
  ソース位置は取れない。まず数式1つ単位で使いものになるか見る。
- **デリミタを含めて選択する** — 囲む記号を押したときに `\sqrt{$x$}` となり
  壊れる。中身だけなら0009の挙動にそのまま乗る。
- **クリックでカーソルを先頭に置くだけ（選択しない）** — パレットの
  「選択範囲を囲む」が使えず、「プレビューから編集する」の半分しか実現しない。
- **`data-line` を使い回す** — 行単位では同じ行の2つめの数式を指せない
  （サンプル文書の1行に数式が2つある箇所がある）。
- **フォーカスを奪わない（0043と同じ）** — 選択がChromiumで描画されず、
  選ばれたことが画面で分からない（0043はそのために塗る層を足した）。
  クリックの起点がプレビューなので、奪って困る入力先がない。

## スコープ外

- 本文（見出し・箇条書き・表）のクリック。まず数式に絞る。
- グラフブロックのクリック。
- 数式の上でのドラッグによる文字選択（コピー）。クリック（`click`）だけを見る。
- 式の番号と参照（[0044](../issues/0044-equation-numbers.md)）。このissueが作る
  ラッパの上に載せる。
