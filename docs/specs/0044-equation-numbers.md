# 0044: 式に番号を振って参照できない

- 対応issue: [0044](../issues/0044-equation-numbers.md)
- 状態: approved
- 作成日: 2026-09-22

## 目的

ノートでは「式(1)を(2)へ代入すると」のように式を番号で指す。いまは `\tag{1}` で
手で番号を振れるが、**式を1つ挿入しただけで全部ずれる**。参照のほうも `(1)` と
書いた文字列でしかなく、飛べないし、ずれても気づかない。

このissueのあと、**番号を振りたい式に `\tag{名前}` と書けば、番号は文書順に
自動で振られる**。本文からは `[(1)](#eq-名前)` と書いて参照でき、式を足し引き
しても番号と参照が揃ったままになる。参照をクリックすればその式へ移動する。

**採番は意図した式だけ**に入る。`\tag` を書いていない式には番号が付かない。

## 仕様

### 1. 記法

**新しい記法を作らない**（[R7](../requirements.md#r7-markdownとして正しく扱える)）。
すでにある標準の道具を2つ借りる。

| 何を | 借りる道具 | 持ち出した先での見え方 |
|---|---|---|
| 採番の印とラベル | LaTeXの `\tag{名前}` | 式の右に `(名前)` が出る |
| 参照 | Markdownのリンク `[(1)](#eq-名前)` | `(1)` というリンクとして読める |

`{#eq:quad}` のような独自のラベル記法は採らない。

### 2. 採番

**ブロック数式（`$$...$$`）のうち、LaTeXに `\tag{ラベル}` を含むもの**を、
文書順に1から採番する。

- ラベルは `{` `}` と改行を含まない1文字以上の文字列。前後の空白は落とす。
  日本語も使える（`\tag{解の公式}`）。
- **インライン数式の `\tag` は対象外。** KaTeXが
  `ParseError: KaTeX parse error: \tag works only in display equations` を返す
  （実測）。いままでどおり赤字で出る。
- 同じラベルが2つ以上あるときは、**どちらも採番するが、参照は最初のものを指す**。
- コードブロック・インラインコードの中は数式にならないので、採番もされない。

### 3. 番号の描画

**`\tag{ラベル}` はLaTeXから取り除いてKaTeXへ渡し、番号はHTMLの要素として
式の右に出す。**

```html
<span class="math-anchor math-anchor--block math-anchor--numbered" id="eq-1"
      data-math-start="…" data-math-end="…">
  …KaTeXの出力…<span class="eq-number">(1)</span>
</span>
```

**KaTeXの `\tag` に番号を出させない理由**: `\tag` は `mtable width="100%"` を作り、
幅が足りないと**式と番号が重なる**。幅360pxで長い式（サンプル文書の正規分布の
密度関数）に `\tag{1}` を付けて実測したところ、`\right)` と `(1)` が重なり、
横スクロールも出ないので読めないまま固定された（スクリーンショットで確認）。
幅600px・1440pxでは重ならない。

ラッパを `display: flex; align-items: center` にし、式の側に `min-width: 0` と
`overflow-x: auto`、番号の側に `flex-shrink: 0` を置く。こうすると幅が足りない
ときは**式のほうがブロック内で横スクロールし、番号は右端に残る**。

寸法（幅1440 / 600 / 360pxのいずれでも同じ。日本語、本文フォントで実測）:

| 番号 | 幅 |
|---|---|
| `(1)` | 22.7px |
| `(10)` | 32.8px |
| `(100)` | 43px |

式との間の余白は16px。**幅360pxでは、式に残る幅が 312 − 22.7 − 16 = 273.3px**
（プレビューの内側312pxから引いた値）。番号のない式は今までどおり312px使える。

### 4. アンカー

番号付きの式のラッパに `id="eq-<番号>"` を付ける（`eq-1`, `eq-2`, …）。

**HTMLに入るのは自前で数えた数字だけで、ラベル（利用者の入力）は入らない。**
0020のデータ属性と同じ理由で、サニタイズを迂回する経路（
[アーキテクチャ4節](../architecture.md#4-サニタイズの境界)）を広げない。

### 5. 参照

Markdownのリンクのうち、**リンク先が `#eq-` で始まるもの**を参照とみなす。

- ラベルが採番済みなら、**リンク先を `#eq-<番号>` に差し替える**。
- **リンクの文字列が `(数字)` の形なら、その数字を現在の番号に差し替える。**
  それ以外の文字列はそのまま残す（`[式A](#eq-a)` は `式A` のまま）。
- ラベルが見つからない（採番されていない・打ち間違い）ときは**何もしない**。
  リンクはそのまま残り、クリックしても飛ばない。

入力と出力の例（`\tag{quad}` が1番、`\tag{mean}` が2番に採番されている文書）:

| ソース | プレビューでの表示 | リンク先 |
|---|---|---|
| `式 [(1)](#eq-quad) より` | 式 (1) より | `#eq-1` |
| `式 [(5)](#eq-mean) より` | 式 (2) より | `#eq-2` |
| `[解の公式](#eq-quad) を見よ` | 解の公式 を見よ | `#eq-1` |
| `式 [(1)](#eq-typo) より` | 式 (1) より（飛べない） | `#eq-typo` のまま |

### 6. 参照をたどる

プレビューの中で `#eq-` で始まるリンクを押すと、**プレビューの中でその式へ
スクロールし、式に0020の輪郭が出る**。ブラウザのハッシュ遷移（URLが変わる）は
起こさない。

- **ソースのカーソルと選択範囲は動かさない。** 読み返している最中に編集位置を
  失わないため（[0010](0010-scroll-sync.md) のスクロール同期と同じ考え）。
  0020のクリック（数式を押したとき）はソースを選ぶが、参照はたどるだけ。
- 飛び先が無い（採番されていないラベル）リンクは、押しても何も起きない。

### 7. 実装の構造

**参照リンクは、数式・グラフと同じくプレースホルダへ退避する**
（`%%MATHEDITOR_REF_n%%`）。

- 理由は[0010](0010-scroll-sync.md)の行番号。`[(1)](#eq-quad)` を
  `[(2)](#eq-2)` に置き換えると**長さが変わる**ので、マスク後の位置と元の位置の
  対応表（`OffsetMap`）が壊れる。退避なら既存の `replaced()` が対応点を記録する。
- 退避はコードの外側だけ（`splitByCode` の外）。コードの中のリンクは対象外。
- ラベル→番号の対応は**文書を最後まで見ないと決まらない**（前方参照がある）ので、
  退避のときは中身を控えるだけにし、差し戻しのときに番号を引く。
- **差し戻すHTMLはDOMPurifyを通す**（グラフと同じ。[0037](0037-graph.md)）。
  抜け道はKaTeXの出力だけに保つ。
- リンクの文字列は**文字として出す**。強調などのMarkdown記法は解釈しない
  （`[**(1)**](#eq-a)` の `**` は文字のまま出る）。

## 未確認の前提

- **`\tag` を2つ書いた式でKaTeXがどう振る舞うか。** 最初の1つをラベルとして
  扱うつもりだが、KaTeX側が後ろを使う可能性がある。実装の前に測る。
- **ラッパをflexにしても、KaTeXのブロック数式の中央寄せと上下の余白
  （`margin: 1.2em 0`）が保たれるか。** `.katex-display` はブロック要素なので
  flexの子として振る舞いが変わりうる。
- **番号付きの式でも0020の輪郭が式と番号の両方を囲むか。** ラッパに付く
  `outline` なので囲むはずだが、flexにしたぶん形が変わる。
- **`\tag` を外したLaTeXがキャッシュのキーとして正しく働くか。**
  同じ式に別のラベルを付けた2件は、`\tag` を外すと同じキーになる。番号は
  ラッパ側に出るので、キャッシュされたKaTeX出力を共有してよいはず。

## 検討したが採らなかった案

- **`\tag{1}` のように数字を書いて自動で振り直す** — 参照先が番号に依存する
  ので、式を足すと参照リンクの書き換えが必要になり、issueの
  「参照も揃ったままになる」を満たせない。
- **`\tag{}`（空）を印にする** — 識別子がないので上と同じ問題。持ち出した先で
  `()` と出るのも意味が落ちる。
- **`{#eq:quad}` のような独自のラベル記法** — R7に反する。持ち出した先で
  「読めないゴミ」になる。
- **KaTeXの `\tag` に番号を描かせる** — 幅360pxで式と番号が重なる（実測）。
- **`id` にラベルをそのまま入れる** — 利用者の入力がサニタイズを迂回して
  HTMLの属性に入る。番号を使えばその経路を作らずに済む。
  markedがリンク先をpercent-encodeする（`#eq-解の公式` →
  `#eq-%E8%A7%A3%E3%81%AE%E5%85%AC%E5%BC%8F`。実測）ことへの対処も要らなくなる。
- **参照をHTML文字列の上で書き換える** — サニタイズ後のHTMLを正規表現で
  触ることになり、属性のエスケープとテキストの偶然の一致に弱い。
  退避と差し戻しはこのパイプラインに既にある形（数式・グラフ）に乗る。
- **参照をたどったときにソースも選ぶ（0020と同じ動き）** — 読み返している
  最中にカーソルが動く。0010で「スクロールは連動させるがカーソルには触らない」
  と決めた線に合わせる。

## スコープ外

- **章ごとの番号**（`(2.1)`）。まず通し番号で。
- **定理・図表の番号**（[0041](../issues/0041-theorem-blocks.md)）。
- `\tag*{…}`（括弧なしのタグ）。
- **パレットから `\tag{}` を挿入する手段**。記法は手で書く前提。
  画面に要素を足す話になるので別issueに起票する。
- リンクの文字列の中のMarkdown記法（`[**(1)**](#eq-a)` の強調）。
- 参照の一覧・逆参照（「この式を参照している箇所」）。
