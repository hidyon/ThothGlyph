# 0054: 広い画面ではパレットを左の縦帯にする

- 対応issue: [0054](../issues/0054-palette-placement.md)
- 状態: implemented
- 作成日: 2026-09-20

## 目的

広い画面でパレットは横いっぱいの帯として置かれ、**横は大きく余り、縦だけを
奪っている**。幅1440pxでボタンは左から400pxまでしか使わず、検索欄までの
約836pxが空いたまま、高さ94pxを全幅で取る。空いているのは横で、
削られているのは縦——本文が使いたい方向である。

**幅1200px以上では、パレットを左の縦帯にする。** 高さの奪いがゼロになり、
本文（textarea）が幅1440pxで721px → **815px**（+94px、+13%）になる。
代わりにプレビューが720px → 630px（-90px）に狭まる。これは交換であって
ただの得ではないので、下に両方の数値を並べる。

## 実測（仕様を決めるために先に測った）

2026-09-20、devcontainerのChromium、日本語、サンプル文書。
ページにCSSを差し込んで測った（実装前に測るため）。

### 3案の比較（幅1440×900 / 1024×768）

| 案 | 1440pxでのパレット | textarea | プレビュー幅 | 1024pxでどうなるか |
|---|---|---|---|---|
| 現状（上の横帯） | 1440×94px | 721px | 720px | 94px / textarea 589px |
| **A: 左の縦帯180px** | **180×845px** | **815px** | 630px | textarea 683px / プレビュー422px |
| A': 左の縦帯220px | 220×845px | 815px | 610px | プレビュー402px |
| B: タブとボタンを1行に | 1440×57px（基本タブ） | 758px | 720px | **破綻**（下記） |

**B案は幅1024pxで壊れる。** タブ行とボタン行を横に並べると、ボタンの入る幅が
79.5pxしか残らず、ギリシャ小文字（31件）でパレットが**1317px**、
textareaが**32px**になった。タブごとの高さも1440pxで57〜232pxとばらつく
（0032で潰した「件数で高さが変わる」が、広い画面で復活する）。採らない。

**A案は帯の幅で交換の度合いが決まる。** 180pxならタブ名でいちばん長い
`Ωギリシャ大文字`（124.7px）が収まり、プレビューの削りが90pxで済む。
220pxでは削りが110pxに増えるだけで、得るものは同じ（textareaは同じ815px）。
**180pxを採る。**

### A案（180px）を幅ごとに測る

| 幅×高さ | textarea（現状→A案） | プレビュー幅（現状→A案） | グラフ（現状→A案） |
|---|---|---|---|
| 1680×1050 | 871 → **965px** | 840 → 750px | 480×320 → 480×320 |
| 1440×900 | 721 → **815px** | 720 → 630px | 480×320 → 480×320 |
| 1280×800 | 621 → **715px** | 640 → 550px | 480×320 → 480×320 |

**幅1024pxでは、グラフが464px → 374pxまで縮む。** 得る縦94pxに対して
失うものが大きいので、**縦帯にするのは幅1200px以上**と決める
（1200pxならグラフは462×308で、現状の480×320とほぼ変わらない）。
どの幅でも数式の横はみ出し・プレビューの横スクロールは出なかった。

### 縦帯の中身（幅1440px・公式タブ＝いちばん背が高い状態）

- パレットの中身は **959px**、帯の高さは845px → **縦スクロールが出る**。
  横スクロールは出ない。
- 公式の2段目タブ（12分類）は帯の中で**9行に折り返す**。
- 公式のボタンは127.2px幅で、名前も式もはみ出さない。
- 検索欄は帯の幅いっぱいで **155px**。

## 仕様

### 1. 幅1200px以上でパレットを左の縦帯にする

`.app` を縦並びのflexから**2列のグリッド**にする。

```
+--------------------------------------------------+
| ツールバー（全幅のまま）                          |
+--------+-----------------------------------------+
| パレット | ソース              | プレビュー       |
| 180px   |                     |                  |
| （縦）   |                     |                  |
+--------+-----------------------------------------+
```

- パレットの幅は **180px** に固定する（`grid-template-columns: 180px 1fr`）。
- パレットの下線は消し、**右に境界線**を引く。
- 帯は `overflow-y: auto`。中身が高いとき（公式タブ）は帯の中で縦にスクロールする。
- `.panes`（ソースとプレビュー）は残りの幅を半分ずつ分ける。

### 2. 帯の中の並び

上から順に、**タブ8つ（縦）→ 検索欄 → 記号の一覧**。

- タブは縦に積む。文字は**左寄せ**、角の丸めは4隅とも6px
  （横帯のときの「上だけ丸い」は、下に一覧が続く形だったため）。
- [0053](0053-palette-tab-icons.md) のアイコンはそのまま先頭に出る。
- 検索欄はタブの下に、帯の幅いっぱい（155px）で置く。
  右寄せ（`margin-left: auto`）は横帯のための指定なので、縦帯では外す。
- 記号の一覧は検索欄の下。帯の幅で折り返す（基本タブで3行）。

### 3. 幅1199px以下は今のまま

- 1199px以下は現在の横帯。[0032](0032-palette-height-narrow.md)（幅720px以下の
  高さの蓋）も[0053](0053-palette-tab-icons.md)（タブのアイコン）も触らない。
- 切り替えはCSSのメディアクエリだけで行う。**JavaScriptで幅を見ない**
  （リサイズのたびに再描画する状態を増やさないため）。

### 4. 「上のパレット」という文言を直す

サンプル文書に位置を指す文言があり、縦帯では嘘になる。位置に依存しない
言い方に直す。

| ファイル | 今 | 直す先 |
|---|---|---|
| `src/sampleDocument.ts` | 上のパレットのボタンを押すと、… | パレットのボタンを押すと、… |
| `src/sampleDocument.ts`（英語） | Press a button in the palette above to … | Press a button in the palette to … |
| `README.md` | 記号や公式は上のパレットから選んで | 記号や公式はパレットから選んで |

**サンプル文書の先頭行（`# 二次方程式の解の公式`）は変えない**
（実機検証の複数の区分が依存している）。

### 対象ファイル

- `src/index.css` — `.app` を幅1200px以上でグリッドにする。パレット・タブ・
  検索欄の縦帯用の指定を、`@media (min-width: 1200px)` の中に足す。
- `src/sampleDocument.ts` — 日英の文言から「上の」「above」を外す。
- `README.md` — 同じ文言。
- `scripts/verify-ui.mjs` — `placement` 区分を足す（下の受け入れ基準）。
- `docs/functional-spec.md` — 画面の図と、パレットの節に幅1200pxの分かれ目。
- `docs/architecture.md` — 画面の図（`+--挿入-- [ 記号パレット ]`）の位置関係。

## 実装で変えたところ

- **パレットのボタンが2行以上並ぶと、上の行が押せなかった**（いちばん大きい）。
  縦帯にしたら `selection` 区分が30秒待って落ちた。原因は**KaTeXのラベルが
  ボタンの外へ上に23.7〜38.7pxはみ出している**ことで、下の行のラベルが
  上の行のボタンの中心を覆い、クリックがそちらに当たっていた。
  `.palette__item * { pointer-events: none }` で中身を当たり判定から外した。
  **これは0054が作った不具合ではなく、既存の潜在バグ**（横帯でもボタンが
  2行以上になる場面——幅1440pxのギリシャ小文字31件など——では同じことが
  起きていた）。縦帯は全タブが3行以上になるので、毎回踏むようになった。
  検証に「どのボタンも中心をクリックすると自分に当たる」を足した。
- **既存チェック4件を横帯の幅（1199px）で測るように直した。** 幅1280px・
  1440pxで「パレットの高さが94px」を見ていたもので、縦帯では845pxになる。
  0032（高さの蓋）・0011（検索欄で高さが増えない）・0053（アイコンで
  高くならない）の意図はいずれも横帯の話なので、測る幅を移した。
  - `search`: 幅1280px → **1199px**
  - `palette-height`: 幅1280px → **1199px**、公式タブは幅1440px → **1199px**
  - `tab-icon`: 幅1440px → **1199px**
- **公式の式は縦帯では2行に折り返す。** 仕様には「名前も式もはみ出さない」と
  書いたが、折り返すことは書いていなかった。ボタン（155px）の外には出ない
  ので読めるが、`α + β = -b/a, αβ = c/a` のように式の途中で改行が入る。
  横帯では1行に収まっていたので、**縦帯にしたぶんの代償**である。
  「式がボタンの外にはみ出さない」を検証に足して固定した。

## 未確認の前提

- **検索欄のplaceholder（`検索（\int, 積分）`）が155pxで切れる可能性がある。**

- 公式タブで帯が縦スクロールしたとき、**2段目のタブ（9行）に隠れて
  ボタンが見えにくくなる**可能性。
  → 2段目は9行を占めるが、その下に公式のボタンが続き、帯をスクロールすれば

- グリッドに変えることで、ツールバーの `position: relative` を前提にした
  掲出（アイコン、0019）がずれないこと。
  → **ずれなかった**（`icon` 区分が全件通り、スクリーンショットでも確認）。

  → **保たれた**（`placement` 区分で1440px→1200px→1199px→360pxと動かしても
  タブの選択が外れず、全区分326件が通っている）。

## 検討したが採らなかった案

- **B案: タブ行とボタン行を1行にまとめる。** 幅1024pxで破綻する（上の実測）。
  幅1440pxでも、タブごとにパレットの高さが57〜232pxとばらつき、
  0032で潰した性質が広い画面で復活する。
- **A'案: 帯の幅を220pxにする。** 得るもの（textarea 815px）は180pxと同じで、
  プレビューの削りだけが90px → 110pxに増える。
- **ソースペインの中に入れる。** エディタとの距離はいちばん縮むが、
  [0043](0043-find-replace.md) の検索バーと [0042](0042-outline.md)（目次）と
  同じ場所を奪い合う。0042の置き場所が決まる前に埋めない。
- **帯の幅を利用者が変えられるようにする（ドラッグ）。** 状態と保存が増える。
  issueの「やらないこと」どおり、まず固定で置く。
- **幅1024pxから縦帯にする。** グラフが464px → 374pxに縮み、
  プレビューが422pxになる。得る縦94pxに見合わない。
