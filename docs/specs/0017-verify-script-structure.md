# 0017: 検証スクリプトを区分に分けて選んで流せるようにする

- 対応issue: [0017](../issues/0017-verify-script-structure.md)
- 状態: draft
- 作成日: 2026-09-19

## 目的

`scripts/verify-ui.mjs` は458行・43チェック・実行20.8秒（起票時377行・38チェック・21秒）。
「前回までのチェックを消さない」というルールの帰結で、ルール自体は正しい。
ただし1つのissueを検証するたびに全部を流すため、開発中の往復が重い。

**区分を選んで流せるようにする。** 何も指定しなければ全件流れるので、
回帰の確認はこれまで通りにできる。

あわせて、[4回目の振り返り](../retrospectives/2026-09-19.md)で見つけた
**チェックどうしの汚染**を構造で防ぐ。いまは先頭から順に流すことで初期状態が
暗黙に成り立っているが、区分を選べるようにすると、その前提が崩れる。

## 仕様

### 1. 区分を関数にまとめて登録する

いまトップレベルに直列で並んでいる処理を、区分ごとの非同期関数にまとめ、
配列に登録する。

```js
const sections = [
  { name: 'initial',   title: '初期表示',            run: async (ctx) => { … } },
  { name: 'autosave',  title: '自動保存（0001）',     run: async (ctx) => { … } },
  { name: 'code-math', title: 'コード内の$（0006）',  run: async (ctx) => { … } },
  { name: 'layout',    title: 'レイアウト',          run: async (ctx) => { … } },
  { name: 'perf',      title: '性能（0007）',        run: async (ctx) => { … } },
  { name: 'theme',     title: 'テーマ（0002）',      run: async (ctx) => { … } },
  { name: 'selection', title: '選択範囲の挿入（0009）', run: async (ctx) => { … } },
]
```

`name` はコマンドラインで打つ名前なのでASCII。`title` は出力に出す日本語。

現在の「レイアウト」チェック（幅600pxでコピーボタンが収まる）は0006の区分の中に
紛れているので、独立した区分に出す。

**チェックの中身は1件も変えない。** 43件すべてを、いまと同じ判定・同じラベルで
新しい構造に移すだけ。件数が減ったら移し忘れである。

### 2. 区分を選んで流す

```bash
node scripts/verify-ui.mjs              # 全区分（これまで通り）
node scripts/verify-ui.mjs theme        # テーマだけ
node scripts/verify-ui.mjs theme perf   # 複数指定
```

知らない名前を渡したら、**何も実行せずに**使える名前を並べて終了コード1で終わる。
打ち間違いに気づかないまま「0件中0件OK」で通るのがいちばん悪い。

### 3. 各区分は既知の初期状態から始める

各区分の実行前に、共通のリセットを必ず通す。

| 消すもの | 方法 |
|---|---|
| 保存された文書 | `localStorage` から `matheditor:document:v1` を消す |
| 保存されたテーマ | `matheditor:theme:v1` を消す |
| OSのテーマ設定 | `emulateMedia({ colorScheme: 'light' })` に戻す |

消す前に**デバウンス待ちを片付ける**。保存が飛んだままリロードすると
`beforeunload` で書き戻され、消したはずの文書が復活する（0009の検証で踏んだ）。
保存状態の表示が空か「保存しました」になるまで待ってから消す。

リセット後に `page.goto(URL)` して、プレビューが描けるまで待つ。

### 4. 出力

区分ごとに見出しを出し、最後にこれまで通り「n/m 件 OK」を出す。
終了コードの規則は変えない（1件でもNG、またはコンソールエラーがあれば1）。

```
== テーマ（0002） ==
OK   OSがダークなら暗い背景になる — rgb(21, 24, 28)
…
受け入れ基準: 43/43 件 OK
```

### 対象ファイル

| ファイル | すること |
|---|---|
| `scripts/verify-ui.mjs` | 区分の登録・選択・リセットの導入。チェックの中身は移すだけ |
| `docs/test-spec.md` | 区分の一覧と、選んで流す方法を書く |
| `docs/issues/0017-*.md` `README.md` | クローズ |

`src/` には触らない。

## 未確認の前提

- **区分ごとの所要時間を測っていない。** 全体20.8秒のうち性能区分（400節の文書を
  作る）が大きいと見ているが、実測していない。受け入れ基準で測って記録する。
- リセットを毎区分で通すと `page.goto` が増えるため、**全区分を流したときの合計は
  いまより遅くなる可能性がある**。目的は「選んで流せること」なので、全体が多少
  遅くなること自体は許容する。ただしどれだけ増えたかは測って記録する。
- `emulateMedia` の設定がリロードをまたいで保たれるかは確かめていない。

## 検討したが採らなかった案

- **Playwright Test の導入。** issueの「やらないこと」どおり。依存が増えるうえ、
  いまの `OK` / `NG` と件数を出す形は0001から機能している。
- **区分をファイルに分割する。** `scripts/verify/*.mjs` に分ける案。
  1ファイルで完結している利点（読めば全部分かる）を失う割に、得るものが少ない。
  行数がさらに倍になったら考える。
- **落ちたチェックだけ再実行する。** [0027](../issues/0027-verify-flaky.md) の
  「やらないこと」に反する。揺れを隠す方向。

## スコープ外

- 落ちたときの記録の残し方、タイミング依存チェックの明示、繰り返し実行。
  すべて [0027](../issues/0027-verify-flaky.md) が扱う。**本issueの直後に続けてやる**
  前提で、区分の構造はそちらが乗ることを想定して作る。
- チェックの追加・削除・閾値の変更。
