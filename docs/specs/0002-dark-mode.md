# 0002: ダークモード

- 対応issue: [0002](../issues/0002-dark-mode.md)
- 状態: implemented
- 作成日: 2026-09-19

## 目的

配色がライト固定で、`color-scheme` の指定もない。OSがダークテーマの環境では
白い画面が眩しい。数式エディタは長時間見つめる道具なので影響が大きい。

OSの設定に追従しつつ、手動でも選べるようにする。選んだテーマは次回訪問時にも
保たれる。ダークでも数式・コード・表・引用が読める配色にする。

## 仕様

### 1. テーマの3状態

| 値 | 意味 |
|---|---|
| `system` | OSの設定に従う（既定値） |
| `light` | 常にライト |
| `dark` | 常にダーク |

`system` を既定にするのは、初回訪問でいきなりOSと違う見た目にしないため。

### 2. 適用の仕組み

`<html>` の `data-theme` 属性で切り替える。

- `system`: 属性を外す（`prefers-color-scheme` のメディアクエリに任せる）
- `light` / `dark`: `data-theme="light"` / `data-theme="dark"` を付ける

CSSは次の3段で書く。

```css
:root { /* ライトの値 */ color-scheme: light; }

@media (prefers-color-scheme: dark) {
  :root:not([data-theme='light']) { /* ダークの値 */ color-scheme: dark; }
}

:root[data-theme='dark'] { /* ダークの値 */ color-scheme: dark; }
```

`color-scheme` を指定するのは、スクロールバーやtextareaのフォームUIを
ブラウザ側でも合わせるため。

### 3. 色の定義

既存の `:root` の8変数にダーク側の値を与える。あわせて、現在ベタ書きされている
色を変数に寄せる（ダークで破綻するため）。

| 変数 | ライト | ダーク | 用途 |
|---|---|---|---|
| `--bg` | `#ffffff` | `#15181c` | 全体の背景、ツールバー |
| `--bg-muted` | `#f6f7f9` | `#1e2228` | パレット、ペインのヘッダ、コード |
| `--bg-editor` | `#fbfbfc` | `#181b20` | エディタ（textarea） |
| `--text` | `#1c2024` | `#e6e9ee` | 本文 |
| `--text-muted` | `#62707f` | `#9aa6b4` | 補助表示 |
| `--border` | `#dfe3e8` | `#2c323a` | 罫線 |
| `--accent` | `#2563eb` | `#5b8cff` | ボタン、選択中のタブ |
| `--accent-soft` | `#e8f0ff` | `#22304d` | パレットのホバー |
| `--danger`（新規） | `#b42318` | `#ff8a80` | 保存失敗の文言 |
| `--math-error`（新規） | `#dc2626` | `#ff9a9a` | 壊れた数式 |
| `--on-accent`（新規） | `#ffffff` | `#0f1115` | アクセント上の文字 |

ベタ書きを置き換える箇所:

- `.toolbar__save--failed` の `#b42318` → `var(--danger)`
- `.button` の `color: #fff` → `var(--on-accent)`
- 狭い画面の `.toolbar__status` の `rgba(28, 32, 36, 0.88)` と `#fff`
  → `var(--text)` / `var(--bg)` を使った配色に置き換える（ダークで黒地に黒字にならないように）

### 4. 壊れた数式の色

KaTeXは `errorColor` をインラインstyleで出すため、CSSで上書きするには
`!important` が要る。

```css
.preview .katex-error { color: var(--math-error) !important; }
```

`renderMarkdown.ts` の `errorColor` はライト側の値（`#dc2626`）のまま残す。
テーマはCSSの担当であり、変換ロジックにテーマを持ち込まないため。

### 5. 切り替えのUI

ツールバーの「サンプルに戻す」の左にボタンを1つ置く。押すたびに
`system → light → dark → system` と巡る。

- 表示は現在の状態: `テーマ: 自動` / `テーマ: ライト` / `テーマ: ダーク`
- `title` は `テーマを切り替える（自動 → ライト → ダーク）`
- 見た目は `.button--quiet`（主操作のコピーから視線を奪わない）
- 狭い画面（720px以下）では `自動` / `ライト` / `ダーク` だけを出す

### 6. 保存

`src/lib/themeStorage.ts` を新規に作る。保存先は `localStorage`、
キーは `matheditor:theme:v1`（[0001](0001-autosave.md) の命名規約に揃える）。

```json
{ "version": 1, "theme": "dark" }
```

- 読めない・版が違う・値が3つのいずれでもない場合は `system` として扱う。
- 読み書きは `try/catch` で囲み、例外を外に出さない。保存に失敗しても
  テーマの切り替え自体は効く（次回訪問時に戻るだけ）。失敗の表示は出さない
  （自動保存と違い、失われるものが小さい）。
- 初期テーマの適用は、**`index.html` のインラインスクリプトで行う**。

  仕様を書いた時点ではReactのマウント時に行う案だったが、実測したところ
  OSがライトで手動ダークを選んでいる場合に白が出た（開発サーバで12ms、
  本番ビルドでは最初に描かれる色が白で20ms）。相談のうえ、インライン
  スクリプトに変えた。保存キーと値の形が `themeStorage.ts` と重複するので、
  両方のファイルにその旨を書いてある。

## 検討したが採らなかった案

- **ライト／ダークの2状態だけにする（OS追従なし）。** 初回訪問でOSと違う
  見た目になる。追従は既定として要る。
- **`prefers-color-scheme` のみで、手動切り替えを持たない。** issueの
  「手動でも切り替えられる」を満たさない。OSごと変えたくない場面がある。
- **`index.html` にインラインスクリプトを置いてちらつきを消す。** 効果はあるが、
  テーマの扱いがReactの外にも散る。まずちらつきの有無を測ってから判断する。
- **CSSの `light-dark()` 関数を使う。** 記述は短くなるが、対応ブラウザが
  新しめで、`data-theme` による手動切り替えと組み合わせる書き方が
  かえって読みにくい。

## スコープ外

- 任意配色のテーマ機能。ライトとダークの2つだけ。
- 印刷用の配色（[0013](../issues/0013-print-style.md)）。
- テーマ以外の表示設定（フォントサイズ、行間）。
