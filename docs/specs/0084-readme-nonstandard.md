# 0084: Markdown標準ではない機能を、READMEに書く

- 対応issue: [0084](../issues/0084-readme-nonstandard.md)
- 状態: implemented
- 作成日: 2026-09-22

## 目的

READMEの「できること」は機能を並べているだけで、**どれがMarkdownの標準で、
どれがこのエディタだけの振る舞いか**が書かれていない。書いたものは持ち出して
使う道具なので、**どこまで持ち出せるか**は使う前に分かるべき情報になっている。

加えて、**式の自動採番と参照（[0044](0044-equation-numbers.md)・
[0083](0083-crossref-dialect.md)）がREADMEに載っていない**。実装されているのに
外から見えない。

このissueのあと、READMEを読んだ人は「この3つ（採番・参照・グラフ）は
このエディタの中だけのもので、持ち出すとこう見える」と分かる。

## 仕様

### 1. 「できること」の表に1行足す

`関数のグラフ` の下に置く（記法に関わる機能をまとめる）。

```
| **式の番号と参照** | 式に `{#eq-名前}` を付けると番号が振られ、本文から `@eq-名前` で参照できる。式を足せば番号も参照も振り直される |
```

### 2. 「書き方」の節に、式の番号と参照の書き方を足す

グラフの説明の**前**に置く（数式まわりの説明を続ける）。本文はこう書く。

````
番号を振りたい式は、閉じの `$$` のうしろに `{#eq-名前}` と書く。
本文からは `@eq-名前` で参照でき、番号は上から順に振り直される。
名前は英小文字・数字・`-` `_` だけで、`eq-` で始める。

```
$$
a^2 + b^2 = c^2
$$ {#eq-pythagoras}

@eq-pythagoras より、斜辺の長さが決まる。
```

この綴りは[Quarto](https://quarto.org/docs/authoring/cross-references.html)と同じ。
古い書き方（`\tag{名前}` と `[(1)](#eq-名前)`）も読めるが、新しく書くならこちらを使う。
````

### 3. 新しい節「このエディタだけの記法」を足す

`## 書き方` と `## 保存と持ち出し` の**間**に置く。持ち出しの話に入る直前で
読ませるため。

```markdown
## このエディタだけの記法

Markdownには**採番も相互参照もグラフも無い**。次の3つはこのエディタが足した
振る舞いで、**持ち出した先では動かない**。記法そのものは標準の範囲か既存の
方言なので、持ち出しても壊れた文字列にはならない。

| 機能 | 書き方 | 持ち出した先での見え方 |
|---|---|---|
| 式の番号 | `$$ … $$ {#eq-名前}` | `{#eq-名前}` が文字として出る（Quarto・Pandocなら番号が付く） |
| 式への参照 | `@eq-名前` | `@eq-名前` が文字として出る（同上） |
| 関数のグラフ | ` ```graph ` | コードブロックとして、書いた式が読める形で残る |

番号まで揃った形で渡したいときは、いまのところ**プレビューを印刷する**しかない。
描画された形での書き出しは今はない（[0050](docs/issues/0050-html-export.md)）。
```

### 4. 書かないこと

- **旧記法（`\tag`）の詳しい説明**。READMEは入口なので、新記法だけ書き、
  「古い書き方も読める」の一文で済ませる。詳細は[機能仕様](../functional-spec.md)。
- **焼き込み（[0082](../issues/0082-bake-equation-numbers.md)）への言及**。
  まだ無いものを「できること」の隣に書くと期待させる。3節の最後の一文
  （0050だけ）に留める。

## 受け入れ基準

READMEは文書なので、**読んで確かめる**ものが中心になる。数字だけは単体テストで固定する。

- [ ] READMEの「できること」に**式の番号と参照の行**があり、`{#eq-名前}` と
      `@eq-名前` の両方が書かれている
- [ ] READMEの「書き方」に、**採番と参照の例**（`$$ … $$ {#eq-pythagoras}` と
      `@eq-pythagoras`）が載っている
- [ ] READMEに**「このエディタだけの記法」の節**があり、採番・参照・グラフの
      3つが**持ち出した先での見え方とセット**で書かれている
- [ ] その節に、完全な形で渡す道が**「今はない」と0050の番号つき**で書かれている
- [ ] 単: `guideTable.test.ts` の954件が「READMEに書いた件数」として
      `palette.test.ts`・`formulas.test.ts` と同じ形で固定されている
- [ ] READMEから参照しているリポジトリ内のリンクがすべて存在する
      （`grep -o '](\([^)h][^)]*\))' README.md` で拾って確かめる）
- [ ] `npm test` が通る（1012件）
- [ ] `npm run lint` が通る

**実機検証は足さない。** 画面は変わらない。

## 検討したが採らなかった案

- **「できること」の表に「持ち出せるか」の列を足す** — 15行すべてに
  関係ない情報が並ぶ（ダークモードの持ち出し可否は意味がない）。
  記法の3つだけを別の節にまとめるほうが読みやすい。
- **機能仕様へのリンクで済ませる** — READMEを読む人は `docs/` を開かない。
  0035でREADMEを使う人向けに書き直した趣旨に反する。

## スコープ外

- 書き出しのときの番号の焼き込み（[0082](../issues/0082-bake-equation-numbers.md)）。
- HTML書き出し（[0050](../issues/0050-html-export.md)）。
- 英語版のREADME（今はない。日本語だけ）。

## 実装したときに変えたこと

| 「番号まで揃った形で渡したいときは、いまのところ**プレビューを印刷する**しかない」 | **「渡す手段は今はない」に書き換えた。** 0050と0082を検討中として挙げ、印刷は「使えるが体裁を整えていない」と断った（[0013](../issues/0013-print-style.md)） | 印刷は確かめていない。**印刷用のスタイルは0013として未着手**なので、勧める書き方は嘘になる |

| 空行の整理は範囲外 | **README全体の連続空行を詰めた**（ユーザーの指示、2026-09-22） | 0083のコミットに巻き込まれた編集で連続空行が増えていたため |
