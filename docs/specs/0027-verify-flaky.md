# 0027: 検証が落ちたときに情報が残るようにする

- 対応issue: [0027](../issues/0027-verify-flaky.md)
- 状態: implemented
- 作成日: 2026-09-19

## 目的

[0026](0026-typescript-strict.md) のマージ直後、検証が1回だけ 42/43 で落ちた。
出力を `tail` で切っていたため、**どのチェックが落ちたかは永久に分からない**。
その後12回流して再現していない。

このissueで作るのは原因の特定ではなく、**次に落ちたときに情報が残る仕組み**である。
あわせて、揺れやすいチェックがどれかをスクリプト上で明示し、揺れの有無を
確かめる手段を用意する。

[0017](0017-verify-script-structure.md) で入れた区分の構造の上に乗る。

## 仕様

### 1. 落ちたチェックを最後にまとめて再掲する

実行の最後、「n/m 件 OK」の直前に、NGだったチェックだけを区分名つきで再掲する。
実測値（`detail`）も一緒に出す。スクロールで流れても、末尾を見れば残る。

```
-- 落ちたチェック（1件） --
NG  [perf] 長文での入力反映が1文字あたり50ms以内 — 63.2ms/文字

受け入れ基準: 42/43 件 OK
```

全件OKなら、この節は出さない。

### 2. 結果をJSONで書き出す

`tmp/verify-result.json` に、実行のたびに上書きで書く（パスは環境変数
`VERIFY_JSON` で変えられる）。出力を切ってしまっても、ファイルを見れば分かる。

```json
{
  "startedAt": "2026-09-19T12:34:56.789Z",
  "durationMs": 20781,
  "sections": ["initial", "autosave", "…"],
  "total": 43,
  "passed": 42,
  "consoleErrors": [],
  "checks": [
    { "section": "perf", "label": "長文での入力反映が…", "ok": false,
      "detail": "63.2ms/文字", "timing": true, "durationMs": 1234 }
  ]
}
```

`tmp/` は既にスクリーンショットの出力先で、gitの追跡外である。

### 3. タイミングに依存するチェックに印をつける

`check()` に `timing` の指定を足し、負荷や待ち時間に依存するチェックに付ける。
出力では印を出し、JSONにも残す。**判定そのものは変えない**（閾値も待ち方も同じ）。

issueのメモで洗い出した6件に付ける。

| 区分 | チェック | 依存しているもの |
|---|---|---|
| autosave | 入力直後は保存中と出る | デバウンスより先に読めるか |
| autosave | 即リロード前は未保存（保存中） | 同上 |
| perf | 長文での入力反映が1文字あたり50ms以内 | マシンの負荷 |
| perf | 入力を止めてから1.5秒以内に追いつく | 同上 |
| perf | 短い文書では更新中が残らない | 固定待ち300ms |
| theme | 初期表示でライトの背景が現れない | 16ms間隔の読み取り |

印は「落ちてもよい」という意味ではない。**落ちたときに疑う順番**を示すもの。

### 4. 繰り返して揺れを見る

```bash
node scripts/verify-ui.mjs --repeat 5 perf
```

指定した区分を5回流し、チェックごとに「5回中n回OK」を出す。1回でも落ちたものが
あれば終了コードを1にする。

全回通ったチェックは1行にまとめ、**揺れたチェックだけを目立たせる**。

```
-- 揺れたチェック（--repeat 5） --
長文での入力反映が1文字あたり50ms以内 — 5回中4回OK（63.2ms/文字 で1回NG）
ほか42件は5回とも同じ結果
```

`--repeat` を付けなければ1回だけ流す（これまで通り）。

### 対象ファイル

| ファイル | すること |
|---|---|
| `scripts/verify-ui.mjs` | NG再掲、JSON出力、`timing` 印、`--repeat` |
| `docs/test-spec.md` | 落ちたときに何が残るか、`--repeat` の使い方を書く |
| `docs/issues/0027-*.md` `README.md` | クローズ |

`src/` には触らない。

## 未確認の前提

- **どのチェックが実際に揺れるかは測っていない。** 上の6件は「依存しているものが
  あるから揺れうる」というだけで、実測ではない。`--repeat` を作った後に測って、
  結果を仕様に記録する。
- 42/43で落ちた1回の原因は不明のままで、**このissueでは特定しない**。
  特定できるとしたら、仕組みを入れた後に再び落ちたときである。
- `tmp/` がgitの追跡外であることは `.gitignore` で確認する。

## 検証の記録

### わざと1件落としたときの出力

`layout` 区分の判定を `copyRight <= toolbarWidth` から `copyRight <= 1` に
一時的に書き換えて、`node scripts/verify-ui.mjs layout autosave` を流した。

```
== レイアウト ==
NG   狭い画面でもコピーボタンが画面内に収まる — right=588 width=600

コンソールエラー: なし

-- 落ちたチェック（1件） --
NG  [layout] 狭い画面でもコピーボタンが画面内に収まる — right=588 width=600

受け入れ基準: 14/15 件 OK
所要時間: 6.1秒
結果: tmp/verify-result.json
```

終了コードは1。再掲には**区分名・ラベル・実測値**が出ている。

### 同じ実行のJSON

```json
{
  "section": "layout",
  "label": "狭い画面でもコピーボタンが画面内に収まる",
  "ok": false,
  "detail": "right=588 width=600",
  "timing": false,
  "durationMs": 776
}
```

`sections: ["autosave", "layout"]`、`total: 15`、`passed: 14` も入っている。

書き換えを戻すと `layout` は 1/1 件OKに戻り、スクリプトの差分は
このissueの変更だけになった。**なお受け入れ基準に「`git status` がクリーン」と
書いたが、0027自身の変更がまだコミットされていない段階では文字どおりには
満たせない。** 確かめたのは「わざと落とすための書き換えが残っていないこと」で、
クリーンであることはコミット後に確認した。

### timing の印

6件すべてに付き、出力では `⏱`、JSONでは `"timing": true` になっている。

| 区分 | チェック |
|---|---|
| autosave | 入力直後は保存中と出る |
| autosave | 即リロード前は未保存（保存中） |
| perf | 長文での入力反映が1文字あたり50ms以内 |
| perf | 入力を止めてから1.5秒以内にプレビューが追いつく |
| perf | 短い文書では更新中が残らない |
| theme | 初期表示でライトの背景が現れない（ちらつきなし） |

### `--repeat 3 perf`

```
-- 揺れたチェック（--repeat 3） --
なし。5件とも3回同じ結果

受け入れ基準: 5/5 件 OK
所要時間: 24.5秒
```

**揺れは観測されなかった。** ただし3回では足りない可能性がある。
42/43で落ちた1回も12回の再実行で再現していないので、この結果は
「揺れがない」ことの証明にはならない。実測値は回ごとに動いており
（追いつき時間は293ms〜1148ms）、閾値1500msに対して余裕はあるが一定ではない。

次に落ちたときに、再掲とJSONから中身が分かる状態になった。それがこのissueの成果で、
**原因の特定は次に落ちたときに持ち越す。**

## 検討したが採らなかった案

- **落ちたチェックの自動リトライ。** issueの「やらないこと」。揺れを隠す。
- **閾値をゆるめる。** 50msと1.5秒は[0007](0007-preview-performance.md)で決めた
  要求そのもの。再現しない失敗を理由に動かさない。
- **`timing` の付いたチェックを既定で除外する。** 揺れるから外す、は回帰を
  見逃す側に倒れる。印を付けるだけにとどめる。
- **すべての実行のJSONを履歴として残す。** `tmp/` が膨らむ割に、いま欲しいのは
  「直前の実行で何が落ちたか」なので上書きで足りる。

## スコープ外

- 42/43で落ちた1回の原因特定。再現しないため、できない。
- CIでの実行と結果の保存（[0025](../issues/0025-ci.md)）。
- チェックの追加・削除・閾値の変更。
