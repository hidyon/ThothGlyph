# 0066: アイコンの図柄を三日月にする

- 対応issue: [0066](../issues/0066-moon-icon.md)
- 状態: implemented
- 作成日: 2026-09-21

## 目的

アイコンが平方根記号のままで、`ThothGlyph` という名前とつながっていない。
**トトは月の神**で、満ち欠けを数えて暦を刻む。図柄を三日月にすると、
名前の由来がアイコンにも出る。

利用者から見て変わるのは、タブ・ツールバー・インストール時のアイコンの絵柄だけ。
色も置き場所も変わらない。

## 仕様

### 1. 図柄

**円を2つ重ねて描く。** 白い円の上に地色の円を置き、はみ出した部分が
三日月になる。円弧のパス（`A` コマンド）は使わない（large-arc と sweep の
組み合わせで膨らむ向きが決まり、狙いと違う形になりやすい。円の重ねなら
確実で、`stroke-width` を持たないぶん縮小でも太さが飛ばない）。

`public/favicon.svg` の中身:

```svg
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 32 32" width="32" height="32" role="img" aria-label="ThothGlyph">
  <title>ThothGlyph</title>
  <!--
    三日月。トトは月の神で、満ち欠けを数えて暦を刻む。
    円弧のパスではなく円を2つ重ねて描く。パスだと large-arc と sweep の
    組み合わせで膨らむ向きが変わり、stroke-width を持つと縮小で太さが飛ぶ。
    <text> を使わないのは、見る側のフォントに依存して字形が変わるため。
  -->
  <rect width="32" height="32" rx="7" fill="#2563eb"/>
  <circle cx="16" cy="16" r="10" fill="#ffffff"/>
  <circle cx="21" cy="14" r="8.5" fill="#2563eb"/>
</svg>
```

採るのは **E3（太い）**。4通りを実測していずれも基準を満たしたが、
16pxで描いて見たときE3が最も明瞭で、上限20%まで5.5ptの余裕がある
（[issue](../issues/0066-moon-icon.md#現状の実測2026-09-21)の表）。

| 値 | 現行（根号） | 三日月E3 | 基準 |
|---|---|---|---|
| 16pxの白インク量 | 9.8% | **14.5%** | 6〜20% |
| 512pxの白インク量 | 9.9% | **14.8%** | — |
| 16pxと512pxの差 | 0.1pt | **0.3pt** | 1.5pt以内 |
| コントラスト比 | 5.17:1 | **5.17:1**（色を変えないので同じ） | 4.5:1以上 |

`rect` の `rx="7"` は残す。`make-icons.mjs` が `apple-touch-icon.png` を
書き出すとき `rx` を正規表現で落とすので（iOSが自分で角を丸めるため）、
**`rx` を持つのは背景の `rect` だけ**という前提を崩さない。円は `r` 属性で
`rx` ではないので、この置換に巻き込まれない。

### 2. PNGの書き出し

`node scripts/make-icons.mjs` で4件を再生成し、**コミットする**。
手で作らない（SVGを直したときにPNGだけ古くなるため）。

| ファイル | 大きさ | 角丸 |
|---|---|---|
| `public/favicon-32.png` | 32 | あり |
| `public/apple-touch-icon.png` | 180 | **なし**（iOSが自分で丸める） |
| `public/icon-192.png` | 192 | あり |
| `public/icon-512.png` | 512 | あり |

### 3. 変えないもの

- **地の色 `#2563eb` と記号の色 `#ffffff`。** 色を動かすとコントラスト比の
  基準を引き直すことになる。
- **ツールバーへの掲出。** `favicon.svg` を20pxで参照する形
  （[0019](0019-app-icon.md) の節7）のまま。パスを書き写さない。
- `manifest.webmanifest`、`index.html` の `<link>`。ファイル名が変わらないため。

### 対象ファイル

| ファイル | すること |
|---|---|
| `public/favicon.svg` | 図柄を三日月に |
| `public/favicon-32.png` / `apple-touch-icon.png` / `icon-192.png` / `icon-512.png` | `make-icons.mjs` で再生成 |
| `scripts/verify-ui.mjs` | **変更不要だった**（白インク量は範囲判定、コントラスト比は色から計算しているため） |
| `docs/screenshots/*.png` | ツールバーにアイコンが写るので撮り直す（**3枚とも変わった**） |
| `docs/functional-spec.md` | 「アイコン」の節。図柄と実測値 |
| `docs/requirements.md` | 非機能要求 N8 の基準と現状 |

## 未確認の前提

- **`icon` 区分14件は、図柄を変えても判定の書き換えなしに通る**と考えている。
  白インク量は範囲判定（6〜20%）、コントラスト比は色から計算しているため。
  ただし確かめていない。落ちたら仕様に戻る。
- **`make-icons.mjs` の `rx` 落としが円に影響しない**と考えている
  （円は `r` 属性）。コードは読んだが、実際に流してはいない。
- 16pxでの見え方は、SVGをブラウザで16pxに描いて目で見た。
  **タブに並んだときどう見えるかは0019と同じく機械では見られない。**

## 実装で分かったこと

**受け入れ基準に「16pxのPNG」と書いていたが、そんなPNGは書き出していない**
（32 / 180 / 192 / 512 の4件）。0019と同じ「512pxと32px」に直した。16pxでの
見え方は、白インク量14.5%という数値と、SVGを16pxで描いて目で見たことで
確かめている。**書き出すファイルの一覧は仕様にも書いてあったのに、基準を
書くときに見ていなかった。**

**未確認の前提は2つとも確認できた。** `icon` 区分14件は判定を1行も変えずに
通った（白インク量は範囲判定、コントラスト比は色から計算している）。
`make-icons.mjs` の `rx` 落としも円に影響しなかった（円は `r` 属性）。

**スクリーンショットは3枚とも変わった。** 仕様では幅1440pxの2枚が変わると
思っていたが、幅360pxの1枚も変わる。狭い画面では名前の文字が隠れて
**アイコンだけが残る**ので、むしろアイコンの比重が大きい。

**全区分の1回目で `scroll` の1件が落ちた**（「1行が折り返す文書でも上端から
32px以内 — 見つからないpx」）。アイコンとは無関係な区分なので、
`--repeat 3` で単独実行したところ**3回とも20/20**、全区分を流し直しても
**393/393**だった。フレークと判断したが、**このチェックには `⏱` が付いていない**。
付けるかどうかは0027（検証の再現性）の続きとして別issueにする。

## 検討したが採らなかった案

**円弧のパスで三日月を描く。** `<path d="M16 6 A10 10 0 1 0 16 26 A12.8 12.8 0 1 0 16 6 Z"/>`
のように2つの円弧で囲む。ノードが1つで済むが、large-arc と sweep の
4通りの組み合わせで膨らむ向きが変わり、狙いの形になるかを描いてみるまで
判断できない。円の重ねは確実で、読む側にも分かりやすい。

**月に加えてトキや刻み目を足す。** 由来をより多く表せるが、16pxでは
要素が2つを超えると塊になる。0019が決めた「直線と太い塊だけで描く」
という方針に従い、月だけにする。

**地の色をエジプトらしい色（砂・青金石）に変える。** 名前に合わせるなら
色も動かせるが、コントラスト比の基準を引き直すことになり、図柄の変更と
混ざると何が原因で数値が動いたか分からなくなる。色を変えるなら別issue。

**E4（大きめ、19.2%）を採る。** 16pxでいちばん堂々として見えるが、
上限20%まで0.8ptしかない。将来の微調整で簡単に超える。
