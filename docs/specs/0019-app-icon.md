# 0019: アプリのアイコン

- 対応issue: [0019](../issues/0019-app-icon.md)
- 状態: 完了（ツールバーへの掲出を追加。下の「スコープを広げた」を参照）
- 作成日: 2026-09-19

## 目的

`public/favicon.svg` にはいまも**Claudeのロゴ**（`fill="#863bff"` の紫の
アスタリスク、9,522バイト）が入っている。足場を作ったときのまま差し替えていない。
他所のロゴを自分のアプリのタブに掲げている状態で、これは見分けの問題である前に
**掲げてはいけないもの**である。

matheditor固有のアイコンに差し替え、タブ・ブックマーク・ホーム画面のどれで見ても
このアプリだと分かるようにする。

なお issueのメモにある「`index.html` の `<html lang="en">` も足場のまま」は、
[0031](0031-english-ui.md) で解消済み（表示中の言語に合わせて `ja` / `en` が入る）。
起票時点の記述が古くなっているだけで、このissueで扱うことは変わらない。

## 仕様

### 1. 何を描くか

**平方根記号（√）を、直線だけで描いた記号。** 背景は角丸正方形の塗り。

```
┌─────────────┐
│      ────── │   横棒（vinculum）
│     ╱       │   上りの斜線
│  ╲ ╱        │   下りの斜線（短い）
└─────────────┘
```

- **直線だけで作る。** 曲線や細い装飾は16pxで潰れる。
- **`<text>` 要素を使わない。** SVGの `<text>` は見る側のフォントに依存し、
  フォントが無い環境で別の字形になるか、消える。パスで描く。
- **背景は不透明な角丸正方形**（`#2563eb`、アプリの `--accent` と同じ）、
  記号は白（`#ffffff`）。

背景を不透明にするのは、**ライト／ダークの判定をブラウザに任せない**ため。
透明背景にすると、タブの地の色の上に直接載り、ダークでは紺色の記号が
黒地に沈む。自前の地を持てば、どちらのテーマでも同じ見え方になる。
（`prefers-color-scheme` をSVG favicon内で使う案は「採らなかった案」に書いた。）

### 2. 置くファイル

| パス | 用途 | 大きさ |
|---|---|---|
| `public/favicon.svg` | 主。差し替え | 32x32のviewBox |
| `public/favicon-32.png` | SVG faviconを読まない環境の控え | 32x32 |
| `public/apple-touch-icon.png` | iOSのホーム画面。**角丸なし**の正方形 | 180x180 |
| `public/icon-192.png` | manifest用 | 192x192 |
| `public/icon-512.png` | manifest用 | 512x512 |
| `public/manifest.webmanifest` | 名前とアイコンの宣言 | — |

iOSはアイコンの角を自分で丸めるため、`apple-touch-icon.png` だけは
**角丸を付けずに書き出す**（付けると角が二重に落ちる）。他のPNGとfaviconは角丸あり。

`index.html` の `<head>` に3行足す（`favicon-32.png` / `apple-touch-icon` / `manifest`）。
既存の `<link rel="icon" type="image/svg+xml">` は残す。

manifestの中身は名前とアイコンだけにする。

```json
{
  "name": "matheditor",
  "short_name": "matheditor",
  "icons": [
    { "src": "/icon-192.png", "sizes": "192x192", "type": "image/png" },
    { "src": "/icon-512.png", "sizes": "512x512", "type": "image/png" }
  ]
}
```

`display` や `start_url` は書かない。書くとPWAとして扱われ始め、
このissueの「やらないこと」（PWA化）に踏み込む。

### 3. PNGはSVGから生成する

**PNGを手で作らない。** 手で作ると、SVGを直したときにPNGだけ古くなる
（同じものが2か所にある問題。[0031](0031-english-ui.md)の振り返りで
CLAUDE.mdから重複を削ったのと同じ理由）。

`scripts/make-icons.mjs` を足す。検証と同じヘッドレスChromiumで
`public/favicon.svg` を指定サイズで描画し、4つのPNGを書き出す。

```bash
node scripts/make-icons.mjs   # public/*.png を作り直す
```

生成したPNGは**コミットする**（ビルド時に生成しない）。Viteの `public/` は
そのまま配られるだけで、生成の仕組みをビルドに足すと devcontainer の外でも
Chromiumが要ることになる。

### 4. 「潰れていない」をどう判定するか（実測して確定）

目視で決めない（issueのメモで釘を刺されている）。**16pxで描いて数える。**

**測るのは「白インク量」。** 白に近いピクセルだけ数える方法は採らない。16pxでは
アンチエイリアスの中間色が大半を占め、それを落とすと太さの差が出ないため
（最初にその方法で測ったら7.7%で、太さを変えても動きが鈍かった）。
地の色と白のあいだのどこにいるかを0〜1で重み付けし、合計を不透明ピクセル数で割る。

この測り方はサイズによらず安定する。実測（線の太さを振ったもの）:

| 線の太さ | 16px | 32px | 512px | 16pxでの実効線幅 |
|---|---|---|---|---|
| 1 | 2.9% | 2.9% | 3.2% | 0.5px |
| 2 | 5.8% | 6.3% | 6.5% | 1.0px |
| 2.5 | 8.3% | 8.2% | 8.2% | 1.25px |
| **3（採用）** | **9.8%** | **9.9%** | **9.9%** | **1.5px** |
| 4 | 12.8% | 13.4% | 13.4% | 2.0px |
| 6 | 20.6% | 20.8% | 20.8% | 3.0px |
| 8 | 28.3% | 28.8% | 28.7% | 4.0px |

この表から基準を決める:

- **16pxでの白インク量が 6%以上・20%以下。** 下は太さ2（線が1pxになり、
  16pxで見えなくなる境）、上は太さ6（3pxになり塊に近づく境）。採用値は9.8%。
- **16pxでの実効線幅が1.25px以上**（`stroke-width ÷ 32 × 16`）。採用値は1.5px。
- **16pxと512pxのインク量の差が1.5ポイント以内。** 縮めたときにインクが
  飛んでいないこと。採用値は0.1ポイント。
- **記号と背景のコントラスト比が4.5:1以上。** 白 `#ffffff` と `#2563eb` で
  **5.17:1**。仕様を書いた時点では「8.6:1になるはず」と見立てていたが、
  計算すると違った。基準は満たすが、**確かめずに書いた数字は外れる**という例として残す。

### 7. ツールバーにも出す（承認を得てスコープを広げた）

タブのアイコンだけでは**アプリを開いている本人からは見えない**。ツールバーの
`matheditor` の左に同じ記号を20pxで置く。

**記号のパスを2か所で持たない。** `Toolbar.tsx` にSVGを書き写すと、
`favicon.svg` を直したときに片方だけ古くなる。`public/favicon.svg` は
ルートに配られているので、`<img src="/favicon.svg">` で参照する。
（アイコンは自前の地を持つので、文字色を継がせる必要がない。`<img>` で足りる。）

画像は装飾なので `alt=""` にする。隣に `matheditor` という文字があり、
読み上げが二重になるため。

**狭い画面では文字を隠して記号だけにする。** 幅600pxでのツールバーの余白は
19px（[0031](0031-english-ui.md)で言語ボタンを足したときに実測）しかなく、
20px＋間隔8pxを足すと溢れる。720px以下では `matheditor` の文字を
**視覚的にだけ隠す**（`clip-path` で、読み上げには残す）。記号が名前の代わりになる。

## 未確認の前提

- ~~**16pxでの被覆率のしきい値（12〜45%）に根拠がない。**~~ → **外れていた。**
  最初の測り方（白に近いピクセルを数える）では7.7%で、12%の下限を割った。
  測り方を白インク量に変え、線の太さを9通り振って実測してから、
  6〜20%に決め直した（上の表）。**前提が崩れたので基準の数字を直してから進めた。**
- **PlaywrightでSVGをPNGに書き出せるか。** `page.screenshot` で撮れるはずだが、
  透明の扱い（`omitBackground`）と、指定サイズちょうどに出るかを確かめていない。
  できなければ別の手段（`sharp` などの依存を足すか、PNGをやめる）に切り替え、
  仕様に戻って相談する。
- **ヘッドレスChromiumがタブのアイコンを実際に描くか。** → **見られなかった。**
  想定どおり、faviconの描画はページのDOMの外にある。機械で確かめたのは
  「6ファイルが200で返る」「SVGをcanvasに描いて数えた値」「PNGの大きさと
  四隅の不透明さ」まで。**タブに出た実物は未確認**のまま残っている。
- **PlaywrightでSVGをPNGに書き出せるか。** → できた。`page.setContent` で
  実寸のdivに流し込み、`screenshot({ omitBackground: true })` で撮る。
  指定サイズちょうどで出て、2回流しても同じバイト列になる（md5一致を確認）。

## スコープを広げた

issueの「やらないこと」には `アプリ名の見せ方やツールバーの意匠は変えない` と
書いてあった。実機で試したユーザーから「アプリのページ内にアイコンがない」と
指摘があり、**ツールバーへの掲出を足すことを承認してもらった**ので、
仕様に節7を追加して実装した。

タブのアイコンは「他人から見た見分け」で、ツールバーのアイコンは
「開いている本人から見た見分け」なので、目的が違う。issueを分ける手もあったが、
同じアセット・同じ判断の続きであること、0019がまだマージされていないことから、
広げるほうを選んだ。

## 実装中に仕様から外れたこと

- **被覆率の測り方を変えた。** 仕様は「白に近いピクセルの割合」で書いていたが、
  16pxではアンチエイリアスの中間色が大半で、太さを変えても値が鈍かった
  （実測7.7%で、仕様の下限12%を割った）。地と白のあいだの位置で重み付けする
  「白インク量」に変え、太さを9通り振って実測してからしきい値を決め直した。
  **前提が崩れたので、実装を進める前に仕様へ戻って数字を入れ替えた。**
- **検証の判定を1回直した。** 「`<text>` を持たない」を文字列一致で見ていたため、
  SVGのコメントに書いた「`<text>` を使わない」という**説明そのもの**に当たって
  落ちた。コメントを除いてから要素を見る形に変えた。
- **機能仕様のツールバー図を直した。** 0019とは関係なく、0002（テーマ）と
  0031（言語）で増えたボタンが図に反映されていなかった。0031のクローズ時に
  直すべきものが漏れていたので、ここで直した。

## 検討したが採らなかった案

- **SVG内で `prefers-color-scheme` を使い、テーマごとに色を変える。**
  SVG faviconでメディアクエリが効くかはブラウザによって差があり、
  効かない環境では「どちらのテーマで見ても同じ1色」になる。背景を不透明にすれば
  この問題自体が消える。**不確かな仕組みに頼らず、仕組みが要らない形にする。**
- **Σ（総和）を描く。** 直線だけで描ける点は√と同じだが、`Σ` は数学以外でも
  よく使われ（集計、合計）、他のアプリと見分けにくい。√のほうが輪郭が非対称で、
  16pxでも形が残る。
- **2ペイン（左ソース・右プレビュー）の構造を描く。** 何のアプリかは伝わるが、
  16pxでは「2つの四角」にしかならず、他のエディタと区別できない。
- **文字で `M` や `me` を出す。** フォント依存になり、パスに変換すると
  結局は字形を手で持つことになる。数式の道具であることも伝わらない。
- **PNGをビルド時に生成する。** devcontainerの外でもChromiumが要ることになる。
  生成物をコミットして、作り直しは手で流す。
- **`.ico` を置く。** いまのブラウザはSVGかPNGで足りる。増やすほど
  「どれが本物か」が分かりにくくなる。
