# NNNN: タイトル

- 対応issue: [NNNN](../issues/NNNN-slug.md)
- 状態: draft / approved / implemented
- 作成日: YYYY-MM-DD

## 目的

このissueを解決すると、ユーザーにとって何がどう変わるか。1〜2段落。

## 仕様

実装すべき振る舞いを具体的に書く。UIがあるなら画面のどこに何が出るか、
どの操作でどうなるかを書く。データを持つなら形と保存先を書く。

### 対象ファイル

触る予定のファイルと、それぞれで何をするか。

## 受け入れ基準

「こう操作すると、こうなる」の形で書く。実装が終わったらこの一覧を実際に
上から確認する。検証できない基準は書かない。

- [ ] （操作）すると（期待結果）になる
- [ ] （操作）すると（期待結果）になる
- [ ] `npm run build` と `npm run lint` が通る

## 検討したが採らなかった案

なぜ採らなかったかとセットで。後から蒸し返さないための記録。

## スコープ外

この仕様では扱わないこと。別issueにするものはissue番号を書く。
