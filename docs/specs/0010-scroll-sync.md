## 目的

長い文書を書いているとき、いま編集している段落がプレビューのどこにあるのかを
探さずに済むようにする。エディタをスクロールすると、プレビューの対応する位置が
一緒に動く。

また、リロードしても続きから書けるようにする。いまは内容は復元されるが
（[0001](0001-autosave.md)）、スクロール位置とカーソルは先頭に戻るので、
長い文書では毎回「どこまで書いたか」を探し直すことになる。

## 仕様

### 1. 行の対応づけ — 割合ではなく行番号で合わせる

issueのメモにある2案のうち、**行番号で合わせる案を採る**。割合（スクロール量の比）は
ソースの1行と出力の高さが対応しないため、ブロック数式・表・コードブロックを含む
文書で大きくずれる。このエディタは数式を書くためのものなので、いちばんずれる
ところで使えないことになる。

`renderMarkdown` の出力するトップレベルのブロック要素に、そのブロックが始まる
**元ソースの行番号**を `data-line="N"`（1始まり）として付ける。

```
# 見出し          →  <h1 data-line="1">見出し</h1>
                     （空行）
本文              →  <p data-line="3">本文</p>
```

- 付けるのはトップレベルのブロックだけ。入れ子（リストの項目、表のセル）には付けない。
  アンカーは数十〜数百あれば足り、細かくするほど測定のコストが増える。
- 何も出力しないトークン（空行）には付けない。
- KaTeXの出力（差し戻される数式HTML）には付けない。パイプラインの **5** は
  サニタイズの後なので、`data-line` は **3** の時点で入り、**4** を通って残る。

実装は `marked.lexer()` でトップレベルのトークンに分け、トークンごとに
`marked.parser([token])` して先頭の開始タグに属性を差し込み、連結する。

**行番号は数式を退避する前のソースで数える。** `$$...$$` は複数行を1つの
プレースホルダに畳むので、退避後のテキストで数えると以降の行が全部ずれる。
`extractFormulas` に、退避したテキスト上の位置と元ソース上の位置の対応
（プレースホルダごとの開始位置と、元の文字列が含む改行の数）を返させ、
そこから元ソースの行番号に直す。

### 2. エディタ側の行の位置を測る

`<textarea>` は行の座標を返さないので、同じ書体・同じ幅・同じ折り返しの
**ミラー要素**を隣に置いて測る。

- `.editor-mirror` は `position: absolute` / `visibility: hidden` /
  `pointer-events: none` / `aria-hidden` で置く。**画面が占める幅・高さは 0px**
  （絶対配置なので他の要素を1pxも押しのけない）。見える要素は増えない。
- 中身はソースを分割したテキストで、アンカー行（プレビューに `data-line` が
  付いた行）の先頭に `<span data-line="N">` を置く。各spanの `offsetTop` が
  その行のエディタ内のy座標。
- 測り直すのは、ソースが変わったとき（プレビューと同じ `useDeferredValue` の
  値を使う）と、ペインの幅が変わったとき（`ResizeObserver`）。
  スクロールのたびには測らず、直前の測定結果を使う。

### 3. 同期（エディタ → プレビュー）

エディタの `scroll` で、`requestAnimationFrame` に1回だけまとめて次を行う。

1. エディタの `scrollTop` を、測ったアンカーのy座標の列に照らして
   「上端に見えている位置」を行番号（小数を含む）として求める。
2. プレビュー側の `data-line` 要素のうち、その行番号を挟む2つを選び、
   両者の `offsetTop` を線形補間してプレビューの `scrollTop` にする。
3. アンカーより手前なら先頭（0）、最後のアンカーより後ろなら、最後のアンカーと
   文書末尾の間で同じように補間する。

補間の計算は DOM に触らない純粋関数 `lib/syncScroll.ts` に出し、単体テストで固める。
DOMから値を読むのと `scrollTop` に書くのだけがコンポーネント側に残る。

**逆方向（プレビュー → エディタ）は作らない。** 片方向なら「いまプレビューが
動いたのは自分がエディタを動かしたからだ」が常に成り立ち、同期の打ち消し合いを
見張る必要がない。

### 4. 位置の保存と復元

保存先は [0001](0001-autosave.md) の `matheditor:document:v1`。**版は上げず、
任意フィールドとして足す**（古いデータは欠けているだけで読める。新しいデータを
古いコードが読んでも、知らないフィールドを無視して本文は読める）。

```
キー: matheditor:document:v1
値:   { "version": 1, "source": "...", "savedAt": "...",
        "cursor": 1234, "topLine": 57 }
```

- `cursor` は `selectionStart`。数値でない・範囲外なら無視して0として扱う。
- `topLine` はエディタの上端に見えている行番号（1始まり、小数可）。
  ピクセルではなく行で持つのは、次に開いたときの画面幅や書体が違っても
  同じ場所に戻るため。
- 読み込み時に数値でなければ、そのフィールドだけ「なし」として扱う。
  壊れた値で起動を壊さない（0001と同じ方針）。

保存のタイミングは本文と同じ600msのデバウンス。ただし
**本文が変わらず位置だけが変わったときは、保存状態の表示を変えない**
（スクロールしただけで「保存中…」が点滅するのは、保存の表示の意味を薄める）。
`beforeunload` でも書き切る。

復元は起動時に1回。`cursor` を `setSelectionRange` で当ててエディタに
フォーカスし、`topLine` が上端に来るようエディタをスクロールする。
プレビューは3の同期で追従する。保存がなければ何もしない（先頭から）。

## 未確認の前提

**確かめたもの**（仕様を書く前に実行して確認した）:

- DOMPurify は `data-line` 属性を落とさない（`USE_PROFILES` に `html` を
  含めた現在の設定のまま、`<p data-line="3">` が残ることを確認）。
- `marked.lexer()` でトップレベルに分け、トークンごとに `marked.parser([token])`
  した結果を連結すると、文書全体を `marked.parse()` した結果と一致する
  （見出し・段落・箇条書き・表・引用・コードフェンスを含む文書で確認）。

**確かめていないもの**:

- `<textarea>` とミラー要素の折り返し位置がChromiumで一致すること。
  `font` / `width` / `padding` / `border` / `white-space` / `word-break` /
  `overflow-wrap` / `tab-size` を揃える必要があり、1つでも漏れるとずれる。
  実装はここの確認から始める。
- 400節の文書でミラーの構築と測定に何msかかるか。入力のたびに測ると
  [0007](0007-preview-performance.md) で作った余裕を食う可能性がある。
- プレビューのKaTeXが使うフォントの読み込みが終わる前に `offsetTop` を測ると、
  読み込み後に位置が変わってずれる可能性。
- 位置だけの保存が、既存の `autosave` 区分14件（保存表示の遷移を見ている）に
  影響しないこと。

これらが崩れたら、実装を続けずに仕様へ戻る。

## 検討したが採らなかった案

- **割合（スクロール量の比）で合わせる。** 実装は10行で済むが、ブロック数式・表・
  コードブロックのところでずれる。このエディタでいちばんよく使う書き方が
  いちばんずれるので、「探さずに済む」という目的を満たさない。
- **アンカーを全行に置く。** 対応は最も正確になるが、400節の文書でspanが
  数千個になり、測定のコストが入力の体感に出る。ブロック単位で足りる。
- **`scrollTop` をピクセルで保存する。** 画面幅や書体が変わると別の場所に戻る。
  行で持てば幅が変わっても同じ段落に戻る。
- **保存形式の版を2に上げる。** 上げると、版違いを「保存なし」として捨てる
  現在の読み込み（0001）に引っかかり、既存の利用者の本文が消える。
  任意フィールドを足すだけなら、古いデータも新しいデータも読める。
- **プレビュー → エディタの逆方向同期。** 打ち消し合いの抑止が要る。
  issueでも「まず片方向で使ってみる」としている。

## スコープ外

- 逆方向（プレビュー → エディタ）の同期。使ってみてから別issueで判断する。
- プレビューのクリックでソースの該当箇所へ飛ぶこと（[0020](../issues/0020-preview-click-to-edit.md)）。
  ただし本仕様で入る `data-line` は0020の土台になる。
- エディタの行番号表示、シンタックスハイライト。
- 複数文書ごとの位置の保存（[0004](../issues/0004-multi-document.md)）。
