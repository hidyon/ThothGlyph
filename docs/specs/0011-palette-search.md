# 0011: 記号パレットの検索

- 対応issue: [0011](../issues/0011-palette-search.md)
- 状態: implemented
- 作成日: 2026-09-19

## 目的

いまパレットは8つのタブに分かれており、目的の記号がどのタブにあるかを覚えて
いないと往復する。記号62件と公式60件、合わせて122件がタブの奥にある。

検索欄に打てば、タブを意識せず全グループを横断して絞り込めるようにする。
`\int` のようなコマンド名でも「積分」「integral」のような名前でも引ける。
キーボードだけで、絞り込み → 選択 → 挿入まで終わる。

## 仕様

### 1. 検索欄の置き場所と大きさ

**検索欄はタブ行の右端に置く**（`margin-left: auto`）。パレットに新しい行を
作らない。[0032](../issues/0032-palette-height-narrow.md) が言うように狭い画面では
パレットが既に画面の3割を占めており、行を増やすといちばん狭いところで効く。

実測（現状、日本語表示、`.palette` の高さ）:

| 幅 | パレット | タブ行 | タブ行の最終行に残っている幅 |
|---|---|---|---|
| 1280px | 94px | 36px（1行） | 606px |
| 720px | 94px | 36px（1行） | 46px |
| 600px | 126px | 68px（2行） | 433px |

検索欄は `flex: 0 1 180px` / 高さ28px（タブの高さ30pxより低い）で置く。上の表から、

- 1280px: タブ行に180pxが収まるので**パレットの高さは94pxのまま（増分0px）**。
- 600px: タブは既に2行で、2行目に433px空いているのでそこに収まる。
  **126pxのまま（増分0px）**。
- 720px: 残り46pxに180pxは入らないので折り返して2行になる。
  **94px → 126px（増分32px = タブ高さ30px + gap 2px）**。
  これは現状の600pxでのパレット高さと同じで、それ以上には増えない。

受け入れ基準では3つの幅すべてで **126px以下**であることを測る。

**実装後の実測**: 1280px = 94px（増分0）、720px = 124px、600px = 126px（増分0）。
見込みどおり、どの幅でも126pxを超えなかった。

### 2. 検索の規則（`lib/search.ts`、純粋関数）

```ts
export type SearchHit =
  | { kind: 'symbol'; item: PaletteItem; group: Text }
  | { kind: 'formula'; formula: Formula; group: Text }

export function searchPalette(query: string): { hits: SearchHit[]; omitted: number }
```

- **照合するもの**: 記号は `label`（LaTeX）と `title` の日英両方。公式は `name` の
  日英両方と `preview`（LaTeX）。`snippet` は照合しない（`%CURSOR%` や `$$` に
  当たって直感に反する一致が出る）。
- **正規化**: 照合する側とクエリの両方から `\` `{` `}` `^` `_` と空白を取り除き、
  小文字にする。これで `\alpha` / `alpha` / `ALPHA` が同じものを引き、
  `frac` が `\frac{a}{b}` に当たる。
- **表示言語に関わらず日英両方で引ける。** 日本語表示のまま `integral` と打っても
  出る。言語ごとに引ける語が変わるほうが驚きが大きい。
- **部分一致。** 曖昧検索もスコアリングもしない（issueの「やらないこと」）。
  ただし並び順だけは**前方一致を部分一致より先**にする。`pi` と打ったときに
  `\pi` が `\varpi` や `\epsilon` より先に来ないと使えない。同順のものは
  パレットの定義順（記号の8グループ → 公式の12分類）。
- **上限40件。** 超えた分は返さず `omitted` に件数を返す。`a` のような1文字では
  100件近く当たり、画面がパレットで埋まる。
- 空文字と空白だけのクエリは0件（検索していない状態として扱う）。

### 3. 検索中の画面

クエリが空でない間は、タブの中身の代わりに**検索結果のパネル**を出す。

- タブは消さずに並べたまま、**どのタブも選択状態にしない**
  （`aria-selected="false"`、`palette__tab--active` を付けない）。
  横断検索なので「いま基本タブを見ている」は嘘になる。
- 結果のボタンは既存のものを使い回す。記号は今と同じLaTeXのボタン、公式は
  今と同じ「名前＋式」のボタン。tooltipは今の `describeInsertion` の文言に
  グループ名を添える（`messages.inGroup`。日本語は `分数（選択範囲を囲む）［基本］`、
  英語は `Fraction (wraps selection) [Basic]`）。
- 1件も当たらなければ `一致する記号がありません` / `No matching symbols` を出す。
- 上限を超えたときだけ、末尾に `他N件` / `N more` を出す。
- タブをクリックすると検索を終える（クエリを空にして、そのタブを表示する）。
- クエリを空に戻すと、**検索を始める前に見ていたタブに戻る**（選択は保持している）。
- 挿入してもクエリは消さない。同じ記号を続けて入れられる。

### 4. キーボードだけで完結する

| 場所 | キー | 動き |
|---|---|---|
| 検索欄 | 文字入力 | 絞り込む |
| 検索欄 | `Enter` | 先頭の結果を挿入する（フォーカスはエディタへ戻る） |
| 検索欄 | `↓` | 先頭の結果のボタンへフォーカスを移す |
| 検索欄 | `Esc` | クエリを空にする。既に空ならエディタへフォーカスを戻す |
| 結果のボタン | `↓` `→` / `↑` `←` | 次 / 前の結果へフォーカスを移す |
| 結果のボタン | `Enter` `Space` | 挿入する（ボタンの既定動作） |
| 結果のボタン | `Esc` | 検索欄へフォーカスを戻す |

矢印は**並び順の前後**として扱う。折り返しの位置はDOMを測らないと分からず、
測るほどの価値がない（1次元で足りる）。

挿入は既存の `onInsert`（`App.handleInsert`）をそのまま呼ぶ。挿入後に
エディタへフォーカスが戻るのも既存の挙動のまま。

**検索欄にフォーカスを移しても、textareaの選択範囲は失われてはならない。**
`handleInsert` は `textarea.selectionStart` を読んで [0009](0009-wrap-selection.md) の
「選択を囲む」を実現している。ここが崩れると0009の回帰になるので、
実装は最初にこれを確かめる（下の「未確認の前提」）。

- ~~**検索欄にフォーカスがある間も、textareaの `selectionStart` / `selectionEnd` が
  保たれること。**~~ 実装前にChromiumで確認した。選択範囲を作ってから
  `<input type="search">` にフォーカスを移し、文字を打っても

- flex-wrap のタブ行に180pxの入力欄を足したときの折り返しが、1節の予測どおりに
  なること（表の実測値は入力欄が無い状態のもの）。
- 日本語IMEの変換中にも `onChange` が走り、確定前の文字で結果が入れ替わること。
  変換中を特別扱いしない前提で進める（`積分` の変換途中に `せきぶん` で
  0件になっても、確定すれば当たる）。読み仮名での検索は持たないので、
  `せきぶん` では引けない。
- ~~上限40件が多すぎないか~~ **崩れた。** 実測すると、幅600pxで `a` と打った
  ときパレットが画面の65%（523px）を占め、ソースが82px（2行）しか残らなかった。
  16件でも55%。公式のボタンが幅広で1行に1〜2件しか入らないため、件数を
  減らすだけでは足りない。ユーザーと相談して**結果の欄に高さの蓋を付ける**

## 実装中に変えたこと

1. **結果の欄に高さの蓋を付けた**（`max-height: min(168px, 21vh)` とスクロール）。
   理由は上の「未確認の前提」のとおり。上限40件は残してある（返す件数の上限と、
   画面の占有の上限は別のもの）。実測は幅600px・40件でパレットが画面の30%、
   ソースが225px残る。
2. **受け入れ基準の `taylor` を `parts` / `部分積分` に直した。** 公式60件に
   テイラー展開は無く、仕様を書いた時点で実データを確かめていなかった。
3. **「挿入するとプレビューの `.katex` が1つ増える」を「∫として描画される」に
   直した。** 既存の `$x$` の中に挿入するので数式の数は増えない（1 → 1 で落ちた）。
   0029と同じく、描画された形で見るほうが強い基準になる。
4. **検索欄は `.palette__tabs` の子ではなく、`.palette__bar` の子にした。**
   `role="tablist"` の子に入力欄を置くのはARIA的に正しくない。タブは
   `display: contents` で同じ行に並べ、`role="tablist"` の入れ物は残した。

## 検討したが採らなかった案

- **検索欄を独立した行に置く。** 見た目は素直だが、どの幅でもパレットが
  約40px高くなる。0032で「パレットが画面の3割」と言っている狭い画面で、
  足すいちばん悪い場所になる。
- **検索を9番目のタブにする。** タブを押してから打つことになり、
  「タブの往復をやめたい」という目的と逆を向く。
- **読み仮名（`せきぶん`）を持たせる。** 122件すべてに読みを足すことになり、
  以後の追加で1件あたり書くものが増える（[0031](0031-english-ui.md) で
  「1行に日英を書くだけで済む」ようにした形を崩す）。まず名前とコマンド名で
  引いてみて、足りなければ別issueにする。
- **曖昧一致・スコアリング。** issueの「やらないこと」。前方一致を先に出す
  並べ替えだけで、実用上どこまで足りるか見る。
- **タブを検索結果タブに置き換える（タブが1つ増える）。** 検索を終えたときに
  どのタブへ戻るかが曖昧になる。タブの選択は保持したまま、表示だけ差し替える。

## スコープ外

- 検索欄にフォーカスを当てるショートカット（`Ctrl+K` など）。
  キー操作全体は [0008](../issues/0008-keyboard-shortcuts.md) で扱う。
- 挿入後に検索欄へフォーカスを戻す連続挿入モード。
- 読み仮名検索、曖昧検索、履歴・よく使う記号。
- プレビューから記号を選ぶ経路（[0020](../issues/0020-preview-click-to-edit.md)）。
