# 0012: .mdファイルの読み込み

- 対応issue: [0012](../issues/0012-file-io.md)
- 状態: implemented
- 作成日: 2026-09-20

## 目的

いま手元の `.md` を matheditor で開く手段がない。エディタに貼り付け直すしかなく、
長い文書ほど面倒になる。このissueで、**手元の `.md` を開いて続きが書ける**
ようにする。入口はファイル選択のボタンとドラッグ＆ドロップの2つ。

書き出し（ダウンロード）は [0034](../issues/0034-file-save.md) で別に扱う。

## 置き場所の実測

[0033](0033-toolbar-overflow-phone.md) で基準幅を360pxまで下げたので、
先に置き場所を測った（ヘッドレスChromium、高さ667px）。

**ツールバーには置けない。** 幅360pxでボタン4つの右端は350px、右のpaddingは10pxで、
5つ目を足す余地がない（0033の実測）。

**ソースペインの見出し行には余地がある。** 幅360pxで見出し行は360px幅あり、
「ソース」の文字は37px（英語 `Source` は49px）しか使っていない。
ここに「ファイルを開く」ボタン（実測106×29px）を置き、見出し行を
`display: flex` + `justify-content: space-between` にして右端へ寄せる。

ただし**そのまま足すと見出し行が30px → 36pxに高くなり**、幅375pxのtextareaが
207px → 201pxに減る（0032・0033で守ってきた207pxを割る）。
見出し行の縦paddingを `6px` → `0`、`min-height: 30px` にして、ボタンの
paddingを `5px 10px` にすると高さが変わらない。この組み合わせで測った結果:

| 画面幅 | 見出し行の高さ（ソース/プレビュー） | ボタン | textareaの高さ | 横スクロール |
|---|---|---|---|---|
| 1440px | 30 / 30px（変化なし） | 106×29px | 488px（変化なし） | なし |
| 600px | 30 / 30px（変化なし） | 106×29px | 227px（変化なし） | なし |
| 375px | 30 / 30px（変化なし） | 106×29px | 207px（変化なし） | なし |
| 360px | 30 / 30px（変化なし） | 106×29px | 207px（変化なし） | なし |

`min-height` を入れるのは、縦paddingを0にするとボタンのないプレビュー側の
見出し行だけが縮んで左右でずれるため。

## 仕様

### 入口1: ファイルを開くボタン

ソースペインの見出し行の右端に `ファイルを開く` / `Open file` を置く。
押すと `<input type="file">`（画面に出さない）を開く。
`accept=".md,.markdown,.txt,text/markdown,text/plain"`。

### 入口2: ドラッグ＆ドロップ

**ソースペイン全体**（`.pane--editor`）がドロップ先。ファイルを重ねている間は
ペインの枠を強調色にする（**大きさは変えない**。ドロップ領域の表示で
レイアウトが動くと、下のプレビューまでずれる）。
ブラウザ既定の「ファイルを開いて表示」は `preventDefault` で止める。

### 読み込みの判定と正規化

受け取ったファイルは、この順で見る。

1. 2件以上ドロップされた → 何も読まず `一度に開けるのは1つだけです`
2. 拡張子が `.md` / `.markdown` / `.txt` のどれでもない → `.md ファイルを選んでください`
3. 1MBを超える → `ファイルが大きすぎます（上限1MB）`
4. 読み取りに失敗した → `ファイルを読み込めませんでした`

上限を1MBにする根拠: [0007](0007-preview-performance.md) の検証で扱えている
400節・400数式の文書が**26.9 kB**（実測）。その約38倍にあたり、
これを超える文書はプレビューの性能以前に自動保存（localStorage）が通らない。

読めたテキストは、エディタへ入れる前に正規化する。

- 先頭のBOM（`﻿`）を取り除く
- 改行を `\r\n` / `\r` → `\n` に揃える

### 置き換えの確認

読み込みは編集中の内容を**置き換える**（[0001](0001-autosave.md) で保存された
内容も上書きされる）。そのため「サンプルに戻す」と同じく、置き換える前に
確認ダイアログを出す。

> `編集中の内容を破棄して <ファイル名> を読み込みます。よろしいですか？`
> （`Discard what you have written and open <ファイル名>?`）

- OKなら置き換える。置き換えた内容は通常どおり自動保存される。
- キャンセルなら**何も変わらない**（エディタも保存も触らない）。
- 確認は**内容が空でも出す**。出す・出さないの条件を持つと、
  「今回は出なかった」理由が画面から分からなくなる。

### 結果の表示

コピーの結果と同じ枠（`.toolbar__status`）に出し、数秒で消える。

| 結果 | 表示 |
|---|---|
| 読み込めた | `<ファイル名> を読み込みました` / `Opened <ファイル名>` |
| 断った・失敗した | 上の判定の文言 |

同じファイルを続けて2回選べるよう、読み込み後は `<input>` の値を空に戻す。

### 対象ファイル

- `src/lib/loadMarkdownFile.ts`（新規） — 判定と正規化の純粋関数。
  `checkFile(name, size)` が `ok` か拒否の理由を返し、`normalizeText(text)` が
  BOMと改行を揃える。ファイルの読み取り自体（`File.text()`）は呼ぶ側に置く。
- `src/lib/loadMarkdownFile.test.ts`（新規） — 上の2つの単体テスト。
- `src/components/Editor.tsx` — 見出し行にボタンと `<input type="file">`、
  ペインに `onDragOver` / `onDragLeave` / `onDrop`。
- `src/App.tsx` — 読み込みの結果を受けて本文を置き換え、結果の表示を渡す。
- `src/lib/messages.ts` — 文言を2言語で足す（ボタン、確認、結果4種）。
- `src/index.css` — 見出し行のflex化と `min-height: 30px`、ボタン、ドロップ中の枠。
- `scripts/verify-ui.mjs` — 区分 `file-load` を新設する（既存の区分は消さない）。
- `docs/` の4文書 — 機能仕様に操作を、テスト仕様にチェック一覧を足す。

## 未確認の前提

- Playwrightの `setInputFiles` は画面に出していない（`display: none` の）
  `<input type="file">` にも入れられる、と考えているが確かめていない。
  入らなければ、検証では `<input>` を一時的に見える状態にするのではなく、
  **入力要素を画面外に置く形**（`.sr-only` 相当）へ実装のほうを変える。
- ドラッグ＆ドロップは、PlaywrightでDataTransferを組み立てて `drop` を
  発火させれば検証できると考えているが、確かめていない。
  できなければドロップの検証だけ手動にし、そう記録する。
- `File.text()` はdevcontainerのChromiumで使える（Safari 14以降/Chrome 76以降）と
  考えているが、このプロジェクトで使うのは初めてなので確かめていない。

## 実装で分かったこと（未確認の前提の答え）

- **`setInputFiles` は視覚的に隠した `<input type="file">` にも入った。**
  ただし `input[type="file"]` 自身が `role=button` として数えられるため、
  `getByRole('button', { name: 'ファイルを開く' })` が2件当たった。
  `<input>` に `aria-hidden="true"` を付け、入口を見えるボタン1つに絞って解決した。
- **ドラッグ＆ドロップはPlaywrightで検証できた。** `DataTransfer` を
  `evaluateHandle` で組み立て、`dispatchEvent('dragover' / 'drop')` に渡す形。
  手動検証に落とさずに済んだ。
- **`File.text()` はdevcontainerのChromiumで動いた。**
- 仕様に書いていなかったことが1つあった。`.button--small` を
  `.button` と同じ詳細度で書くと、幅720px以下の `.button`（`padding: 7px 12px`）に
  後ろから上書きされ、見出し行が33pxになる（textareaは204px）。
  `.button.button--small` と2つ重ねて詳細度で勝たせた。
- ボタンの見た目は `button--quiet`（枠だけ）にした。既定の `.button` は
  塗りつぶしで、ツールバーの「Markdownをコピー」と同じ強さになる。
  ソースの見出し行のボタンがそれと並ぶのは強調の序列として不自然だった。

## 検討したが採らなかった案

- **ツールバーにボタンを足す**。幅360pxで余地がない（上の実測）。
  文言をさらに短くすれば入るが、0033で短縮したばかりのボタンを
  もう一段削ることになり、何のボタンか読めなくなる。
- **File System Access API（`showOpenFilePicker`）**。開いたファイルへ
  そのまま上書き保存できるが、Safari・Firefoxが対応していない。
  0012の「やらないこと」にも書いてある。
- **確認なしで読み込み、Undoで戻せるようにする**。Undoは
  [0021](../issues/0021-undo.md) が未解決で、いま乗せる土台がない。
- **ドロップ先をtextareaだけにする**。ペインの余白（見出し行や下端）に
  落としたときに黙って無視されるより、ペイン全体で受けるほうが外しにくい。

## スコープ外
