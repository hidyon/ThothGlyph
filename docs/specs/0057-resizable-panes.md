# 0057: 3つの領域の幅をドラッグで変えられるようにする

- 対応issue: [0057](../issues/0057-resizable-panes.md)
- 状態: implemented
- 作成日: 2026-09-20

## 目的

パレット180px・ソース630px・プレビュー630px（幅1440px）はCSSが決めていて、
利用者は変えられない。書いているときはソースを、読み返すときはプレビューを
広くしたい。領域の境目をドラッグして分け方を変えられるようにし、
その分け方を次に開いたときも保つ。

## 仕様

### 1. 仕切りは2本、幅1200px以上でだけ動かせる

```
[ パレット ]│[ ソース ]│[ プレビュー ]
           ↑         ↑
        仕切り1     仕切り2
```

- 仕切りは**グリッドの列として6px**を占める（2本で12px）。
- **幅1199px以下では仕切りを出さない。** 横帯（パレットが上）では
  パレットとの境目が縦ではないうえ、幅720px以下は上下分割になるため。
  幅1200px未満に狭めたときは、保存した値を使わず既定の分け方で描く。

### 2. 下限

| 領域 | 下限 | 根拠 |
|---|---|---|
| パレット | **150px** | タブ名が折り返さない下限（実測） |
| ソース | **360px** | 見出し行のボタン3つが1行に収まる下限（実測） |
| プレビュー | **360px** | グラフが312pxで0037の検証値と同じ。240pxで数式がはみ出す |

下限に達したらそれ以上動かない（ドラッグしても値が変わらない）。
**画面が狭くて3つの下限＋仕切り12pxの合計（882px）に足りないときは、
保存値を捨てて既定に戻す**（幅1200px以上でだけ可変なので、通常は起こらない）。

### 3. 操作

- **ドラッグ**: 仕切りを押して左右に動かす。離した時点の値を保存する。
- **キーボード**: 仕切りは `tabindex="0"` で `role="separator"`
  （`aria-orientation="vertical"`）。左右キーで**16px**ずつ動く。
- **ダブルクリック**: その仕切りを既定（パレット180px / ソースとプレビューは半々）に戻す。
- ドラッグ中はカーソルを `col-resize` にする。

### 4. 保存の形

テーマ（`matheditor:theme:v1`）と同じ形で、専用のキーに持つ。

```json
{ "version": 1, "palette": 180, "sourceRatio": 0.5 }
```

- `palette` は**px**（下限150px）。
- `sourceRatio` は**ソースとプレビューの合計に対するソースの割合**（0〜1）。
  pxで持つと、ウィンドウを広げたときにソースだけが広がる。
  **割合で持てば、広げたときに両方が広がる。**
- 読めない・壊れている・版違いなら既定（`palette: 180`, `sourceRatio: 0.5`）。
  保存の失敗は握りつぶす（テーマ・言語と同じ。失われるのは分け方だけ）。
- 変換は `src/lib/paneSizes.ts` の純粋関数にまとめ、単体テストで固定する
  （`loadPaneSizes` / `savePaneSizes` / `clampPaneSizes`）。

**入力と出力の例**（`clampPaneSizes(保存値, 画面の幅)`）:

| 保存値 | 画面の幅 | 結果 | なぜ |
|---|---|---|---|
| `{palette: 180, sourceRatio: 0.5}` | 1440px | そのまま | 下限を満たす |
| `{palette: 100, sourceRatio: 0.5}` | 1440px | `palette: 150` | パレットの下限 |
| `{palette: 180, sourceRatio: 0.95}` | 1440px | `sourceRatio: 0.713` | プレビュー360pxの下限 |
| `{palette: 900, sourceRatio: 0.5}` | 1440px | `palette: 516` | ソース360px＋プレビュー360px＋仕切り12pxを残す |

## 実装で変えたところ

- **丸める場所を2回間違えた。** どちらもドラッグが「動かしたぶんだけ動かない」形で出た。
  - `clampPaneSizes` がパレットの幅を毎回 `Math.round` していたため、
    12ステップのドラッグで**100pxのつもりが96px**しか動かなかった。
  - 同じく `sourceRatio` を3桁に丸めていたため、ソース側も96pxになった。
  - 丸めるのは**画面に当てるとき（`paneColumns`・`--palette-width`）と
    保存するときだけ**に寄せた。`paneColumns` は3桁だと幅1440pxで0.6pxずれて
    下限の360pxを359pxにするので、**5桁**にしてある。
- **`.panes` にインラインで `grid-template-columns` を当てたら、狭い画面が壊れた。**
  インラインスタイルはメディアクエリより強いので、幅720px以下の上下分割まで
  3列のままになり、`layout` `file-load` `file-save` `find` `graph` の
  **19件が落ちた**（見出し行が52/86px、textareaが185px、目盛りが0px）。
  App からは CSS変数（`--pane-columns`）で渡し、当てるのは幅1200px以上の
  メディアクエリの中だけにした。
- **仕切りの `grid-row: 2` が `.panes` の中の仕切りにも効いていた。**
  1行しかない `.panes` に2行目ができ、プレビューが6pxの列へ押し出された。
  `.app > .pane-divider` に絞った。
- **0054の基準「プレビューが625px以上」を620pxに直した。** 仕切り2本（12px）が
  入ったぶん、幅1440pxのプレビューは630px → **624px**になる。仕様どおりの
  帰結なので、比べる意図（横帯の720pxとの差）を保ったまま数値を移した。
  `docs/functional-spec.md` の数値も直した。

## 未確認の前提

- **ドラッグ中の再描画コスト。** → **16.5ms/回**（400節の文書、仕切りの
  操作1回あたり）。100msの基準に対して十分速く、**離すまで反映しない形に
  変える必要はなかった**。
- `role="separator"` に `tabindex` を付けたとき、Chromiumが
  `getByRole('separator')` で拾えること。
  → 検証では `.pane-divider` で掴んでおり、`getByRole` は使っていない。
  フォーカスと左右キーは効くことを確かめた（16pxずつ動く）。
- ダブルクリックとドラッグ開始が競合しないこと。
  → **競合しなかった**（ダブルクリックで既定に戻り、その後もドラッグできる）。

## 検討したが採らなかった案

- **pxで両方を保存する。** ウィンドウを広げたときにソースだけが広がる。
  割合で持てば両方が広がる。
- **仕切りを境界線の上に重ねる（絶対配置）。** 列を消費せずに済むが、
  位置の計算を自分で持つことになる。グリッドの列にすれば
  ブラウザが位置を決める（代償は12px）。
- **幅721〜1199pxでもソースとプレビューだけ可変にする。** 幅721pxでは
  左右が360.5pxずつで既に下限なので、動かせる余地がほとんどない。
  [0054](0054-palette-placement.md)と同じ1200pxの線で揃える。
- **領域を閉じられるようにする。** [0022](../issues/0022-narrow-pane-switch.md)
  （狭い画面での切り替え）と混ざる。別issueのまま残す。
