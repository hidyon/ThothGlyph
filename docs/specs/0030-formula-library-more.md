# 0030: 公式をさらに30件追加する

- 対応issue: [0030](../issues/0030-formula-library-more.md)
- 状態: implemented
- 作成日: 2026-09-19

## 目的

[0018](0018-formula-library.md) で6分類30件を収録したが、高校数学の範囲でも
**ベクトル・図形と方程式・確率・複素数が1件も入っていない**。微分・積分も
基本形だけで、部分積分や置換積分がない。

0018の仕様は「この一覧が仕様であり、増減は別issueにする」としたので、
その受け皿がこのissue。30件足して**合計60件・12分類**にする。

## 仕様

### 1. 追加する30件（6分類×5件）

| 分類 | 公式 |
|---|---|
| **ベクトル** | 内積、なす角、大きさ（成分）、平行条件、内分点 |
| **図形と方程式** | 2点間の距離、点と直線の距離、円の方程式、直線の方程式、円の接線 |
| **確率・統計** | 順列、組合せ、余事象、条件付き確率、期待値 |
| **複素数** | 絶対値、共役との積、極形式、ド・モアブルの定理、和の共役 |
| **微分・積分（応用）** | 商の微分、合成関数の微分、部分積分、置換積分、回転体の体積 |
| **極限・不等式** | sin x / x の極限、e の定義、二項定理、相加相乗平均、三角不等式 |

**この一覧が仕様。** 増減はさらに別issueにする（0018と同じ約束）。

既存の6分類（方程式・三角比・三角関数・指数対数・数列・微分積分）は**変えない**。
微分・積分の追加分は `微分・積分（応用）` という別分類にして、既存の
`微分・積分` には手を入れない。既存の分類に足すと、0018で合意した一覧が
崩れるため。

### 2. データの形は変えない

`formulas.ts` の `formula(name, preview)` をそのまま使う。
`CURSOR_TOKEN` は 0018 で決めた置き方（**最初に書き換えたくなる記号の直前**、
トークンを取り除いた文字列がLaTeXとして正しくなる位置）に従う。

`block()` が `\n$$\n...\n$$\n` を作るので、挿入の形も変わらない。

### 3. テストの期待値を直す

`formulas.test.ts` の「6分類・30件」「各分類5件ずつ」を
**12分類・60件**・各5件に直す。全件走査（KaTeXでエラーにならない、
`CURSOR_TOKEN` がちょうど1つ、名前が重複しない）はそのまま効く。

### 対象ファイル

| ファイル | すること |
|---|---|
| `src/lib/formulas.ts` | 6分類30件を追加。既存の30件には触らない |
| `src/lib/formulas.test.ts` | 件数の期待値を12分類60件に直す |
| `scripts/verify-ui.mjs` | `formula` 区分の「6分類」を12分類に直し、追加分の確認を足す |
| `docs/functional-spec.md` / `docs/test-spec.md` | 収録内容と件数を更新 |

`SymbolPalette.tsx` と `index.css` は**触らない**見込み。分類が増えるだけで
描画の仕組みは同じ（[0029](0029-greek-complete.md) と同じく、データ駆動が
守られているかの確認になる）。

## 測定の記録

### 幅600px（2段目タブが12分類になった影響）

| 項目 | 実測 |
|---|---|
| 2段目のタブ | **2行**（6分類のときは1行） |
| パレットの高さ | **279px**（0018の測定では207px） |
| 横スクロール | 出ない |

**画面の高さ900pxに対して31%をパレットが占める。** 高さ667pxの
スマートフォンなら42%になる。0018から72px増えており、
[0029](0029-greek-complete.md) でタブが1つ増えたぶんと、2段目が2行になったぶん。

これは仕様の想定（「折り返ること自体は問題ない」）を超えていると判断し、
**[0032](../issues/0032-palette-height-narrow.md) として起票した**。
0030のスコープ（公式を足す）では直さない。

### `SymbolPalette.tsx` と `index.css`

**どちらも差分なし。** 分類が6→12に増えても描画の仕組みに触れずに済んだ
（[0029](0029-greek-complete.md) と同じく、データ駆動が守られていることの確認）。

## 検討したが採らなかった案

- **既存の `微分・積分` に5件足して10件にする。** 0018で「各分類5件」と
  合意した形が崩れる。分類を分けるほうが、あとから見て何を足したか分かる。
- **分類を増やさず、既存6分類の中に振り分ける。** ベクトルや複素数は
  既存のどの分類にも入らない。無理に入れると探せなくなる。
- **2段目のタブをスクロールさせる。** 折り返しのほうが全体が見えて探しやすい。
  高さが問題になるなら、そのとき別の見せ方を考える。
