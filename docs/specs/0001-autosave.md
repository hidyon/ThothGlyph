# 0001: 編集内容の自動保存

- 対応issue: [0001](../issues/0001-autosave.md)
- 状態: implemented
- 作成日: 2026-09-19

## 目的

今は編集中のMarkdownがReactのstateにしかないので、リロードやタブを閉じるだけで
書いたものが消える。数式入りの文書は書くのに時間がかかるため、この消失はこのアプリで
いちばん痛い欠陥である。

この仕様で、ユーザーは何も操作しなくても編集内容がブラウザに残り、次に開いたときに
続きから書けるようになる。あわせて「保存されている」ことと「いつ保存されたか」が
ツールバーで分かるようにし、保存後もサンプル文書に戻せる道を残す。

## 仕様

### 1. 保存形式と保存先

`localStorage` のキー `matheditor:document:v1` に、次のJSONを1件だけ持つ。

```json
{ "version": 1, "source": "# 見出し\n...", "savedAt": "2026-09-19T12:34:56.789Z" }
```

- `version` は将来 0004（複数文書）で形式を変えるときの識別子。読み込み時に
  `version !== 1` なら「保存なし」として扱う（壊れたデータで起動を壊さない）。
- `savedAt` はISO 8601のUTC文字列。表示は現地時刻に変換する。
- キーに `document` を含めるのは、0004で `matheditor:documents:v2` のように
  複数形へ移れるようにするため。今回の実装では1件しか書かない。

### 2. 保存のタイミング

- `source` が変わってから **600ms** 入力が止まったら保存する（デバウンス）。
  1文字ごとに書くとlocalStorageへの同期書き込みが入力を重くするため。
- ページを離れるとき（`beforeunload`）に、未保存の変更があれば即座に保存する。
  デバウンス待ちの内容が失われないようにする。
- 初回表示の直後（まだ何も編集していない状態）には保存しない。サンプル文書を
  そのまま保存済みにしてしまうと「初回訪問時はサンプル」という区別が消える。

### 3. 起動時の復元

1. `localStorage` から読む。読めて `version === 1` で `source` が文字列なら、
   それを初期値にする。
2. 読めない（キーがない／JSONが壊れている／`localStorage` が例外を投げる）場合は
   サンプル文書を初期値にする。この場合エラーは画面に出さない（初回訪問と
   区別できず、出しても読者にできることがない）。

### 4. 保存状態の表示

ツールバーの右側、「Markdownをコピー」ボタンの左に保存状態を出す。
コピー結果のメッセージ（`toolbar__status`）とは別の要素にし、同時に出ても
互いを消さない。文言は次の4状態。

| 状態 | 表示 |
|---|---|
| 保存済み | `保存しました 12:34` |
| 未保存の変更あり（デバウンス待ち） | `保存中…` |
| 保存に失敗 | `保存できません（ブラウザの設定か容量の上限）` |
| 復元なし・未編集 | （何も出さない） |

- 時刻は `HH:MM`（24時間、現地時刻）。秒は出さない（頻繁に変わって視線を奪う）。
- 失敗表示は消さずに出し続ける。保存できていないことは一時的な通知では足りない。

### 5. サンプル文書に戻す

ツールバーに「サンプルに戻す」ボタンを置く。押すと `window.confirm` で
「編集中の内容を破棄してサンプル文書に戻します。よろしいですか？」と確認し、
OKなら `source` をサンプル文書に置き換える。置き換えた内容は通常の編集と同じく
デバウンス後に保存される（=元の内容は失われる。確認ダイアログでその旨を伝える）。

### 6. localStorageが使えない環境

`localStorage` へのアクセス自体が例外を投げうる（プライベートウィンドウ、
サイトデータ無効、容量超過）。読み書きはすべて `try/catch` で囲み、失敗しても
編集は続けられる。書き込み失敗時のみ 4. の失敗表示を出す。

### 対象ファイル

| ファイル | 変更内容 |
|---|---|
| `src/lib/documentStorage.ts` | 新規。`loadDocument()` / `saveDocument(source)` を置く。`localStorage` に触るのはここだけにする |
| `src/lib/documentStorage.test.ts` | 置かない（このリポジトリにテスト基盤がない。受け入れ基準は実機検証で確認する） |
| `src/App.tsx` | 初期値を `loadDocument()` から取る。デバウンス保存と `beforeunload` の配線、保存状態のstate、サンプルに戻すハンドラ |
| `src/components/Toolbar.tsx` | 保存状態の表示と「サンプルに戻す」ボタンを追加。props に `saveState` と `onReset` を受ける |
| `src/index.css` | 保存状態表示のスタイル（`toolbar__save`）。既存のボタンのスタイルを流用する |
| `scripts/verify-ui.mjs` | 受け入れ基準を確認する手順を追記（入力→リロード→復元、サンプルに戻す） |

保存のデバウンスは `App.tsx` 内の `useEffect` + `setTimeout` で書く。ライブラリは足さない。

## 受け入れ基準

- [x] 初回訪問（localStorageが空）でアクセスすると、サンプル文書が表示される
- [x] エディタに文字を入力して1秒待つと、ツールバーに `保存しました HH:MM` が出る
- [x] 入力直後（デバウンス中）は `保存中…` が出ている
- [x] 入力後にリロードすると、入力した内容が復元されている（サンプルではない）
- [x] 入力直後（600ms以内）にリロードしても、入力した内容が復元されている
      （`beforeunload` での保存が効いている）
- [x] 復元した内容の数式がプレビューで正しく描画されている（KaTeXのエラーが出ない）
- [x] 「サンプルに戻す」を押して確認をOKすると、エディタがサンプル文書に戻る
- [x] 「サンプルに戻す」の確認をキャンセルすると、内容が変わらない
- [x] `localStorage` に壊れたJSON（`'{'` など）を入れてリロードすると、
      エラーにならずサンプル文書が表示される
- [x] 一連の操作中にコンソールエラーが出ない
- [x] `npm run build` と `npm run lint` が通る

## 検討したが採らなかった案

- **1文字ごとに保存する。** localStorageは同期APIなので、大きな文書では入力の
  たびにメインスレッドが止まる。デバウンス＋`beforeunload` で消失リスクは十分に
  下げられる。
- **IndexedDBを使う。** 1文書ならlocalStorageの5MBで足りる。非同期APIの分だけ
  コードが増える。容量が問題になるのは0004（複数文書）からなので、そこで判断する。
- **`savedAt` を持たず保存時刻をstateだけに置く。** 「いつ保存されたか」をリロード
  直後にも出したいので永続化する。0004で「最終更新順に並べる」にも使える。
- **「サンプルに戻す」の代わりにUndoで戻れるようにする。** textareaのUndoは
  リロードを跨がないので、保存後にサンプルを二度と見られない問題が解けない。
- **`beforeunload` で「保存されていません」の離脱確認を出す。** 自動保存があるのに
  確認ダイアログが出るのは矛盾していて、かつブラウザが文言を無視する。
