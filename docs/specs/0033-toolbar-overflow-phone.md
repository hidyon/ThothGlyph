# 0033: 幅414px以下でツールバーのボタンが画面から溢れる

- 対応issue: [0033](../issues/0033-toolbar-overflow-phone.md)
- 状態: implemented
- 作成日: 2026-09-20

## 目的

スマートフォンの実幅（360〜414px）でmatheditorを開くと、ツールバーの
「Markdownをコピー」が画面の外へ出て、ページ全体が横スクロールする。
横スクロールしている間は本文のどこを見ているかが分からなくなり、
コピーボタンまで指で送らないと文書を持ち出せない。

このissueで、**幅320pxまで横スクロールなしでツールバーの4ボタンすべてが
画面内に収まる**ようにする。ツールバーの高さは変えないので、0032で確保した
textareaの高さは減らさない。

## 現状の実測

`node tmp/measure-toolbar.mjs` 相当（ヘッドレスChromium、高さ667px、初期表示）で
測った値。`scrollW` は `document.documentElement.scrollWidth`。

| 画面幅 | scrollW（日本語） | 溢れ | scrollW（英語） | 溢れ |
|---|---|---|---|---|
| 600px | 600 | 0 | 600 | 0 |
| 446px | 446 | 0 | 446 | 0 |
| 440px | 440 | 0 | 446 | **6px** |
| 435px | 435 | 0 | 446 | **11px** |
| 430px | 435 | **5px** | 446 | **16px** |
| 414px | 435 | **21px** | 446 | **32px** |
| 375px | 435 | **60px** | 446 | **71px** |
| 360px | 435 | **75px** | 446 | **86px** |

溢れ始めるのは**日本語で435px未満、英語で446px未満**。ツールバーの中身は
それ以上縮まないので、幅を減らしてもscrollWidthは435/446で止まる。

ボタンの実測幅（`.toolbar__actions` の合計は日本語409px・英語420px）:

| ボタン | 日本語 | 英語 |
|---|---|---|
| 言語（`日本語` / `English`） | 65px | 73px |
| テーマ（`自動` / `Auto`） | 52px | 56px |
| `サンプルに戻す` / `Reset to sample` | 117px | 131px |
| `Markdownをコピー` / `Copy Markdown` | 143px | 128px |

幅360pxでツールバーに使える幅は、padding 10+10・アイコン20px・gap 16pxを引いて
**304px**。日本語で105px、英語で116px足りない。言語・テーマはすでに
`.button__label`（「言語: 」「テーマ: 」）を隠しており、これ以上削るところがない。
残りは「サンプルに戻す」と「Markdownをコピー」の2つ。

## 仕様

**幅480px以下で、「サンプルに戻す」と「Markdownをコピー」の表示を短縮する。**

| ボタン | 481px以上 | 480px以下 |
|---|---|---|
| リセット | サンプルに戻す / Reset to sample | **戻す** / **Reset** |
| コピー | Markdownをコピー / Copy Markdown | **コピー** / **Copy** |

- 境目を480pxにするのは、溢れ始める幅（日本語435px・英語446px）より上で、
  かつ既存の確認幅600pxより下だから。600pxでの見た目は変わらない。
- 短縮しても**ボタンのアクセシブルな名前は変えない**。`aria-label` に
  長いほうの文言を常に付け、画面に出す文字だけを差し替える。
  読み上げと、検証スクリプトの `getByRole('button', { name: 'Markdownをコピー' })` が
  幅によって変わらないようにするため。
- 短縮は**文字の差し替えだけ**で、ボタンの数・並び・高さ・押せる範囲は変えない。
  ツールバーは1行のままで、折り返さない（折り返すとtextareaの高さが減る。
  0032で確保したぶんを打ち消す）。

短縮ラベルをDOMに入れて測った結果（同じ条件）、幅320pxでも横スクロールは出ない:

| 画面幅 | scrollW（日本語） | scrollW（英語） |
|---|---|---|
| 480px | 480 | 480 |
| 414px | 414 | 414 |
| 375px | 375 | 375 |
| 360px | 360 | 360 |
| 320px | 320 | 320 |

このとき `.toolbar__actions` は日本語264px・英語280px（現状の409/420から縮む）。
ボタンの幅は「戻す」52px・「コピー」63px（英語は `Reset` 62px・`Copy` 57px）。

### 実装で分かったこと（未確認の前提2が崩れた）

上の320pxの表は**保存状態が空の初期表示**で測ったもので、
「保存しました 12:34 / Saved at 05:18」が出ている状態では足りなかった。
文言の短縮だけを入れて測り直した結果:

| 画面幅 | 保存状態あり・日本語 | 保存状態あり・英語 |
|---|---|---|
| 360px | 溢れなし | **2px溢れる** |
| 320px | 26px溢れる | 42px溢れる |

保存状態を消すのは採らず（書いたものが残っているかの表示は狭い画面でも要る）、
幅480px以下で `.toolbar__actions` の `gap` を 8px → 6px、`.button` の左右の
padding を 12px → 10px に詰めた。高さ（34px）は変えないので、textareaのぶんは減らない。
詰めたあとの実測:

| 画面幅 | 保存状態あり・日本語 | 保存状態あり・英語 |
|---|---|---|
| 480px | 溢れなし | 溢れなし |
| 414px | 溢れなし | 溢れなし |
| 375px | 溢れなし | 溢れなし |
| 360px | 溢れなし | 溢れなし |
| 320px | 2px溢れる | 18px溢れる |

**このissueで約束するのは360pxまで**（要求仕様のN5・N9もその幅で書く）。
320pxは保存状態が空なら両言語とも収まるが、出ているときは収まらない。

### 要求仕様の基準幅

[requirements.md](../requirements.md) のN5・N9は「720px以下」「600px」と書いてあり、
スマートフォンの実幅を見ていなかった。このissueで**基準を360pxまで下げる**
（N5「720px以下でツールバーのボタンが画面内に収まる（360pxで確認）」、
N9「360pxで横スクロールが出ない」）。実測は320pxまで取るが、要求として約束するのは
360px（Androidの実幅の下限として一般的な値）までにする。

### 対象ファイル

- `src/lib/messages.ts` — 短縮ラベルを2言語で足す（`resetShort`・`copyShort`）。
  既存と同じ `t('戻す', 'Reset')` の形で、長いほうの隣に置く。
- `src/components/Toolbar.tsx` — リセット・コピーの2ボタンを、長短2つの
  `<span>` を持つ形にする。`aria-label` に長いほうを常に付ける。
- `src/index.css` — `@media (max-width: 480px)` を新設し、長いほうを `display: none`、
  短いほうを表示に切り替える。既存の720pxのブロックには手を入れない。
- `scripts/verify-ui.mjs` — `layout` 区分に幅360px・幅375pxのチェックを足す
  （既存の600pxのチェックは消さない）。
- `docs/requirements.md` — N5・N9の基準幅を更新する。
- `docs/functional-spec.md`・`docs/test-spec.md` — 画面の説明とチェック一覧を更新する。

## 未確認の前提

- `display: none` にした `<span>` の文字は、ブラウザのアクセシビリティツリーからも
  外れる（＝`aria-label` を付ければ名前は長いほうに固定される）と考えているが、
  Chromiumでの実挙動は確かめていない。実装時にまず
  `getByRole('button', { name: 'Markdownをコピー' })` が幅360pxで引けるかを見る。
- 幅480px以下でも `.toolbar__save`（保存状態、max-width 56px）は現状のままで
  収まると見ている。上の320pxの実測は保存状態が空の初期表示で取ったので、
  「保存しました 12:34」が出ている状態では測っていない。
  → **崩れた。** 英語・幅360pxで2px溢れた（上の「実装で分かったこと」）。
  gapとpaddingを詰めて360pxまで収め、約束する幅を320pxから360pxへ直した。

## 検討したが採らなかった案

- **ツールバーを2行に折り返す**（`flex-wrap: wrap`）。高さが増え、幅375pxで
  207pxしかないtextareaがさらに減る。0032で高さを確保した直後に打ち消すことになる。
- **`.toolbar__actions` を横スクロールさせる**。ボタンは押せるが、
  画面外のボタンは存在に気づけない。issueの「隠して終わりにしない」に反する。
- **文字を消してアイコンだけにする**。4ボタンのうちコピー・リセットに
  共有できるアイコンがなく、0019でアイコンを1つ作るのに要した手間を考えると
  このissueの範囲を超える。短縮ラベルで320pxまで収まるので、必要がない。
- **`.button__label` の仕組み（720px以下）をそのまま流用する**。600pxでの表示まで
  短くなり、既存の見た目と検証の前提が変わる。別の境目を足すほうが影響が小さい。
