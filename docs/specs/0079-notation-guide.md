# 0079: 算式記載ガイド

- 対応issue: [0079](../issues/0079-notation-guide.md)
- 状態: approved
- 作成日: 2026-09-22

## 目的

パレットで入るのは用意した記号151件と公式75件だけで、そこから外れた瞬間に
「何と書けばいいか」を調べる手段がアプリの中にない。**ツールバーの「ガイド」を
押すと、書ける記法とコマンドを引ける文書が画面に重なって開く**ようにする。
閉じれば元の編集に戻り、書きかけの文書には一切触れない。

ガイドは2層にする。前半は「分数を書く」「行列を書く」のような**目的から引く
解説**、後半は**KaTeXが対応するコマンドの全件表**（コマンドと、それが描かれた
姿の対）。知らない人が入口から入れて、知っている人が引ける形にする。

## 仕様

### 1. 開き方・閉じ方

ツールバーに5つ目のボタン「ガイド」/「Guide」を、`サンプルに戻す` の左に置く。

| 幅 | ボタンの文言 | 実測の大きさ |
|---|---|---|
| 481px以上 | `ガイド` / `Guide` | **72.0×34px**（ja）/ **71.1×32px**（en） |
| 480px以下 | `?` のみ | **24.9×31px**（日英とも） |

> 測った条件: 幅1440px・高さ900px、保存状態「保存しました 04:58」を出した状態
> （ツールバーがいちばん混む状態）。`.button--quiet` に既存の4ボタンと同じ
> クラスを当てて実測した値。

**幅480px以下では `.toolbar__actions` の `gap` を6px→4px、`.button` の左右の
padding を10px→8px に詰める。** 詰めずにボタンを足すと、英語表示・幅360px・
保存状態ありで**13px 横に溢れた**（実測。0033のコメントどおり、この幅は既に2pxしか
余っていない）。詰めた状態での実測は日英とも**溢れ0px**、ツールバーの高さ51px（ja）/
48px（en）、textareaの高さ323px（ja）/326px（en）で、いずれもボタンを足す前と同じ。

開いたあとの閉じ方は3つ。**Escapeキー**、パネル右上の閉じるボタン、
パネルの外側のクリック。閉じるとフォーカスはガイドボタンへ戻す。

開いている間、**編集中の文書・カーソル位置・選択範囲・保存状態は変わらない**。
ガイドは読むだけで、ここからエディタへ挿入する導線は作らない（スコープ外）。

### 2. パネルの寸法

`position: fixed` で画面に重ねる。**幅721px以上は上下左右24pxの余白を残した
最大幅960pxの中央寄せ、720px以下は全面。** 中身は縦にスクロールし、
横スクロールは出さない。

実測（高さ667pxのビューポート、中身3000pxのスクロール状態）:

| ビューポート | パネル | 画面に占める割合 | 横スクロール |
|---|---|---|---|
| 1440×667 | 960×619 | 67% × 93% | 0 |
| 1200×667 | 960×619 | 80% × 93% | 0 |
| 960×667 | 912×619 | 95% × 93% | 0 |
| 721×667 | 673×619 | 93% × 93% | 0 |
| 720×667 | 720×667 | 100% × 100% | 0 |
| 600×667 | 600×667 | 100% × 100% | 0 |
| 375×667 | 375×667 | 100% × 100% | 0 |
| 360×667 | 360×667 | 100% × 100% | 0 |

パネルは編集画面を覆うので、**パレット・ソース・プレビューの寸法は変えない**
（0032・0054・0057で決めた高さと幅に触らない）。

### 3. 中身の構成

日本語と英語の両方を持ち、表示言語（0031）に従う。

**第1部「目的から書く」** — 13項目。各項目は「書くもの」（コードとして表示）と
「出るもの」（実際に描画された結果）の対で示す。

1. 分数と根号　2. 上付き・下付き　3. ギリシャ文字　4. 大きな演算子（和・積・積分）
5. 括弧の大きさ　6. 行列　7. 場合分け　8. 複数行の整列　9. 装飾とアクセント
10. 書体　11. ブロック数式と `$$`　12. 式の番号（`\tag`）と参照
13. 関数のグラフ（```graph）

**第2部「コマンド一覧」** — 分類ごとの表。列は **コマンド / 描画 / 名前**。
「名前」は `palette.ts` の `title` と `formulas.ts` の `name` から引けるものだけ
入れ、無いものは空欄にする（967件ぶんの名前を新しく書き起こさない）。

分類と件数（KaTeXの由来から機械的に決めた実測値。合計967件）:

| 分類 | 由来 | 件数 |
|---|---|---|
| 関係子 | `symbols.ts` の `rel` | 236 |
| その他の記号 | `symbols.ts` の `textord` | 118 |
| 二項演算子 | `symbols.ts` の `bin` | 66 |
| 文字と変数 | `symbols.ts` の `mathord` | 32 |
| 大きな演算子 | `functions/op` + `symbols.ts` の `op` | 61 |
| 矢印 | `functions/arrow` | 25 |
| 装飾・アクセント | `symbols.ts` の `accent` + `functions/accent*` | 40 |
| 書体・文字の大きさ | `functions/font` + `functions/styling` | 26 |
| 括弧・区切り | `symbols.ts` の `open`/`close` + `functions/delimsizing` | 45 |
| 分数と二項係数 | `functions/genfrac` | 18 |
| 囲み・線 | `functions/enclose`/`overline`/`underline`/`horizBrace` | 15 |
| 間隔・改行 | `symbols.ts` の `spacing` + `functions/kern`/`cr` | 10 |
| マクロ・その他 | `macros.ts` ほか | 275 |

加えて **環境38種**（`pmatrix` `cases` `aligned` など）を第2部の末尾に別表で置く。

### 4. コマンドの集め方（生成物）

`scripts/extract-katex-commands.mjs` が `node_modules/katex/src/` から抽出し、
**`src/lib/guideCommands.ts` を生成してコミットする。** 実行時にKaTeXの内部を
読まない（内部構造に依存する箇所をビルド時の1か所に閉じる）。

抽出元は3つで、重複を除いて**1059件**（記号533・関数270・マクロ294）。
ここから**載せないもの92件**を落として**967件**にする。

| 落とすもの | 件数 | 理由 |
|---|---|---|
| `\@` で始まる内部マクロと `\show` `\html@mathml` `\bra@ket` `\bra@set` `\operatorname@` `\tag@literal` `\tag@paren` | 37 | 利用者が書くものではない。`\show` は**コンソールにデバッグ出力を吐く**（実測） |
| Khan由来の色マクロ（`\blueA` `\goldD` など） | 55 | KaTeXが同梱しているだけで、この文書の記法ではない |

引数の要るコマンドには**例**を手で書く。967件のうち**719件は引数なしでそのまま
描画でき**（実測）、**248件は例が要る**。うち35件はパレット・公式のLaTeXから
引ける（`\frac` → `\frac{a}{b}`）ので、**手で書くのは213件**。

規則の入出力の例:

| コマンド | 由来 | 例 | 表に出る行 |
|---|---|---|---|
| `\alpha` | `symbols.ts` / `mathord` | 不要（そのまま描ける） | `\alpha` ・ α ・ アルファ |
| `\frac` | `functions/genfrac` | `\frac{a}{b}`（パレットの `label` から） | `\frac{a}{b}` ・ 分数の姿 ・ 分数 |
| `\Bigl` | `functions/delimsizing` | `\Bigl(` （手で書く213件のひとつ） | `\Bigl(` ・ 大きい括弧 ・ （空欄） |
| `\@ifstar` | `macros.ts`（内部） | — | **出さない** |

### 5. 描き方

ガイド本文は**このエディタの記法で書いたMarkdown文字列**として持ち、
表示のときに既存の `renderMarkdown(source, lang)` を通す。ガイド自身が
書式の実例になり、パイプラインを二重に持たない。

- `src/guideDocument.ts` — 第1部の本文（日英）。
- `src/lib/guideCommands.ts` — 第4節の生成物（データのみ）。
- `src/lib/guideTable.ts` — `buildCommandTable(lang)`。上のデータからMarkdownの
  表を組む**純粋関数**（単体テストの対象）。

**ガイドのデータは遅延チャンク側に置く**（`lib/engine.ts` からたどれる側）。
初期チャンクに入れるとN10（初期JS 300 kB以下）に効く。エンジンが届く前に
ガイドを開いた場合は、パネルに `準備中…` / `Loading…` を出す（0024と同じ文言）。

性能の基準は**開いてから最後の数式が描かれるまで1.5秒以内**。
実測の裏づけ: 719件の数式を含む20 kBの文書がプレビューに出そろうまで
**197ms**（幅1440px、開発サーバ、ローカル、ja）。

## 未確認の前提

- **パネルの中身を `renderMarkdown` で描いても、プレビュー側の仕組みと干渉
  しないこと。** 数式は `.math-anchor` で包まれ、プレビューではクリックで
  ソースの範囲が選ばれる（0020）。パネルはプレビューとは別のDOMなので当たらない
  はずだが、確かめていない。式の番号（0044）の採番がガイド内で走ることも同じ。
- **`Ctrl+F` がガイドを開いている間にどちらへ効くか。** 0043の検索バーは文書に
  対するもので、ガイドの中は探せない。ガイド内の検索はスコープ外だが、
  開いている間に検索バーが開くのは筋が悪い可能性がある。
- **967件ぶんのKaTeX出力（実測341 kB／719件）を1つのDOMに入れたときの
  メモリと描画。** 時間は197msと測ったが、狭い画面（360px）での縦の長さと
  スクロールの追従は測っていない。
- **`dist-file/app.js`（現在602.8 kB）がどれだけ増えるか。** 上限の取り決めは
  いまのところ無いが、増分は実装後に記録する。
- **`palette.ts` / `formulas.ts` から名前を引く突き合わせの精度。** `\frac` を
  `\frac{a}{b}` から拾う形で、誤って別のコマンドに当たらないかは実装で確かめる。

## 検討したが採らなかった案

- **プレビュー側をガイド表示に切り替える** — 書いたものが見えなくなる。
  「書きながら調べる」ができない。
- **別タブで開く静的ページ** — `file://`（0074）での配り方が増え、
  IIFEの単一ファイルという前提と噛み合わない。
- **967件すべてに日英の名前を書く** — 量が現実的でなく、機械翻訳では
  「関係子」の区別がつかない。名前は既にある226件ぶんだけ出し、
  残りはコマンドと描画で引いてもらう。
- **実行時にKaTeXの内部から一覧を作る** — `node_modules/katex/src/` は
  公開APIではない。ビルド時の1回に閉じ、生成物をコミットする。

## スコープ外

- **ガイドからエディタへの挿入。** 読むための画面で、パレットの役割を持たせない。
- **ガイド内の検索。** 967行を目で探すのは重いので、クローズ時に新しいissueとして
  起票する（0011の検索はパレットの151件＋公式75件が対象で、ガイドは対象外）。
- **機能仕様・READMEの「対応する記法」の更新** — [0051](../issues/0051-undocumented-syntax.md)。
  ただしガイドに `<details>` を載せるかは0051の判断が要るので、**今回は載せない**。
- **未対応コマンドのエラー扱い** — [0063](../issues/0063-unsupported-commands.md)。
