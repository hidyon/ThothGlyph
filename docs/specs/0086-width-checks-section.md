# 0086: 幅に関わる検証を1つの区分にまとめ、既定では流さない

- 対応issue: [0086](../issues/0086-width-checks-section.md)
- 状態: implemented
- 作成日: 2026-09-22

## 目的

画面幅を測る149件のUIチェックを `width` 区分へ集める。通常の回帰確認は、画面寸法の調整を後回しにしている間も、寸法以外の回帰を結果から見つけられる。

`node scripts/verify-ui.mjs width` を明示すれば、これまでと同じ149件の幅チェックを実行できる。判定・ラベル・閾値を変えずに残すため、レイアウトを調整するissueでは従来どおり回帰を検出できる。

## 仕様

### 1. `width` 区分を任意実行区分として登録する

`scripts/verify-ui.mjs` の区分に、表示名を「画面幅」、コマンドライン名を `width` とする区分を追加する。区分は、既定実行に含めるかを表す属性を持つ。

- 引数なしでは、既定実行の区分だけを実行する。`width` は含めない。
- 区分名を1つ以上指定したときは、既定か任意かにかかわらず、指定された区分だけを実行する。
- `node scripts/verify-ui.mjs width` は `width` のみを実行する。
- `node scripts/verify-ui.mjs layout width` は `layout` と `width` を実行する。
- 知らない名前の扱い、`--repeat`、終了コード、結果JSONの形式は変えない。

現在538件あるチェックのうち、既定実行は389件、`width` は149件になる。

### 2. 幅指定の149件を移す

ラベルに `幅<数値>` を含む `check()` を、幅を設定してから確認するために必要な操作・待機・要素の取得と一緒に `width` 区分へ移す。元の区分からは、そのチェックだけを外す。

移す対象のうち、直接ラベルを持つものは次の106件である。これに加え、実行時に組み立てるラベルの幅チェック43件を同じ区分へ記録し、合計149件とする。

### 3. テスト仕様を現在の構成に合わせる

`docs/test-spec.md` の実行例と区分表を更新する。

- 引数なしの実行が、任意実行の `width` 区分を除くことを明記する。
- `width` の実行例を加える。
- 区分表に「画面幅」/`width`/149件を載せ、元の区分の内容と件数から移した幅チェックを除く。
- 画面寸法の調整が必要なissueでは `width` を指定して流すことを明記する。

要求仕様のN5・N9・N11は変更しない。幅の保証を確認する実行経路を通常実行から任意実行へ移すだけである。

## 検討したが採らなかった案

- 幅チェックを削除する。レイアウトを調整するissueで回帰に気づけなくなるため採らない。
- 各区分に残したまま、失敗を無視する。通常の実行結果から本物の回帰を判別できないため採らない。
- 幅チェックだけ判定や閾値を緩める。チェックの意味を変えることになり、0027の「判定を変えない」方針にも反するため採らない。

## スコープ外

- CSSやレイアウトの調整。幅チェックが落ちたときに別issueとして扱う。
- 要求仕様N5・N9・N11の削除または保証内容の変更。
- 幅以外のチェックの追加、削除、判定変更。
