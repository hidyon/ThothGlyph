# 0088: 自分用スニペットをバックアップ・移行できない

- 対応issue: [0088](../issues/0088-personal-snippet-backup.md)
- 状態: implemented
- 作成日: 2026-09-22

## 目的

利用者が自分用スニペットを1つのファイルとして保管し、端末・ブラウザ・プロファイルを替えても自分で復元できるようにする。同期サービスを持たず、データの移動を利用者の操作として完結させる。

## 仕様

### 1. 書き出し

自分用タブに「バックアップを書き出す」/「Export backup」を出す。押すと、現在の全スニペットを `thothglyph-snippets.json` としてダウンロードする。

ファイルは次のJSONだけを持つ。

```json
{
  "version": 1,
  "snippets": [
    { "id": "…", "name": "平方根", "body": "\\sqrt{%CURSOR%}" }
  ]
}
```

空の一覧も有効なバックアップとして書き出せる。

### 2. 読み込み

同じ場所に「バックアップを読み込む」/「Import backup」を出す。利用者がJSONファイルを選ぶと、形式をすべて検証してから「現在の自分用スニペットを置き換えます。よろしいですか？」と確認する。

確認すると、ファイル内の一覧で現在の一覧を丸ごと置き換える。キャンセル、読めないJSON、`version` の違い、`snippets` が配列でない場合、または項目の `id`・空でない `name`・空でない `body` が不正な場合は、何も保存しない。成功・失敗の結果は既存の通知欄に出す。

### 3. 表示と検証

入口と通知は日英に対応する。ファイル選択は `.json` に絞るが、拡張子だけでは信用せず本文を検証する。パレットの既存の登録・編集・削除・挿入は変えない。

## 受け入れ基準

- [x] 2件のスニペットを登録して書き出すと、`version: 1` と2件の `id`・`name`・`body` を持つJSONファイルが得られる
- [x] 空の一覧を書き出して別環境で読み込むと、空の一覧として復元できる
- [x] 読み込みの確認後、複数行と `%CURSOR%` を含むスニペットが名前・本文とも復元され、選択範囲への挿入も従来どおり動く
- [x] 読み込み確認をキャンセルすると、現在の一覧は変わらない
- [x] 壊れたJSON、版違い、不正な項目を読み込んでも、現在の一覧は変わらず失敗が表示される
- [x] 幅360px・1440pxで自分用タブの入出力操作に横スクロールが出ず、既存の登録・編集・削除・検索・公式が使える
- [x] `npm test`、`npm run build`、`npm run lint` が通る

## 検討したが採らなかった案

- 読み込み時に現在の一覧へ追加する。重複したID・名前をどちらにするか利用者が判断できず、移行時に意図しない重複を増やすため採らない。
- localStorageを丸ごとバックアップする。文書本文・テーマなどを混ぜると、スニペットを移したいだけの利用者が別の作業環境を壊しうるため採らない。
- クラウド同期を追加する。アカウント・通信・競合解決が必要となり、ブラウザ内で完結する方針から外れるため採らない。
