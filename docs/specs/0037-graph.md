# 0037: 関数のグラフを挿入する

- 対応issue: [0037](../issues/0037-graph.md)
- 状態: draft
- 作成日: 2026-09-20

## 目的

いま数式は式としてしか書けない。`y = x^2 - 2x` のグラフを文章に挟みたい場面で、
このエディタには手段がまったくない。

` ```graph ` というコードフェンスに関数を書くと、プレビューにグラフが描かれる
ようにする。ソースはテキストのまま残るので、あとから範囲や式を直せる。
外へ持ち出したときは（図にはならないが）式が文字として読める形で残る。

## 実測（仕様を決めるために先に測った）

### 描画コスト

式の評価器とSVG生成をひととおり試作し、Node 22で1回あたりの時間を測った
（`x^2 - 2x` / `sin(x)` / `1/x` の3本、200回の平均）。

| 条件 | 1回あたり | 生成されるSVGの文字数 |
|---|---|---|
| 関数3本 / 200点 | 0.48 ms | 10,559 |
| 関数3本 / 400点 | 0.75 ms | 19,376 |
| 関数3本 / 800点 | 1.38 ms | 37,148 |
| 関数1本 / 400点 | 0.22 ms | — |

[N1](../requirements.md)（1文字あたり50ms以内）に対して十分小さい。
**サンプル数は400点**にする（800点にしても曲線の見た目は変わらず、文字数だけ倍になる）。

### 大きさと目盛りの読みやすさ

プレビューに縦横比3:2のSVGを入れ、ヘッドレスChromiumで実測した。
スタイルは次のとおり（このまま採用する）。

```css
.graph { display: block; width: 100%; max-width: 480px; height: auto; margin: 16px auto; }
.graph .graph__tick { font-size: 13px; }         /* SVGのユーザー単位 */
@media (max-width: 720px) { .graph { max-height: 38vh; } }
@media (max-width: 480px) { .graph .graph__tick { font-size: 18px; } }
```

| 画面 | 図の大きさ | 目盛りの実際の大きさ | プレビューのペイン高 | 収まるか |
|---|---|---|---|---|
| 1440×900 | 480×320 | 13.0px | 755px | はい |
| 720×800 | 456×304 | 12.4px | 328px | はい |
| 600×800 | 456×304 | 12.4px | 328px | はい |
| 540×720 | 410×274 | 11.1px | 288px | はい |
| 480×700 | 399×266 | 15.0px | 278px | はい |
| 414×896 | 366×244 | 13.7px | 376px | はい |
| 375×667 | 327×218 | 12.3px | 241px | はい |
| 360×640 | 312×208 | 11.7px | 228px | はい |

分かったこと:

- **上限を付けないと広い画面で図が巨大になる**（幅1440pxで672×448px）。`max-width: 480px` で止める。
- **上下2分割（720px以下）では、プレビューのペインより図が高くなる**ことがある
  （幅540×高さ720で図320px vs ペイン288px）。`max-height: 38vh` を入れると全幅で収まる。
- **SVG内の文字は図と一緒に縮む**ので、幅360pxでは13px指定が7.2pxまで落ちて読めない。
  480px以下で18ユーザー単位に上げると、実際の大きさが11.7〜15pxに収まる。
  文字の大きさを属性ではなく**CSSで当てる**のは、これをメディアクエリで切り替えるため。
- 全幅で横スクロールは発生しない。

### DOMPurifyがSVGを落とさないか

`USE_PROFILES: { html: true, mathMl: true, svg: true }`（現行のまま）に通した結果、
`svg` / `g` / `line` / `path` / `text` / `rect` / `defs` / `clipPath` と、
`viewBox` `stroke-width` `stroke-dasharray` `text-anchor` `font-size` `clip-path`
`aria-label` `class` はすべて残った。**グラフのSVGはサニタイズを通せる**
（KaTeXの出力と違い、迂回させる必要がない）。

ただし `clipPath` は**使わない**。`id` を持つため、同じ文書に複数のグラフがあると
`id` が衝突する。描画側で範囲外の点を打たないことで代用する（後述）。

## 仕様

### 記法

情報文字列が `graph` のコードフェンスを、グラフの指定として扱う。

````
```graph
y = x^2 - 2x
x: -3..5
```
````

ブロックの中身は**1行1指定**で、行の種類は3つだけ。

| 行 | 意味 | 省略時 |
|---|---|---|
| `y = <式>` | 描く関数。上から順に色を割り当てる。**最大3本** | 1本も無ければエラー |
| `x: <数>..<数>` | xの範囲 | `-5..5` |
| `y: <数>..<数>` | yの範囲 | 自動（下の「yの範囲の決め方」） |

- 空行と、`#` で始まる行は無視する（コメント）。
- 行の前後の空白は無視する。
- 上のどれにも当てはまらない行はエラーにする（黙って無視しない。
  打ち間違いが黙殺されると、なぜ描かれないのか分からなくなる）。
- `x:` `y:` が2回以上書かれたら**最後のものを使う**。

### 式の文法

| 要素 | 書けるもの |
|---|---|
| 数 | `3` `0.5` `.5` |
| 変数 | `x` のみ |
| 定数 | `pi` `e` |
| 演算子 | `+` `-` `*` `/` `^`（`^` は右結合、単項マイナスあり） |
| 括弧 | `(` `)` |
| 関数 | `sin` `cos` `tan` `sqrt` `abs` `exp` `log`（自然対数） |
| 暗黙の乗算 | `2x` `3(x+1)` `2sin(x)` は `*` を補う |

大文字は受け付けない（`X` `SIN` はエラー）。角度はラジアン。

**`eval` も `new Function` も使わない。** トークナイザ → shunting-yard で逆ポーランドへ →
評価、をすべて純粋関数として書く（[0012](0012-file-load.md) で外から来たテキストが
ソースに入る経路が既にある）。試作で次の値を確認済み。

| 式 | x | 値 |
|---|---|---|
| `x^2 - 2x` | 3 | 3 |
| `2x + 1` | 4 | 9 |
| `-x^2` | 3 | -9 |
| `2sin(x)` | π/2 | 2 |
| `1/x` | 0 | Infinity（描かない点として扱う） |

### サンプリングと描画

1. xの範囲を**400等分**して401点で評価する。
2. yが有限でない点（`NaN` / `±Infinity`）は**打たない**。
3. yの範囲の外に出た点も**打たない**。
4. 点を打たなかったところで線を切る（`M` で打ち直す）。

**3と4が、`1/x` や `tan(x)` で画面を縦断する偽の線を防ぐ規則**である。
漸近線の近くでは値が範囲外に出るので、そこで線が切れる。
`clipPath` を使わずに済むのも同じ理由。

入出力の例:

| 入力 | 描かれるもの |
|---|---|
| `y = sin(x)` / `x: -pi..pi` | 正弦曲線1本。yの範囲は自動で約 -1.1..1.1 |
| `y = x^2` と `y = 2x + 1`（2行） | 2本を別の色で重ね、凡例に式を出す |
| `y = 1/x` / `x: -5..5` | x=0 の左右で線が切れ、縦線でつながらない |

なお `x: -pi..pi` のように、範囲にも式を書ける（同じ評価器を使う。`x` は使えない）。

### yの範囲の決め方（自動のとき）

有限なyを昇順に並べ、**下位5%と上位5%を捨てた**範囲の最小・最大を取り、
上下に高さの10%の余白を足す。

単純な最小・最大にしないのは、`1/x` や `tan(x)` が桁違いの値を出して曲線が
1本の直線に潰れるため。捨てた点は範囲外として描かれない（上の規則3）。

最小と最大が等しいとき（`y = 2` のような定数）は、±1 にする。

### 見た目

- 縦横比は **3:2**（viewBox `0 0 480 320`）。
- 目盛りはx・yとも**5本**。グリッド線を薄く引き、目盛りの値を軸の外側に出す。
- 数値は有効数字3桁までで、末尾の0を落とす（`1`, `1.5`, `0.333`）。
- x=0 / y=0 が範囲に入るときは、軸を他のグリッド線より濃く引く。
- 線の色は3本ぶん。ライト `#2563eb` / `#dc2626` / `#16a34a`、
  ダーク `#60a5fa` / `#f87171` / `#4ade80`。CSS変数（`--graph-line-1..3`）で当て、
  ダークの値は `[data-theme]` 側で差し替える。
- **関数が2本以上のときだけ凡例**を図の下に出す（色の線分＋式のテキスト）。
  凡例が出る分、グラフの領域は上に詰まる（SVG全体の高さは変えない）。
- `role="img"` と `aria-label`（`y = x^2 - 2x のグラフ` / `Graph of y = x^2 - 2x`）を付ける。

### エラーの出し方

グラフを描けないときは、**そのブロックの位置に赤字のメッセージを1行**出す。
数式と同じで、プレビュー全体は消えない。表示は `.graph-error` で、
`.katex-error` と同じ色（`#dc2626`）を使う。

| 原因 | メッセージ（日本語 / 英語） |
|---|---|
| `y =` の行がない | `グラフの式がありません` / `No function to plot` |
| 関数が4本以上 | `関数は3本までです` / `At most 3 functions` |
| 式が読めない | `式を読めません: <式>` / `Cannot read expression: <式>` |
| 範囲が読めない | `範囲を読めません: <行>` / `Cannot read range: <行>` |
| 範囲の幅が0以下 | `範囲の左が右以上です: <行>` / `Range is empty: <行>` |
| どれでもない行 | `読めない行です: <行>` / `Unknown line: <行>` |
| 全点が描けない | `この範囲に描ける点がありません` / `Nothing to plot in this range` |

メッセージに載せる `<式>` `<行>` は**HTMLエスケープしてから**入れる
（SVGと違い、これは利用者が書いた文字列をそのまま出す箇所）。

### 変換パイプラインへの接続

数式と同じ「退避 → marked → サニタイズ → 差し戻し」に乗せる
（[アーキテクチャ](../architecture.md#3-変換パイプラインlibrendermarkdownts)）。

```
1. splitByCode()                 いまのまま
2. コード領域のうち graph フェンスを %%MATHEDITOR_GRAPH_n%% へ退避   ← 追加
3. コードの外側の数式を %%MATHEDITOR_MATH_n%% へ退避                いまのまま
4. marked.parse()                いまのまま
5. DOMPurify.sanitize()          いまのまま
6. グラフを差し戻す（SVG）        ← 追加。サニタイズ済みのSVGを入れる
7. 数式を差し戻す（KaTeX）        いまのまま
```

- **グラフの退避は数式の退避より先**。ブロックの中の `$` を数式にしないため
  （[0006](0006-math-in-code.md) と同じ理由）。
- `splitByCode()` はフェンスの言語名を持たないので、コードのセグメントの
  先頭行が ` ```graph ` / ` ~~~graph ` かどうかで見分ける。
  言語名の後ろに余計な文字が付くもの（` ```graphql `）は**グラフにしない**。
- 生成したSVGは、差し戻す前に**個別にDOMPurifyへ通す**。KaTeXの出力と違って
  通せることを実測済みなので、抜け道を増やさない。
- 描画結果は**ブロックの本文をキーにしたMapでキャッシュ**する（上限100件、
  超えたら挿入順に捨てる）。数式のキャッシュと同じ方式。

### パレット

「Markdown」グループ（現在6件）の末尾に雛形を1件足す。

- ラベル: `\text{グラフ}`（ラベルはKaTeXで描かれるため、他の項目と同じ書式にする）
- 挿入されるもの:

  ````
  ```graph

  x: -5..5

  ````

- tooltip: `関数のグラフ` / `Function graph`

## 未確認の前提

- 凡例の式のテキストが長いとき（`y = sqrt(abs(x)) + 2sin(x)` など）、図の幅から
  はみ出す可能性がある。実装時に幅360pxで測り、はみ出すなら省略記号で切る。

  4.5:1ではなく3:1を目安にする）。実装時に測り、足りなければ値を変える。
- 遅延チャンクの増加量。`node scripts/measure-load.mjs` で実装前後を比べる。

## 検討したが採らなかった案

- **画像（data: URI）として挿入する**。持ち出した先でも図として見える代わりに、
  ソースが数千文字の不可読な行になり、あとから直せない（作り直しになる）。
  編集の道具としては割に合わない。持ち出しの穴は
  [0003](../issues/0003-image-export.md) と合わせて別issueで埋める。
- **グラフ描画のライブラリを入れる**。[0024](0024-bundle-size.md) で初期バンドルを
  243kBまで削ったばかりで、描くのは折れ線と目盛りの文字だけ。自前のSVGで足りる。
- **`clipPath` で図の外側を切る**。`id` が文書内で衝突する。範囲外の点を打たない
  規則で代用でき、その規則は漸近線の処理としても必要だった。
- **`eval` / `new Function` で式を評価する**。外から読み込んだ `.md` が
  そのままコードとして走る経路を作らない。
- **目盛りの文字の大きさを属性で持つ**。メディアクエリで切り替えられず、
  幅360pxで7.2pxまで落ちて読めない（実測）。
