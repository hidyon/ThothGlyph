# 0043: 文書の中を検索・置換する

- 対応issue: [0043](../issues/0043-find-replace.md)
- 状態: draft
- 作成日: 2026-09-20

## 目的

編集中の文書の中を探す手段がない。ブラウザの `Ctrl+F` はプレビューのテキストには
当たるが、**textareaの中は当たらず、編集位置も動かない**。置換にいたっては手段がない。

ノートを書き進めてから記号を変えたくなること（`\alpha` を `\beta` に全部直す）は
よくあるので、**探して、その場へカーソルを動かし、置き換える**までを閉じる。

## 実測（画面に足すものを先に測った）

### 入口（ソースペインの見出し行に3つ目のボタン）

[0034](0034-file-save.md) の時点で「3つ目を足すときは幅を測り直すこと」と
書いてあるので測った（ヘッドレスChromium、高さ667px）。

| 画面幅 | ボタン幅の内訳 | 右端 | 見出し行の高さ | textareaの高さ | 折り返し | 横スクロール |
|---|---|---|---|---|---|---|
| 360px（日本語） | 44 + 106 + 106 | 344px | 30px（変化なし） | 207px（変化なし） | なし | なし |
| 360px（英語） | 49 + 98 + 83 | 344px | 30px（変化なし） | 210px（変化なし） | なし | なし |
| 375px | 同上 | 359px | 30px | 207px | なし | なし |
| 414px | 同上 | 398px | 30px | 227px | なし | なし |

**3つ目を足しても見出し行は30pxのまま**で、幅360pxでも収まる（右端344px / 360px）。
[0032](0032-palette-height-narrow.md)・[0033](0033-toolbar-overflow-phone.md) で
確保したtextareaの高さ（幅375pxで207px）も減らない。

### バーを開いたときの占有

見出し行の直下に、**開いたときだけ**出る。検索の行と置換の行を分け、
置換の行は `置換` を押したときだけ出す。幅480px以下ではボタンの文言を短くする
（0033と同じ手）。

| 画面 | 検索のみ | 置換も開く | textarea（検索のみ / 置換も） | 横スクロール |
|---|---|---|---|---|
| 1440×900 | 41px | 75px | 680 / 646px | なし |
| 720×800 | 41px | 75px | 253 / 219px | なし |
| 600×800 | 41px | 75px | 253 / 219px | なし |
| 414×896 | 41px | 73px | 301 / 269px | なし |
| 375×667 | 41px | 73px | 166 / 134px | なし |
| 360×640 | 41px | 73px | 153 / 121px | なし |

英語表示でも同じ（幅360pxで41 / 73px、textarea 156 / 124px）。

分かったこと:

- **1行に全部並べると狭い画面で破綻する。** 検索・件数・前後・置換欄・置換・
  すべて置換・閉じるを1行に入れた最初の案は、幅375pxの英語で**バーが105px**に
  なり、textareaが105pxまで痩せた（基準の207pxの半分）。
- **行の中も折り返させないと横スクロールが出る。** 入力欄に `min-width` を
  残したままだと幅375px・360pxで `scrollWidth > innerWidth` になった
  （[N5](../requirements.md) に触れる）。`min-width: 0` と `flex-wrap` で消える。
- 幅360pxで置換まで開くとtextareaは121px（約5行）。**バーは `Esc` で閉じられる**
  ので、書く間は閉じておける。

## 仕様

### 入口と出口

| 操作 | 結果 |
|---|---|
| ソースの見出し行の `検索` / `Find` を押す | バーが開き、検索欄にフォーカスが入る |
| エディタにフォーカスがある状態で `Ctrl+F` | 同上（ブラウザの検索は開かない） |
| バーの `閉じる` / `×` を押す | バーが閉じ、エディタへフォーカスが戻る |
| 検索欄・置換欄で `Esc` | 同上 |

**`Ctrl+F` を奪うのはエディタ（textarea）にフォーカスがあるときだけ。**
プレビューやパレットにフォーカスがあるときはブラウザの検索に任せる
（プレビューの文字を探したい人の手段を残す）。

選択範囲があるときにバーを開いたら、その文字列を検索欄の初期値にする。

### バーの中身

```
[検索欄        ] 3/12件 [前へ][次へ][置換][閉じる]
[置換後の文字列 ] [置換][すべて置換]        ← 「置換」を押している間だけ
```

幅480px以下では `前へ` `次へ` `閉じる` `すべて置換` の文言を
`‹` `›` `×` `全て` に短くする（長いほうは `aria-label` に残す。0033と同じ）。

### 検索の規則

- **素の文字列として照合する。** 正規表現は使わない。
- **大文字と小文字を区別する。** LaTeXでは `\alpha` と `\Alpha` が別物で、
  区別しないと置換で壊れる。
- 重なる一致は数えない（左から順に、一致したぶんだけ進む）。
- 検索欄が空のときは0件で、何も選択しない。

| 文書 | 検索語 | 一致 |
|---|---|---|
| `aaaa` | `aa` | 2件（0文字目と2文字目。1文字目からの一致は数えない） |
| `\alpha + \Alpha` | `\alpha` | 1件（大文字小文字を区別する） |
| `x + 1` | （空） | 0件 |

### 移動

- `次へ` で次の一致へ、`前へ` で前の一致へ。**末尾まで行ったら先頭へ回る**
  （何件目かは件数表示で分かるので、回ったことは分かる）。
- 移動すると、その一致が**textarea上で選択され、見えるところまでスクロールする**。
- 件数表示は `3/12件` / `3/12`。0件なら `0件` / `No matches`。
- 検索語を変えたら、カーソル位置から**後ろにある最初の一致**へ移る。

### 置換の規則

- `置換` は**いま選ばれている一致**を置き換え、次の一致へ移る。
- `すべて置換` は文書中の一致をすべて置き換える。
- **置換後の文字列は再検索の対象にしない**（`x` → `xx` が無限に増えない）。
- どちらも [0021](0021-undo.md) の経路（`App.tsx` の `insertIntoTextarea`）を通す。
  **`すべて置換` は「全文を選んで置換後の全文を1回で入れる」**ので、
  何件置き換えても `Ctrl+Z` 1回で戻る。

| 文書 | 検索 | 置換後 | すべて置換の結果 |
|---|---|---|---|
| `aaaa` | `aa` | `b` | `bb` |
| `x^2 + x` | `x` | `xx` | `xx^2 + xx`（置換した `xx` は再度置換されない） |
| `\alpha` | `\alpha` | `\beta` | `\beta` |

### キーボード

| 場所 | キー | 動き |
|---|---|---|
| 検索欄 | `Enter` | 次の一致へ |
| 検索欄 | `Shift+Enter` | 前の一致へ |
| 検索欄・置換欄 | `Esc` | 閉じてエディタへ戻る |
| エディタ | `Ctrl+F` | バーを開く |

[0011](0011-palette-search.md) の検索欄（`Esc` でエディタへ戻る）と揃える。

### 状態の持ち方

- バーの開閉・検索語・置換語・何件目かは、**`Editor` 側のUIの一時的な状態**にする
  （[アーキテクチャ](../architecture.md#画面の状態)が認めている例外。パレットの
  検索クエリと同じ扱い）。保存もしない。
- **textareaの選択とスクロール、置換の実行は `App.tsx` のコールバック**に置く。
  `textareaRef` を持っているのが `App` で、挿入の経路（0021）もそこにあるため。
  `Editor` は「どうしたいか」を渡すだけにする。
- 一致の計算は `lib/findMatches.ts` の純粋関数で、単体テストで固定する。

## 未確認の前提

- `Ctrl+F` を `preventDefault` で奪えること（Chromium以外は確かめていない。
  奪えない環境ではボタンから開けるので、機能は失われない）。
- `すべて置換` で全文を差し替えたとき、Undoが**1回で**戻ること。
  0021の実測では `execCommand('insertText')` が履歴に乗ったが、
  **全文の差し替えでも同じか**は確かめていない。ここが崩れたら、
  「1件ずつ置換をまとめる」方式に変える（Undoの回数が増える）。
- 長い文書（0007の400節・26.9kB）で、1文字打つたびに一致を数え直しても
  [N1](../requirements.md)（50ms/文字）に収まること。収まらなければ、
  数え直しを入力から遅らせる。

## 検討したが採らなかった案

- **ブラウザの `Ctrl+F` に任せる**（何も作らない）。textareaの中は当たらず、
  当たっても編集位置が動かないので、このissueの目的を満たさない。
- **`Ctrl+F` を常に奪う。** プレビューの文字を探す手段が消える。
  エディタにフォーカスがあるときだけ奪えば両方残る。
- **プレビュー側も一致をハイライトする。** 変換パイプラインに検索語を持ち込む
  ことになり、[アーキテクチャ](../architecture.md)の「`renderMarkdown` は
  ソースだけから決まる」を崩す。ソース側だけにする。
- **正規表現での検索。** 打ち間違いで文書を壊しやすく、Undoが1回で戻るとはいえ
  怖い。素の文字列で足りる場面から始める。
- **1行のバーにすべて並べる。** 実測で幅375pxの英語が105px（textarea 105px）に
  なった。検索と置換を分ければ41px / 73pxに収まる。

## スコープ外

- 正規表現、単語単位の一致、大文字小文字を無視する切り替え
- プレビュー側のハイライト
- 複数文書をまたぐ検索（[0004](../issues/0004-multi-document.md) の後）
- 検索語の履歴・保存
