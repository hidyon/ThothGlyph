**通っているチェックが、見るべき状態を見ていない**ことがある。
スクリーンショットはそれを捕まえる。

## 仕様が実装中に変わった箇所

### 0053: 「2行になる幅」と「1行の下限」を取り違えた

仕様の表に「A案では944pxで2行になる」と書き、受け入れ基準を
「幅944pxで1行のまま」にした。測定スクリプトは幅を1pxずつ狭めて
**最初に2行になった幅**を返していたので、944pxは既に2行だった。
正しくは945px以上で1行。検証で落ちて気づき、基準を945pxに直した。

数値は正しく、条件（日本語・幅）も書いてあった。ずれたのは**境目の向き**である。

### 0055: 「Αとして描画される」は、確かめようのない基準だった

受け入れ基準に「数式の中で `\Alpha` がΑとして描画される」と書いた。
検証すると落ちた。KaTeXは `\Alpha` を**ラテン文字のA（U+0041）**として描き、
Α（U+0391）は出力のどこにも現れない。

仕様を書く前に `katex.renderToString` で13件を実際に通してあり、
「描けること」は確かめていた。確かめていなかったのは**何として描かれるか**で、
基準にはそちらを書いていた。基準を
「エラーなく描画され、式のソース（MathMLの注釈）に `\Alpha` が残る」に変えた。

0029が「見た目がまったく同じ」と書いたのは字形の話だと読んでいたが、
実際は**文字コードの水準で同じ**だった。**一度確かめた事実の、確かめていない側**が
基準に入り込んだ形である。

→ **提案1**: 「〜として描画される」「〜に変換される」を基準に書くなら、
期待する出力を仕様の時点で実際に出し、その文字列を仕様に貼る。

## 受け入れ基準で捕まえられなかった問題

### 0054: ボタンが2行以上並ぶと上の行が押せなかった（既存の潜在バグ）

縦帯にしたら `selection` 区分が30秒待って落ちた。原因は**KaTeXのラベルが
ボタンの外へ上に23.7〜38.7pxはみ出している**ことで、下の行のラベルが上の行の
ボタンの中心を覆い、クリックがそちらに当たっていた。
`.palette__item * { pointer-events: none }` で直した。

これは0054が作ったものではない。**横帯でもボタンが2行以上になる場面**
（幅1440pxのギリシャ小文字31件など）では前から起きていたはずで、
縦帯は全タブが3行以上になるので毎回踏むようになっただけである。

0054の受け入れ基準（寸法・グラフ・スクロール）では捕まらなかった。
捕まえたのは**0009で書かれた既存の区分**で、
**レイアウトを変えるissueでは、既存の全区分を流すことそのものが基準**になる。
CLAUDE.mdの「全項目を満たしたらクローズ」と test-spec.md の全区分は
既にそう書いてあるので、ルールは足さない。

### 0053: 既存チェックが innerText でタブ名を読んでいた

アイコンを足したらタブの `innerText` が `√基本` になり、
`palette-height` と `search` の2件が落ちた。アイコンは `aria-hidden` なので
`getByRole` の名前には入らない。`tabLabels()` を共通ヘルパにして3か所を寄せた。

**自分の変更が起こした回帰**なので、その場で直して仕様に記録した（CLAUDE.md
どおり）。ここは想定内の作業だった。

### 0054: 既存チェック4件が「パレットは横帯」を前提にしていた

幅1280px・1440pxで「パレットの高さが94px」を見ていたチェックが、縦帯で落ちた。
0032（蓋）・0011（検索欄）・0053（アイコン）の意図はいずれも横帯の話なので、
**測る幅を1199pxへ移した**（壊れたのではなく、前提が変わった）。

前提が変わったチェックを「落ちたから直す」ではなく
**「何を確かめたかったのか」に戻して測り直す**のは、今回うまくいった形である。

## 着手順の予告は当たったか

0053の起票時に「**0054 → 0053の順が安い**。0054でタブの並ぶ向きが変わりうるので、
逆順だとアイコンの寸法を測り直す」と書き、実際には逆順（0053 → 0054）でやった。

結果は**予告どおり、ただし小さかった**。測り直したのは `tab-icon` 区分の
1件だけ（幅1440px → 1199px）で、アイコンの寸法そのものは縦帯でも変わらなかった。
**予告を書いておいたので、落ちたときに迷わなかった**のが効いている。

## CLAUDE.mdへの変更提案（2026-09-20 承認・適用済み）

### 提案1: 出力が論点の基準は、期待する出力を先に出して貼る（+1行）

```diff
 受け入れ基準は**外から観測できる結果**で書く。内部の状態ではなく、画面に何が出るか、
 値がどうなるかで書く（「保存しない」ではなく「保存状態の表示が出ない」）。
 **見た目が論点の基準は「スクリーンショットで見て分かる」で書く**
 （0043の「選択される」は、Chromiumが描画しないので見えなかった）。
+**「〜として描画される」「〜に変換される」は、期待する出力を仕様の時点で
+実際に出し、その文字列を仕様に貼る**（0055の「Αとして描画される」は、
+KaTeXがラテン文字のAを出すので永久に満たせない基準だった）。
 性能に関わるissueは、**起票の時点で現状を実測**し、基準に数値を書く。
```

根拠: 0055で「`\Alpha` がΑとして描画される」を基準にしたが、KaTeXの出力は
ラテン文字のA（U+0041）で、Α（U+0391）はどこにも現れない。
仕様の時点で13件を `katex.renderToString` に通していながら、
「描けるか」しか見ておらず「何として描けるか」を見ていなかった。

### 提案2: 冒頭の説明を現在の画面に合わせる（±0行、既存行の書き換え）

```diff
 数式入りMarkdownを書くためのWebエディタ。左にMarkdownソース、右にリアルタイムプレビュー、
-上部に記号パレット。書いたソースはクリップボードにコピーして持ち出す。
+記号パレット（幅1200px以上では左の縦帯、それ以下では上部の横帯）。
+書いたソースはクリップボードにコピーして持ち出す。
```

根拠: 0054でパレットの置き場所が幅で変わるようになり、「上部に」が
広い画面では事実と違う。CLAUDE.mdの冒頭はこのリポジトリが何かの説明なので、
画面の形が変わったら直す。

2件とも承認され、同じコミットで適用した（171行 → **175行**）。
