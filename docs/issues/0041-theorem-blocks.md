# 0041: 定理・定義・証明の囲みがない

- 状態: open
- 起票日: 2026-09-20

## 背景

数式ノートは「定理」「定義」「例」「証明」という単位で書かれる。読むほうも
その単位で探す。ところがMarkdownにはその区別がなく、このエディタにも手段がない。

いまできるのは引用で代用することだけで、サンプル文書の書き方に倣うなら
`> **定理.** 三角形の内角の和は $180°$ である。` のようになる。
種類ごとの見た目の違いは出せず、「ここからここまでが証明」という範囲も示せない。

## やりたいこと

- 定理・定義・補題・例・証明といった**種類のある囲み**を書ける。
- 種類が見た目で区別でき、プレビューで範囲が分かる。
- 囲みの中にも数式・箇条書き・グラフが書ける。
- 書き方を覚えていなくてもパレットから入れられる。
- 外へ持ち出したとき、内容が読める形で残る（[0037](0037-graph.md) と同じ考え方）。

## やらないこと

- 定理の自動採番と相互参照。番号は [0044](0044-equation-numbers.md) と
  合わせて考えるほうが筋がよい。
- 利用者が種類を自分で定義すること。まず固定のセットで使ってみる。

## メモ

**[R7](../requirements.md#r7-markdownとして正しく扱える) の方針（独自記法は
原則採用しない）に従うこと。** 標準の入れ物を借りるか、借りられないなら入れない。
候補は3つで、**仕様の時点で例を3件ずつ書き、持ち出した先でどう見えるかを
並べて比べること。**

| 候補 | 借りている入れ物 | 持ち出した先での見え方 |
|---|---|---|
| 生のHTML（`<div class="theorem">…`） | Markdownが元から許している生のHTML | 多くの環境で中身がそのまま読める（classは落ちることがある） |
| コードブロック（` ```定理 `） | 言語名。[0037](0037-graph.md) のグラフと同じ入れ方 | コードブロックとして読める。ただし中身がMarkdownとして解釈されないので、数式や箇条書きを入れるには自前で再パースが要る |
| 引用＋目印（`> [!定理]`） | 引用 | 引用として読めるが、`[!定理]` の行がそのまま残る。**GitHubの独自拡張なので、標準ではない** |

3つ目は標準ではないため、採るなら理由を仕様に書くこと。
- 種類の名前を日英どちらで書くかも決める（`定理` と `theorem` の両方を受けるか）。
- 証明の終わりの記号（∎）を自動で付けるかどうか。
