# 0037: 関数のグラフを挿入する

- 状態: open
- 起票日: 2026-09-20

## 背景

このエディタは数式を**式として**描けるが、**図として**は描けない。
講義ノートや解説記事では「$y = x^2 - 2x$ のグラフ」を並べて見せたい場面が
繰り返し出てくるのに、いまその手段が1つもない。パレットの88記号・60公式は
すべて式の断片で、図を作れるものはない。

回避策も弱い。外部で描いた画像を `![](...)` で貼ることはできるが、
このアプリはサーバを持たないので画像の置き場所がなく、書いたものを
`.md` として持ち出す（[R4](../requirements.md)）前提とも噛み合わない。

## やりたいこと

- `y = f(x)` の形の関数を書くと、プレビューにグラフが描かれる。
- 1枚に複数の関数を重ねられ、どれがどれか見分けられる。
- x の範囲を指定できる。y の範囲は指定しなければ自動で決まる。
- 軸・目盛り・グリッドがあり、グラフから値が読める。
- 書き方を間違えてもプレビュー全体が消えず、どこが悪いか分かる
  （[R1](../requirements.md) の数式と同じ扱い）。
- グラフの書き方を覚えていなくても、パレットから雛形を挿入して始められる
  （[R2](../requirements.md)）。
- ダークモードでもグラフが読める（[R5](../requirements.md)）。
- 狭い画面（幅360px）でもプレビューからはみ出さない。

## やらないこと

- **データ系列（折れ線・散布図）**。[0038](0038-graph-series.md) に回す。
  凡例・点の形・目盛りの決め方が関数とは別の判断になるため、
  まず関数だけで土台（式の評価・SVG描画・パイプラインへの接続）を固める。
- **グラフの画像書き出し**。[0003](0003-image-export.md)（数式の画像書き出し）と
  同じ問題なので、まとめて別issueで扱う。持ち出した先ではグラフにならず、
  ` ```graph ` ブロックが文字として見えるだけになる。この穴は承知のうえで残す。
- 媒介変数表示・極座標・陰関数（`x^2+y^2=1`）・対数軸・3D。
- 塗りつぶし（定積分の面積）、漸近線や交点の注記。
- グラフをマウスで動かす（拡大、ドラッグ、値の読み取り）。
- グラフ用の外部ライブラリを入れること。[0024](../specs/0024-bundle-size.md) で
  初期バンドルを243kBまで削ったばかりで、描くのは折れ線と目盛りの文字だけ。

## メモ

### 記法

Markdownのコードフェンスを入れ物として借りる（` ```graph `）。

````
```graph
y = x^2 - 2x
x: -3..5
```
````

新しい記法を作らずフェンスを使う理由:

- フェンスの中はMarkdownとして解釈されないので、`^` や `*` が強調に化けない。
  `$` で数式を囲むのと同じ理屈。
- 持ち出した先（GitHubなど）ではコードブロックとして表示され、
  式が文字として読める形で残る。壊れたり消えたりはしない。
- 変換パイプラインの1段目 `splitByCode()` が既にフェンスを切り分けている。

対する「data: URI の画像として挿入する」案は、持ち出した先でも図として
見える代わりに、ソースが数千文字の不可読な行になり、あとから範囲や式を
直せなくなる（作り直しになる）。編集の道具としては割に合わないと判断した。

### 実装で詰めるところ（仕様で決める）

- **パイプラインへの接続**: 数式と同じ「退避 → marked → サニタイズ → 差し戻し」に
  乗せる。ただし `splitByCode()` は**フェンスの言語名を捕まえていない**
  （セグメントのテキストにフェンス行ごと入っている）ので、`graph` を見分ける
  手当てが要る。
- **サニタイズ**: 生成するSVGは数値と文字列だけなので、KaTeXの出力と違って
  DOMPurifyを通せるはず（`USE_PROFILES` の `svg` は有効済み）。
  通して要素が落ちないか実測する。
- **式の評価**: `eval` や `new Function` は使わない。トークナイザと評価器を
  `lib/` の純粋関数として書き、単体テストで固定する
  （[0012](../specs/0012-file-load.md) で外部ファイルを読む経路が既にある）。
- **不連続点**: `1/x` や `tan(x)` をサンプル間で素通しにすると、画面を縦断する
  偽の線が出る。「y が範囲の高さを超えて飛んだら線を切る」などの規則を
  仕様に書き、入出力の例を並べる。
- **置き場所**: 描画コードはプレビューでしか要らないので、遅延チャンク側
  （`lib/engine.ts` からたどれる側）に置けば初期バンドルは増えない。
- **性能**: [N1](../requirements.md)（1文字あたり50ms以内）に効く。数式と同じく
  ブロック本文をキーにした描画キャッシュを持つ。
- **パレット**: 「Markdown」グループ（現在6件）に雛形ボタンを1件足す。
  [0032](../specs/0032-palette-height-narrow.md) で高さに上限があるので
  狭い画面は悪くならないが、**READMEの件数を固定している単体テストが落ちる**
  ので、READMEの数字も同じコミットで直すこと。
- **スクリーンショット**: 画面の見た目が変わるので
  `node scripts/make-screenshots.mjs` で撮り直す。

### 未確認の前提（仕様を書く前に実測する）

- 400点サンプリング×3本のSVG生成が1文字あたり何msか（N1の50msに収まるか）。
- 幅360pxのプレビューでグラフが読める大きさに収まるか（縦横比の決め方）。
- DOMPurifyのsvgプロファイルが `path` / `line` / `text` を落とさないか。
