# 0005: devcontainerでの開発に移行する

- 状態: closed
- 完了日: 2026-09-19
- 起票日: 2026-09-19

## 背景

現在の開発環境はホスト（WSL2 + nvm）に直接依存している。具体的に次の暗黙の前提が
リポジトリの外にある。

- Node 20.20.2 が nvm で入っていること（vite 8 は `^20.19.0 || >=22.12.0` を要求する）
- 検証用のChromiumが `~/.cache/ms-playwright/chromium-1234/` にあること。
  このパスはCLAUDE.mdにベタ書きされていて、環境が変われば即座に嘘になる
- `playwright-core` がスクラッチパッドに手でインストールされていること。
  セッションが変わると消える

つまり「このリポジトリをcloneすれば開発できる」状態になっていない。仕様駆動開発は
受け入れ基準を実際に動かして検証することが要なので、検証環境が再現しないのは
進め方そのものの土台が弱いということになる。

## やりたいこと

- リポジトリをcloneしてVSCodeでコンテナを開けば、追加の手作業なしに
  `npm run dev` / `npm run build` / `npm run lint` が動く。
- 受け入れ基準の検証（ヘッドレスChromiumでの操作とスクリーンショット）が
  コンテナ内で完結する。ホストに何が入っているかに依存しない。
- Claude Codeもコンテナ内で動き、ホストとコンテナで環境差が生じない。
- CLAUDE.mdからホスト固有のパスが消える。

## やらないこと

- CI（GitHub Actions等）の構築。まずローカルの再現性だけを解決する。
- 本番デプロイ用のイメージ。開発用コンテナに限る。

## メモ

- Docker 28.1.1 がホストで動作確認済み。
- ChromiumをイメージにDockerfileで入れると+500MB程度。承知の上で含める判断をした
  （検証が環境依存でなくなることを優先）。
- `playwright-core` をスクラッチパッドではなくdevDependencyにすれば、
  バージョンとブラウザ版数が package-lock.json で固定される。仕様で検討する。
