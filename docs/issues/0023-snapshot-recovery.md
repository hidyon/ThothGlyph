# 0023: 誤操作から書いたものを取り戻せない

- 状態: open
- 起票日: 2026-09-19

## 背景

`src/lib/documentStorage.ts` は `localStorage` の1つのキーを上書きするだけで、
**過去の状態を持たない**。[0001](0001-autosave.md) で「書いたものが消えない」
（[R3](../requirements.md)）は満たしたが、守られているのは**最新の1件だけ**である。

いちばん効くのは「サンプルに戻す」ボタン。`window.confirm` は出るが、
OKを押した瞬間に書いていたものは上書きされ、取り戻す手段がない。
確認ダイアログは押し間違いを減らすだけで、押し間違えたあとを救わない。

## やりたいこと

- 直前の状態に戻せる。少なくとも「サンプルに戻す」の直後は取り消せる。
- 何世代か前の状態を選んで戻せる（世代数は仕様で決める）。
- 戻せることが画面から分かる（隠し機能にしない）。
- 保存の仕組みが重くならない（[0007](0007-preview-performance.md) で測った
  入力の反応を悪くしない）。

## やらないこと

- 無制限の履歴。`localStorage` には容量の上限があり、長い文書を何十世代も
  持つと破綻する。
- 文字単位のUndo。それは [0021](0021-undo.md) が扱う。こちらは
  「保存された状態」の単位で戻す話。
- 複数文書の管理（[0004](0004-multi-document.md)）。こちらは1つの文書の来歴。

## メモ

- 保存形式を変えるので、[0004](0004-multi-document.md) より**先に**やるか
  **一緒に**やるほうが手戻りが少ない可能性がある。README の着手順の目安では
  0004は0010（スクロール同期）より後としている。順序を仕様で相談すること。
- 既存の保存形式には版番号がある（`matheditor:document:v1`）。
  版を上げたときに古い形式をどう読むかは [0001](0001-autosave.md) の仕様にある。
- `localStorage` の容量上限がどれくらいで、何世代持てるかは確かめていない。**未確認。**
- 「サンプルに戻す」の直後だけを救うなら、トースト上の「元に戻す」で足りるかもしれない。
  全世代の一覧より軽い。どちらにするかを仕様で決めること。
