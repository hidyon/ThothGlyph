# 0001: 編集内容の自動保存

- 状態: closed
- 起票日: 2026-09-19

## 背景

現在、編集中のMarkdownはReactのstateにしか存在しない。タブを閉じる、リロードする、
ブラウザが落ちる、のいずれでも書いた内容が消える。数式を含む文書は書くのに時間が
かかるので、消失の代償が大きい。

MVPで最初に埋めるべき穴はここだと判断した（保存がないことが現状いちばん怖い）。

## やりたいこと

- ページをリロードしても、直前まで編集していた内容が復元されている。
- 保存のためにユーザーが何か操作する必要はない。
- 保存されていることがユーザーに分かる（いつ保存されたか、など）。
- 初回訪問時はこれまで通りサンプル文書が表示される。

## やらないこと

- 複数文書の管理（別issue: 0004）。ここでは「編集中の1つ」だけを保つ。
- サーバへの保存・同期。localStorageの範囲で完結させる。

## メモ

- 保存先はlocalStorageを想定。容量上限（5MB前後）と、プライベートウィンドウや
  サイトデータ無効時に読み書きが例外を投げうる点への対処が要る。
- 「サンプル文書に戻す」手段がないと、保存後にサンプルを二度と見られなくなる。
  仕様段階で検討すること。

## 結果（2026-09-19 クローズ）

仕様 [0001](../specs/0001-autosave.md) の通り実装した。受け入れ基準は
`node scripts/verify-ui.mjs` で15件すべてOK、コンソールエラーなし。

仕様になかった追加確認を2つ入れた（いずれもスクリプトに残してある）:

- `localStorage.setItem` を例外に差し替えて、失敗表示が出ることを確認した。
- 狭い画面（600px）でボタンが画面外に押し出されないことを座標で確認した。

実装中に仕様から変えた点: 「初回レンダリングか」で初回保存を抑止する実装が
React StrictModeの二重マウントで破れたため、最後に保存した内容と比較する方式にした。
振る舞いは仕様のままで、内部の判定だけが変わっている。
