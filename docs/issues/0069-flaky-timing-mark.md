# 0069: フレークするチェックに `⏱` が付いていない

- 状態: open
- 起票日: 2026-09-21

## 背景

[0027](0027-verify-flaky.md) で、**負荷や待ち時間に結果が左右されうるチェック**に
`⏱`（timing）の印を入れた。`scripts/verify-ui.mjs` の `check()` の第4引数
`{ timing: true }` で付き、「落ちてもよい」という意味ではなく
**落ちたときに疑う順番**を示すものと決めてある。

[0066](0066-moon-icon.md)（三日月のアイコン）の検証で、`scroll` 区分の
**「1行が折り返す文書でも上端から32px以内」が全区分の1回目で落ちた**。
アイコンとは無関係な区分なので `--repeat 3` で単独実行したところ3回とも20/20、
全区分を流し直しても393/393だった。フレークと判断したが、
**このチェックには `⏱` が付いていない**（[0066の仕様](../specs/0066-moon-icon.md#実装で分かったこと)に記録した）。

0066の仕様には「付けるかどうかは0027の続きとして別issueにする」と書いたが、
**起票されていなかった**。振り返り（11回目）で見つけて起票した。

## やりたいこと

- **1回目で落ちて単独では通るチェックに、`⏱` が付いている。**
  落ちたときに「疑う順番」が画面から分かる。
- 逆に、`⏱` が付いているのに実際は揺れないチェックがあれば外す。
  印が多すぎると「落ちてもよい」に読み替えられてしまう。

## やらないこと

- **判定そのもの（閾値や待ち方）を変えること。** 0027で決めたとおり、
  `⏱` は印であって判定を緩めない。揺れを止める作業は別の話。
- **フレークを握りつぶすこと。** 再実行で通ったら成功とみなす仕組みは入れない。
- **全区分を何度も流す仕組み（CI）を作ること**（[0025](0025-ci.md)）。

## メモ

- `--repeat N` で同じ区分を繰り返し流せる（0027）。結果の
  `tmp/verify-result.json` には `flaky` と各チェックの `durationMs` が入る。
  **どのチェックが揺れたかは既に記録されている**ので、まずそれを読む。
- 現在 `⏱` が付いているチェックの一覧と根拠は
  [docs/test-spec.md](../test-spec.md) にある。
- 0066で揺れたのは `scroll` 区分（[0010](0010-scroll-sync.md)）の
  「1行が折り返す文書でも上端から32px以内」。スクロールの同期は
  デバウンスと描画待ちの上に乗っているので、揺れる側に見える。
- **`scroll` 区分は全区分の中で25.7秒と重い**（3番目）。全区分の1回目で
  落ちたことから、直前の区分が残した負荷の影響も疑える。
