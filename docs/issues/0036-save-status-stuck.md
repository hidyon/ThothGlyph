# 0036: 編集を取り消して保存済みの内容に戻すと「保存中…」が消えない

- 状態: closed
- 起票日: 2026-09-20

## 背景

ツールバーの保存状態が**「保存中…」のまま永久に止まる**ことがある。
[0021](0021-undo.md) の実装中に見つけた。0021の変更とは独立していて、
パレットに触れなくても再現する。

再現手順（実測、幅1440px・日本語表示）:

1. 文書を開き、自動保存が「保存しました」になるまで待つ
2. `z` と1文字打つ → 「保存中…」になる
3. すぐ Backspace で消す（600msの保存デバウンスが終わる前に、手順1の内容へ戻す）
4. 2.5秒待っても**「保存中…」のまま**。10秒待っても変わらない

原因は `src/App.tsx` の保存のeffect。`source` が変わるたびに
`setSaveState({ status: 'pending' })` を立てるが、

```ts
if (source === savedSource.current) return
```

で早期に抜ける経路では、直前に立てた `pending` を戻さない。保存すべきものは
無いので正しくは「保存しました」（または保存前の表示）に戻るべきところが、
「保存中…」の表示だけが残る。

**実害は表示だけではない**（2026-09-21に実測して分かった。起票時は
「表示だけ」と書いていたが誤り）。早期リターンは `unsaved.current`
（まだ保存していない内容）も戻さないので、**`beforeunload` が取り消した編集を
書き戻す**。

| 手順 | 結果（実測） |
|---|---|
| 1文字打って600ms以上待つ | `保存しました 16:21` |
| 続けて1文字打ち、120ms後に Backspace で消す | **`保存中…` のまま止まる** |
| その状態でリロードする | **消した文字が戻る**（末尾が `az` になった） |

`verify-ui.mjs` の `resetState` にある「保存が飛んだままリロードすると
beforeunload で書き戻され、消したはずの文書が復活する（0009の検証で踏んだ）」は
この不具合のこと。**検証側では回避されていたが、実際の利用では踏む。**

ただし
**保存状態の表示は「いま失われうるか」を伝える唯一の手掛かり**なので、
嘘をついたままになるのは困る。0021でCtrl+Zが効くようになったことで、
「保存済みの内容へ戻す」操作が1打鍵でできるようになり、踏む機会が増えた。

## やりたいこと

- 編集を取り消して保存済みの内容へ戻したとき、保存状態の表示が
  「保存中…」で止まらない。
- そのとき何が出るか（「保存しました」に戻るのか、表示を消すのか）を決める。
  保存した時刻は保持しているので、**戻す先は「保存しました hh:mm」が素直**。

## やらないこと

- 保存のデバウンス時間（600ms）の変更。
- 保存の形式や保存先の変更（[0004](0004-multi-document.md) の側）。

## メモ

- 検証スクリプトの `undo` 区分は、この不具合を避けるために
  **保存状態の表示ではなくlocalStorageの内容で保存の完了を待っている**
  （`savedAs`）。直したら、表示で待つ形に戻せる。
- `saveSettled()`（`scripts/verify-ui.mjs` の共通ヘルパ）はこの状態だと
  5秒のタイムアウトまで待つ。全区分の所要時間にも効いている。
- 受け入れ基準は実機検証になる。`autosave` 区分に足すのが素直。
