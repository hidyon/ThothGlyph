# 0047: 数式の中で定義したマクロが、別の式や別の文書にも残る

- 状態: open
- 起票日: 2026-09-20

## 背景

`$\def\R{\mathbb{R}} \R$` と書いた後、**別の数式**で `$\R$` と書くと、
定義していないのに描画されることを確かめた。同じことは文書を入れ替えた後
（`サンプルに戻す`、ファイルの読み込み）にも起きる。KaTeXのマクロ状態が
モジュールの中で共有されていて、`renderToString` の呼び出しをまたいで残るため。

これは2つの意味で問題になる。

1. **見えない依存ができる。** `\def` を書いた行を消しても、リロードするまでは
   `\R` が描画され続ける。リロードした瞬間に壊れる（書いた人には理由が分からない）。
2. **`renderMarkdown` が純粋関数でなくなっている。**
   [アーキテクチャ](../architecture.md)には「同じ入力からは同じ出力が返る」と
   書いてあり、数式のキャッシュ（LaTeX文字列をキーにする）はその前提に立っている。
   いまは呼ぶ順序で結果が変わる。

## やりたいこと

- ある数式で定義したマクロが、**別の数式に勝手に効かない**。
- 文書を入れ替えたら、前の文書の定義が残らない。
- 同じ入力からは同じ出力が返る（キャッシュの有無でも、呼ぶ順序でも変わらない）。

## やらないこと

- マクロを機能として使えるようにすること。それは [0046](0046-math-macros.md)。
  このissueは**漏れを止める**ところまで。

## メモ

- KaTeXの `renderToString` に `macros` を渡すと、その呼び出しの中だけで使う辞書に
  できる（渡さないと内部の状態が使われる）。呼び出しごとに空の辞書を渡すのが
  いちばん素直だが、**確かめていないのでまず実測すること**。
- 受け入れ基準は単体テストで書ける。`$\def\R{x}\R$` を描画したあとに `$\R$` を
  描画し、後者がエラー（未定義）になること。順序を入れ替えても同じこと。
- 利用者が現に `\def` を使っていた場合、この修正で描画が壊れる。0046を
  近いうちに入れる前提なら受け入れられるが、**順序を相談すること**。
