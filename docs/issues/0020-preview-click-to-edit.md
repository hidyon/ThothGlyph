# 0020: プレビューでクリックした箇所をパレットで編集する

- 状態: closed
- 起票日: 2026-09-19

## 背景

プレビューは今のところ**見るだけ**で、操作の起点にならない。描画された数式を見て
「この分数を直したい」と思っても、左のソースから該当箇所を目で探し、そこへ
カーソルを移してから編集する必要がある。文書が長いほどこの往復が重い
（[0010](0010-scroll-sync.md) がスクロール同期を扱うが、それでも探す手間は残る）。

描画された数式は、LaTeXのどの部分から来たかが分かっているはずのものなので、
クリックした箇所とソースの位置を結びつけられるはずである。

## やりたいこと

- プレビューの数式をクリックすると、ソースの対応する位置にカーソルが移る。
- その状態でパレットの記号を押すと、意図した場所に挿入される。
- どこが選ばれているのかが画面で分かる（クリックした数式とソースの該当箇所の
  両方に印が出る、など）。

## やらないこと

- プレビュー上で直接タイプして編集すること（WYSIWYG）。ソースが唯一の正である
  という構造を崩さない。プレビューはあくまでソースへの入口にする。
- 数式より細かい粒度（「この分数の分母」まで特定する）。まず数式1つ単位で、
  使いものになるか見る。
- Markdownの本文（見出し、箇条書き）のクリック。まず数式に絞る。

## メモ

- 数式は変換の前に退避され、後からHTMLに差し戻される（[アーキテクチャ](../architecture.md)）。
  その退避の時点でソース上の位置が分かるので、差し戻すHTMLに位置を
  データ属性として持たせるのが素直に見える。ただし**未確認**。
- プレビューはキャッシュされている（[0007](0007-preview-performance.md)）。
  位置情報を足すとキャッシュのキーや無効化に影響しうる。
- 「カーソルが移る」だけだと、その数式を丸ごと選択した状態にするのか、
  先頭に置くのかで使い勝手が変わる。[0009](0009-wrap-selection.md) で
  選択範囲があるときの挿入を固めたので、選択する場合はその挙動に乗る。
- クリックできることが見た目から分からないと使われない。カーソル形状や
  ホバーの印をどうするかを仕様で決めること。
