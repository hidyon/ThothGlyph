# 0031: 英語に対応する

- 状態: closed
- 起票日: 2026-09-19

## 背景

画面に出る文字はすべて日本語で、切り替える手段がない。数式を書く道具として
言語に依存しない部分が多いのに、日本語が読めない人は使えない。

現状を数えた（コメントを除く、画面に出る文字列）:

| 場所 | 例 |
|---|---|
| `Toolbar.tsx` | `保存中…` / `保存しました HH:MM` / `保存できません` / `サンプルに戻す` / `Markdownをコピー` / `テーマ: 自動` |
| `Editor.tsx` | `ソース` / `Markdownを入力… 数式は $x^2$ または $$...$$` |
| `Preview.tsx` | `プレビュー` / `更新中…` |
| `palette.ts` | グループ名6件（`基本` `ギリシャ文字` …）と、62件の `title` |
| `formulas.ts` | 分類名6件と、公式30件の `name` |
| `sampleDocument.ts` | 初期表示の文書が全部日本語 |
| `palette.ts` の派生 | `（選択範囲を囲む）` / `（選択範囲の後ろに挿入）` |

加えて **`index.html` が `<html lang="en">` のまま**で、中身が日本語なのに
英語だと宣言している。これは現時点でも誤りで、スクリーンリーダーの読み上げや
ブラウザの翻訳判定に影響する。

## やりたいこと

- 画面の文字を英語に切り替えられる。
- 切り替えた状態がリロードしても保たれる（テーマと同じ扱い）。
- `<html lang>` が、表示している言語と一致する。
- 文字列を足すときに、両方の言語を書く場所が1か所に決まっている。

## やらないこと

- 日本語以外・英語以外の言語。まず2言語で仕組みが要るかを見る。
- 翻訳ライブラリ（i18next など）の導入。
  「状態管理ライブラリもUIフレームワークも入れない」（[CLAUDE.md](../../CLAUDE.md)）
  の方針に照らして、この規模で要るかを仕様で判断する。
- **コード内のコメント・issue・仕様・振り返りの英語化。** CLAUDE.mdは
  これらを日本語で書くと決めており、その方針は変えない。英語にするのは
  **画面に出る文字だけ**。

## メモ

- 切り替えの初期値をどうするか。ブラウザの言語設定（`navigator.language`）に
  従う案と、日本語固定で始める案がある。テーマは「OSに従う／手動」の
  3状態にしたので、同じ形にそろえる手がある（[0002](0002-dark-mode.md)）。
- サンプル文書（`sampleDocument.ts`）をどうするかが重めの判断。
  英語版を別に用意するのか、数式中心の言語に依らない文書にするのか。
  **利用者が書いた文書は翻訳しない**（当たり前だが、仕様に書いておくこと）。
- 公式の `name`（`解の公式` など）と記号の `title`（`平方根` など）が
  合計90件以上ある。ここが翻訳の量のほとんどを占める。
- `describeInsertion` は `title` と文言を組み立てている
  （`平方根（選択範囲を囲む）`）。英語では語順が変わる
  （`Square root (wraps selection)`）ので、文字列の連結では足りない可能性がある。
  **未確認。**
- 検証スクリプトの43件のうち多くが**日本語の文字列で要素を探している**
  （`getByRole('button', { name: 'Markdownをコピー' })` など）。
  言語を切り替えられるようにすると、これらが壊れる。検証をどう書き直すかを
  仕様に含めること。ここが見落としやすい。
