# 0021: パレットで挿入したあとUndoで戻せない

- 状態: open
- 起票日: 2026-09-19

## 背景

パレットの記号を挿入すると、React stateで `textarea` の値を丸ごと差し替える。
ブラウザはこれを「利用者の入力」と見なさないため、**ネイティブのUndo履歴が切れる**。
挿入の直後に Ctrl+Z を押しても、挿入前には戻らない。

[0009](0009-wrap-selection.md) で「どの記号を押しても選択したテキストは消えない」
ようにしたので、取り返しのつかない消失はなくなった。ただし
**間違えて押した記号を1手で取り消せない**ことは残っている。0009の仕様では
「テキストが消えなくなればUndoは不要」と判断してスコープ外に置き、
必要なら別issueにすると明記した。その回収がこのissue。

## やりたいこと

- パレットで挿入した直後に Ctrl+Z を押すと、挿入前の状態に戻る。
- 戻したあと Ctrl+Shift+Z（または Ctrl+Y）でやり直せる。
- 手で打った文字とパレットの挿入が、同じ履歴の上で混ざって扱われる
  （打つ→挿入→打つ、と交互にやっても順番どおりに戻れる）。

## やらないこと

- アプリ独自のUndoスタックを持つこと。ブラウザの履歴と二重になり、
  どちらが効くか予測できなくなる。まずネイティブの履歴を壊さない方法を探す。
- 文書をまたぐ履歴（[0004](0004-multi-document.md) の複数文書間で戻る）。

## メモ

- `document.execCommand('insertText')` を使うとネイティブ履歴を保てる。
  ただし**非推奨API**であり、0009ではこれを理由に採らなかった。採るかどうかが
  このissueの中心の判断になる。代替があるかを仕様の段階で調べること。
- React state を唯一の正としている構造（[アーキテクチャ](../architecture.md)）と
  どう折り合うかを決める必要がある。`execCommand` は DOM を直接変えるので、
  `onChange` 経由で state に戻す形になるはず。**未確認。**
- 受け入れ基準は実機検証になる。`page.keyboard.press('Control+z')` で
  textarea の値が戻ることを見る。
