# 0083: 式のラベルと参照を、既存の方言（Quarto / pandoc-crossref）で書けるようにする

- 状態: closed
- 起票日: 2026-09-22

## 背景

式の参照（[0044](0044-equation-numbers.md)）は `[(1)](#eq-名前)` と書く。
標準のMarkdownリンクを借りた形だが、**リンク文字列に書いた数字は描画のたびに
現在の番号で上書きされる**ため、`[(5)]` と書いても `(2)` と出る。
「書いた数字に意味がある」ように読め、**分かりづらいという指摘が出た**
（2026-09-22、ユーザー）。

一方、同じことをする記法は世の中にすでにある。

| 方言 | ラベル | 参照 |
|---|---|---|
| Quarto | `$$ … $$ {#eq-einstein}` | `@eq-einstein` |
| pandoc-crossref | `$$ … $$ {#eq:einstein}` | `@eq:einstein` |

**独自記法を発明せず、このどちらかに合わせる。** そうすれば「独自記法」ではなく
「既存方言への対応」になり、持ち出した先がQuartoやPandocなら**実際に動く**。

## やりたいこと

- 式に**ラベルを1回だけ書き**、本文からは**数字を書かずに**参照できるようにする。
- 採番・参照・飛び先の振る舞いは0044のまま（文書順に採番、参照を押すと式へ動く）。
- **既存の `\tag{名前}` と `[(1)](#eq-名前)` も読めること。** サンプル文書と
  算式記載ガイドが現行記法で書かれており、利用者の手元の文書も同じ。
- [R7](../requirements.md) の改訂。いまは「Markdownの書式に従わない独自記法は
  原則として採用しない」で、この対応はその例外になる。**例外にする理由**
  （発明ではなく既存方言に乗る／持ち出した先の劣化を承知で採る）を要求仕様に書く。

## やらないこと

- 定理・図表の番号（[0041](0041-theorem-blocks.md)・[0048](0048-geometry-figures.md)）。
  ただし**同じ仕組みで番号を振れる形にしておく**ことは仕様で意識する。
  `\tag` は数式にしか使えないので、方言に寄せる動機の半分はここにある。
- 書き出しのときの番号の焼き込み。[0082](0082-bake-equation-numbers.md)。
- HTML書き出し。[0050](0050-html-export.md)。

## メモ

- **持ち出した先での見え方は現行より悪くなる。** これは承知のうえで採る判断
  （2026-09-22、ユーザー）。逃げ道は0050のHTML書き出し。

  | 書き方 | GitHubに貼ると |
  |---|---|
  | 現行 `\tag{密度}` / `[(1)](#eq-密度)` | `(密度)` / `(1)` として読める |
  | 方言 `{#eq-密度}` / `@eq-密度` | **`{#eq-密度}` と `@eq-密度` がそのまま出る** |

- **綴りをどちらにするか**（`eq-` か `eq:` か）は仕様で決める。このエディタが
  作るアンカーは既に `id="eq-1"` なので、ハイフンのQuarto式のほうが揃う。
- **`$$` はMarkdown変換より前に退避される**（アーキテクチャ3節）。`{#eq-…}` は
  `$$` の外側に残るので、退避の前後どちらで拾うかを仕様で決める。
- 参照の描画を何にするかも決める（`(1)` か `式 (1)` か）。Quartoは
  `Equation 1` と出すが、日本語では「式 (1)」が自然。**表示言語で変わる**。
- **未確認**: QuartoとPandocの実際の出力（`@eq-…` が何と描かれるか、
  ラベルの位置の許容範囲）は手元で確かめていない。仕様を書く前に確かめる。
  合わせると言いながら細部が違うのがいちばん悪い。
