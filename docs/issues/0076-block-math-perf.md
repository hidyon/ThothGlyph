# 0076: ブロック数式の多い文書で入力が基準の50msを超える

- 状態: open
- 起票日: 2026-09-22

## 背景

[0044](0044-equation-numbers.md)（式の番号と参照）の検証で、番号付きの式を
含む長文の入力コストを測ったところ、**1文字あたり52.4ms**で
[N1](../requirements.md#3-非機能要求)の50msを超えた。

0044の実装が原因かを切り分けるため、**文書の長さを揃えて**3通り測った
（幅1440px・400節・3回ずつ・devcontainer内）。

| 文書 | 1文字あたり |
|---|---|
| 400節・400インライン数式（既存の `perf` 区分と同じ） | 38.5 / 39.4 / 39.9ms |
| 400節・ブロック数式100＋インライン300・本文あり（`\tag` なし） | 50.6 / 51.8 / 51.9ms |
| 同上に `\tag` 100件と参照100件を足したもの（0044を使う） | 50.4 / 50.4 / 51.4ms |

**0044の機能を使っても使わなくても同じ**で、効いているのは
**ブロック数式の密度**だった（インライン400件なら約39ms、うち100件を
ブロックに替えると約51ms）。0044より前からある性質で、`perf` 区分が
インライン数式だけの文書を測っていたために見えていなかった。

## やりたいこと

ブロック数式を多く含む文書でも、1文字あたりの入力反映を50ms以内に収める。

## やらないこと

- 基準を緩めること。[0059](0059-perf-headroom.md) と同じ理由で、緩めても
  体感は戻らない。
- ブロック数式の描画をやめること。

## メモ

- `perf` 区分の文書はインライン数式400件で、**ブロック数式が1つもない**。
  区分にブロック数式の多い文書を足すと、この性質を継続して見張れる。
- [0059](0059-perf-headroom.md)（追いつくまでの余裕）と原因が重なる可能性がある。
  どちらもサニタイズとDOMへの反映が効いている見込み。`katex-display` は
  インラインの `katex` より出力が大きい。
- 0044の検証（`eq-number` 区分）では、番号付きの式を25件に減らして
  1文字あたりの基準を見ている。**100件の版はこのissueの再現手順**として使える。
