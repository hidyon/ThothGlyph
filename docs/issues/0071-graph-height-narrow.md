# 0071: 狭い画面でグラフがプレビューの高さに収まらない

- 状態: open
- 起票日: 2026-09-21

## 背景

[0037](0037-graph.md) で入れたグラフは、**幅より高さが先に足りなくなる**。
幅540px・高さ720pxで `y = x^2` を描いたときの実測（日本語表示、サンプルではなく
グラフだけの文書）:

| 選んでいるタブ | パレットの高さ | プレビューのペイン | 図の高さ | 収まるか |
|---|---|---|---|---|
| Markdown（7件） | 100px | 285px | 274px | 収まる |
| 基本（23件） | 141px | 264px | 274px | **収まらない** |
| ギリシャ小文字（31件） | 141px | 264px | 274px | **収まらない** |
| 公式 | 177px | 246px | 274px | **収まらない** |

**パレットの高さは選んでいるタブで変わる**ので、収まるかどうかがタブで変わる。
記号の多いタブを選ぶと収まらないのは[0032](0032-palette-height-narrow.md)の蓋
（141px）に達したときからで、**0037の検証が通っていたのは初期表示のタブ（基本）が
偶然いちばん小さかったから**だった。[0070](0070-wide-accents.md)で基本が23件に
なり、初期表示でも収まらなくなって露出した。

プレビューは縦スクロールできるので**図には届く**（0070で `graph` 区分の基準を
「いちばん高いパレットでも縦スクロールで図の下端まで届く」に書き換えた）。
ただし**開いた瞬間は図の下が切れて見える**。

図の大きさは `renderGraph.ts` が**幅だけから決めている**（480×320pxを上限に、
ペインの幅に合わせて縮小する）。高さは見ていない。

## やりたいこと

- 狭い画面で**開いた瞬間に図の全体が見える**。スクロールしなくてよい。
- 図が小さくなりすぎない。0037で決めた**目盛りの文字11px以上**は守る。
- 広い画面（幅1440px）の図は今のまま（480×320px）。

## やらないこと

- **パレットの高さを変えること。** 0032の蓋（幅720px以下で141px）は
  それ自体が狭い画面のための対策で、これを緩めると別の場所が狭くなる。
- **図の縦横比を自由にすること。** 0037は480×320（3:2）で、
  目盛りの計算と凡例の配置がこの比に依っている。
- **グラフの中身を増やすこと**（[0038](0038-graph-series.md)・[0039](0039-graph-nice-ticks.md)）。

## メモ

- `renderGraph.ts` の3つの制約を先に読むこと（0037の引き継ぎ）:
  色と文字の大きさはCSSで当てる、`clipPath` は使わない、範囲外の点は打たない。
- **高さを見るには、描くときにプレビューのペインの高さが要る。**
  いまの `renderMarkdown` は純粋関数で、画面の寸法を受け取っていない。
  CSSだけで解く手（`max-height: 100%` と `viewBox` のまま縮める）があるかを
  先に調べるとよい。**SVGは `viewBox` があれば高さの制約だけで比を保って縮む。**
- 幅ごとの実測は上の表と、`graph` 区分の出力にある
  （幅540pxで図410×274px、幅375pxで327×218px、幅360pxで312×208px）。
- **目盛りの文字は図と一緒に拡大縮小される。** 図を小さくすると11pxを割る。
  幅360pxではすでに11.7pxで、**余裕は0.7px**（0037の実測）。
  つまり「縮める」方向には**ほとんど余地がない**。図を縮めるのではなく、
  **ペインの高さを増やす（狭い画面でプレビューを広く使う）**方向も検討する。
  [0022](0022-narrow-pane-switch.md)（狭い画面でソースとプレビューを切り替える）と
  合わせると、切り替えたときは全高が使えるので収まる。
