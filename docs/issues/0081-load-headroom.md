# 0081: スロットルなしの初期表示が基準250msに収まらない

- 状態: open
- 起票日: 2026-09-22

## 背景

`node scripts/measure-load.mjs` の「スロットルなしでtextareaまでが250ms以下」が
落ちるようになった。

| | 初期JS | 初期CSS | textareaまで（スロットルなし、3回の中央値） |
|---|---|---|---|
| [0079](0079-notation-guide.md) の前 | 270.51 kB | 10.81 kB | 250 ms / 250 ms（2回の実測） |
| 0079の後 | 272.20 kB | 12.00 kB | 322 / 261 / 256 / 253 ms（4回の実測） |

**基準の250msちょうどに張り付いていたところへ、0079が初期JSを1.7 kB・
初期CSSを1.2 kB足して越えた。** 0079が足したのはガイドのボタンとパネルの
骨組みだけで（954件のコマンド表は遅延チャンク側にある）、増分は小さいが、
余裕が無いところでは効く。

Fast 3G + CPU 4倍のほう（要求仕様N10、1500ms以下）は1079msで余裕がある。
落ちているのは**スロットルなしの250ms**だけで、これは要求仕様の数値ではなく
`measure-load.mjs` が持っている見張りの線。

## やりたいこと

次のどちらかを決めて、**落ちたままにしない**。

- 初期チャンクを削って250ms以下に戻す。
- 250msという線が今も妥当かを測り直し、妥当でなければ基準そのものを見直す
  （見直すなら、なぜその値かを `measure-load.mjs` と要求仕様に書く）。

## やらないこと

- 初期CSSの10 kB超過。それは [0073](0073-initial-css-size.md)（0079で
  10.81 → 12.00 kBになった）。

## メモ

- 実測は同じコンテナで連続して取った。**ばらつきが大きい**（0079の後で
  253〜322ms）ので、判断の前に `measure-load.mjs` を複数回流すこと。
- [0059](0059-perf-headroom.md) と同じ形の「基準に余裕がない」issue。
