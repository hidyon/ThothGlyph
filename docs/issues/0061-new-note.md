# 0061: 白紙のノートを始められない

- 状態: open
- 起票日: 2026-09-21

## 背景

新しい覚書を書き始めようとしたとき、**白紙にする手段が画面にない**。

いまツールバーにあるのは4つで、文書を置き換えるものは「サンプルに戻す」だけ。

| ボタン | 幅（1440px時） | すること |
|---|---|---|
| 言語: 日本語 | 109px | 表示言語の切り替え |
| テーマ: 自動 | 109px | テーマの切り替え |
| サンプルに戻す | 128px | 確認のうえ**サンプル文書**に置き換える |
| Markdownをコピー | 156px | 本文をクリップボードへ |

「サンプルに戻す」の確認は
`編集中の内容を破棄してサンプル文書に戻します。よろしいですか？` で、
OKすると**二次方程式のサンプル文書**が入る。白紙にはならない。

実際に白紙から書き始めるには、ソースの欄で **Ctrl+A → Delete** が要る。
初めて触る人がこれを思いつく理由はない。

## やりたいこと

- 新しいノートを白紙から書き始められる。
- 書きかけの内容を誤って消さない（いまの「サンプルに戻す」と同じく確認が要る）。
- 画面に足すものが、幅360pxで既存のものを溢れさせない。

## やらないこと

- 複数のノートを持つこと（[0004](0004-multi-document.md)）。本issueは
  「いま開いている1つを白紙にする」だけ。消えた内容を戻す話は
  [0023](0023-snapshot-recovery.md)。

## メモ

- **置き場所に余地がない。** 幅360pxで実測すると、
  - ツールバーは**ボタンの右端が350px**（画面幅360px）で、すでに2行になっている。
    5つ目は足せない（[0033](0033-toolbar-overflow-phone.md) の実測と同じ結論）。
  - ソースの見出し行のボタン3つ（`検索` / `ファイルに保存` / `ファイルを開く`）は
    **70〜344px** を占めており、4つ目の余地もほぼない
    （[0043](0043-find-replace.md) が「4つ目を足すときはまた測り直すこと」と
    書いているとおり）。
  - したがって **「サンプルに戻す」を置き換える・兼ねさせる**案が現実的。
    たとえば押したときに「白紙にする / サンプルに戻す」を選ばせる、
    あるいはボタン自体を「新しいノート」に変えてサンプルは初回訪問だけにする。
    **どれを採るかは仕様で決める。**
- サンプル文書は初回訪問の案内を兼ねている（[0040](0040-sample-graph.md) で
  グラフも入れた）。**サンプルへ戻る道をなくすなら、その役割の行き先を
  決めること。**
- 実機検証の複数の区分がサンプル文書の先頭行 `# 二次方程式の解の公式` に
  依存している。ボタンの意味を変えると `autosave` 区分（15件）の
  「サンプルに戻す（OK／キャンセル）」が影響を受ける。
