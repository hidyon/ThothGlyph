どちらもデータを足すだけなので軽い。ただし件数が増えるほど0011（検索）の

**これ以降に記号や公式を足すときは1行に両方書くだけで済む**。

**0037（関数のグラフ）は完了した。** ` ```graph ` のコードフェンスに `y = x^2 - 2x`

ブロックの解析（`graphBlock.ts`）・SVGの生成（`renderGraph.ts`）はいずれも
遅延チャンク側にあり、**初期チャンクへの影響は +0.80 kB**（エラー文言と

- **狭い画面の余白はもう詰まっている。** 幅360pxで図は312×208px、目盛りの文字は
  11.7px、左余白は14.0ユーザー単位しか残っていない。図に要素を足すissueは
  幅360pxで測り直すこと。
- **持ち出した先ではグラフにならない**（コードブロックとして式が残る）。
  この穴は0003（数式の画像書き出し）と合わせて埋める。
- **0040でサンプル文書にグラフを1つ入れた**（判別式の箇条書きの直後、$y = x^2 - 2x$）。

  これで `initial` 区分に初めてチェックが2件入った（0028の残りは見出し・数式の数）。
  **サンプル文書を変えるissueは、実機検証の複数の区分が先頭行
  `# 二次方程式の解の公式` に依存していることに注意する。**
- データ系列は0038、目盛りの値がきりの悪い数になる件は0039へ切り出した。
  0039は0037を実際に使って見つけたもので、`renderGraph.ts` の目盛りの計算を
  差し替えるだけで済む見込み。

**0041〜0051は「数式ノートを作る道具として何が足りないか」を利用者の立場から
洗い出して、まとめて起票したもの**（2026-09-20）。個別の思いつきではなく、
`書く → 見返す → 貯める → 使う` の流れで穴を並べた結果なので、**流れのどこを
埋めるかで選ぶとよい**。

| 流れ | 穴 |
|---|---|
| 書く | [0041](0041-theorem-blocks.md) 定理の囲み、[0045](0045-paste-image.md) 画像、[0046](0046-math-macros.md) マクロ、[0048](0048-geometry-figures.md) 幾何の図 |
| 見返す | [0042](0042-outline.md) 目次、[0043](0043-find-replace.md) 検索・置換、[0044](0044-equation-numbers.md) 式番号 |
| 貯める | [0004](0004-multi-document.md) 複数文書 → [0049](0049-note-list.md) 一覧 |
| 使う | [0013](0013-print-style.md) 印刷、[0050](0050-html-export.md) HTML書き出し、[0003](0003-image-export.md) 画像書き出し |

着手の順として勧めるのは **0004（複数文書）→ 0042（目次）→ 0041（定理の囲み）→
0044（式番号）→ 0013（印刷）**。0004はノートが1件しか持てない制約を外すもので、
ほかの多くがその上に乗る（0049は明示的に0004待ち）。0042は実装が小さく、
長いノートでの体感が大きい。

**依存と順序で気をつけるもの:**

- [0047](0047-macro-leak.md)（マクロの漏れ）は**不具合**で、`renderMarkdown` が
  純粋関数でなくなっているという設計上の問題でもある。[0046](0046-math-macros.md)
  （マクロの機能化）は0047を直した上に乗せる。
- [0045](0045-paste-image.md)（画像）と [0004](0004-multi-document.md)（複数文書）は
  **どちらも保存形式を変える**。別々にやると2回変えることになる。
- [0050](0050-html-export.md)（HTML書き出し）と [0013](0013-print-style.md)（印刷）は
  「画面のUIを外して本文だけにする」土台が重なる。
- [0048](0048-geometry-figures.md)（幾何の図）は0037の土台に乗るが、範囲を
  決めないと果てしない。数直線だけで始める手もある。
- **記法を伴うissue（0041・0044・0048）は、[R7](../requirements.md#r7-markdownとして正しく扱える)
  の方針に従うこと。** Markdownの書式に従わない独自記法は原則採用しない。
  標準の入れ物（見出し・引用・表・コードブロック・生のHTML）を借りるか、
  借りられないなら入れない。グラフ（0037）はコードブロックの言語名を借りている。
- [0051](0051-undocumented-syntax.md) は**現状の記述と実装の差を埋めるだけ**で、
  新しい記法は足さない。`<details>`・`\tag{1}`・外部URLの画像が、書かれていないのに
  動くことを実測で確かめてある。
