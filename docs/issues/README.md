## 着手順の目安

次の3件を優先する。理由は「壊れているものが先、それを安全に直す土台がその前」。

1. [0014](0014-unit-tests.md) 単体テストの土台 — 0006で正規表現に手を入れる前に、
   いま壊れていない変換を固定しておく。
2. [0006](0006-math-in-code.md) コードブロック内の `$` — 実機で確認した不具合。
   数式の書き方を説明する文書が書けない。
3. [0007](0007-preview-performance.md) 長い文書での重さ — 400節の文書で1打鍵あたり
   約1.2秒。長い文書では道具として成立していない。

そのあとは 0002（ダークモード）→ 0009・0008（編集の打鍵）→ 0004（複数文書）を
想定している。0004は0001の保存機構の上に乗るので、保存形式を変える0010より後が
やりやすい。この順序は拘束しない。着手するissueは毎回ユーザーと決める。
