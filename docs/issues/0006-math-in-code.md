# 0006: コードブロック内の `$` が数式として描画される

- 状態: closed
- 起票日: 2026-09-19

## 背景

インラインコード `` `$x^2$` `` やコードフェンス内の `$x_i$` が、コードとして
表示されず KaTeX で描画されてしまう。実機で確認した出力:

```html
<pre><code>sum <span class="katex">…x_i…</span> here</code></pre>
```

原因は `renderMarkdown.ts` の数式退避がMarkdownの構文を見ずに全文へ正規表現を
かけていること。数式をmarkedの前に退避するのは設計上の約束（`_` `*` `\` が
壊れるため）なので、退避そのものはやめられない。退避対象からコード部分を
除く必要がある。

数式エディタで「LaTeXの書き方」を説明する文書が書けないのは、用途からして痛い。

## やりたいこと

- インラインコードとコードフェンスの中の `$...$` が、そのままの文字列として
  表示される。
- 通常の本文中の数式はこれまで通り描画される（`$100 から $200` のような通貨表記を
  数式にしない現在の挙動も維持する）。

## やらないこと

- 数式記法そのものの拡張（`\(...\)` や `\[...\]` への対応）。別issueで検討する。

## メモ

- 実現案: (a) 退避の前にコード部分も同じ仕組みでプレースホルダへ逃がす、
  (b) markedのlexerでトークン列にしてからテキストトークンだけを対象にする。
  (a) の方が今の構造に馴染むが、`` ` `` の数を数えるなどMarkdownのコード記法を
  自前で解釈することになるので、仕様段階で取り違えを洗い出すこと。
- 正規表現を触るので、回帰を守るものが要る。[0014](0014-unit-tests.md)（テスト基盤）を
  先にやるか、同時に入れるかを仕様で決める。

## 結果（2026-09-19 クローズ）

コード領域（フェンスとインラインコード）を切り分け、その外側にだけ数式の
正規表現をかける形にした。フェンスの判定だけは行単位の走査（理由は
[仕様](../specs/0006-math-in-code.md) に追記）。

検証: `npm test` 32件すべて通過（0014で `it.fails()` にしてあった2件を
通常の `it()` に裏返し、入れ子のバッククォート・閉じないフェンス・チルダの
フェンス・コード前後の数式を足した）。実機でも18/18 OK、コンソールエラーなし。
