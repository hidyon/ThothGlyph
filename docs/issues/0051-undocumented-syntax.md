# 0051: 使える記法が機能仕様に書かれていない

- 状態: open
- 起票日: 2026-09-20

## 背景

実際に動かして確かめたところ、[機能仕様](../functional-spec.md)の
「対応する記法」に**書かれていないのに使えるもの**が少なくとも3つあった。

| 記法 | 実際の挙動 |
|---|---|
| `<details>` / `<summary>` | 折りたたみとして描画され、**中の数式も描画される** |
| `\tag{1}`（ブロック数式の中） | 式の右に番号が出る |
| `![図](https://…)` | 外部URLの画像が表示される |

とくに `<details>` は、練習問題と解答を1つのノートに書ける機能として実用的で、
「できることの一覧」に載っていないのはもったいない。

一方で、これらは**意図して入れたものではない**（markedとDOMPurifyとKaTeXが
通しているだけ）。書くなら「今後も壊さない」と決めることになるので、
**書くかどうかの判断が要る**。

## やりたいこと

- 上の3つについて、**対応する記法として書くか、書かないか**を決める。
- 書くと決めたものは機能仕様とREADMEに載せ、壊れたら気づけるようにする
  （単体テストか実機検証のどちらで守るかも決める）。
- 書かないと決めたものは、なぜ書かないかを記録する。

## やらないこと

- 新しい記法を足すこと。このissueは**現状の記述と実装の差を埋める**だけ。
- ローカル画像の対応。それは [0045](0045-paste-image.md)。

この3つは**いずれもMarkdownの標準の範囲**（生のHTML、LaTeXの `\tag`、画像）で、
[R7](../requirements.md#r7-markdownとして正しく扱える) の方針（独自記法は
原則採用しない）とも矛盾しない。載せる方向で検討してよい。

## メモ

- 調べ方は `renderMarkdown` を直接呼ぶ単体テスト（このissueの背景の表も
  その方法で確かめた）。
- `<details>` を正式に載せるなら、パレットの `Markdown` グループに雛形を
  足す価値がある（いま7件。[0037](0037-graph.md) でグラフを足したばかりで、
  **READMEの件数を固定している単体テストが落ちる**ので一緒に直すこと）。
- 他にも同じような「書いていないのに通る記法」がありうる（脚注、取り消し線、
  チェックボックス）。仕様を書くときに一度まとめて確かめること。
