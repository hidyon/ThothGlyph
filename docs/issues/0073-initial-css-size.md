# 0073: 初期CSSが基準の10 kBを超えている

- 状態: open
- 起票日: 2026-09-21

## 背景

[0024](0024-bundle-size.md) で初期バンドルを分けたとき、`scripts/measure-load.mjs` に
**初期CSSは10.00 kB以下**という基準を入れた。いまこれが落ちている。

```
初期CSS  index-CKySFXEQ.css  10.39 kB  gzip 2.76 kB
NG   初期CSSが 10.00 kB 以下 — 10.39 kB
```

**0.39 kB（4%）の超過。** gzip後は2.76 kBで、読み込み時間の基準
（スロットルなしでtextareaまで250ms、Fast 3G + CPU 4倍で1500ms）は
どちらも満たしている。**遅くなってはいないが、決めた線を越えている。**

`src/index.css` を触った直近のissueは
[0010](0010-scroll-sync.md)（スクロールの同期。ミラーの層）で、
その前は [0057](0057-resizable-panes.md)（仕切り）・
[0056](0056-palette-header.md)（パレットの見出し）・
[0054](0054-palette-placement.md)（縦帯）・
[0053](0053-palette-tab-icons.md)（タブのアイコン）。
**画面の作りを変えるissueが続いたぶん、少しずつ増えて越えた**と見える。

[0072](0072-sample-document.md)（サンプル文書の差し替え）の作業中に見つけた。
**0072の変更前でも同じ値**なので、0072とは無関係。

## なぜ気づかれなかったか

`measure-load.mjs` は **`verify-ui.mjs` とは別に手で流すもの**で、
issueをクローズするときの手順に入っていない。
[docs/test-spec.md](../test-spec.md) にも「読み込みに効くissueで使う」と書いてある。
CSSを増やすissueは「読み込みに効く」と意識されないので、流されなかった。

## やりたいこと

- `measure-load.mjs` が12件すべて通る。
- **どちらかを選んで、選んだ理由が残っている**:
  - CSSを10.00 kB以下に減らす（重複した宣言、使われていない規則を削る）
  - 基準を実態に合わせて上げる（gzip後の値で見る形に変えるなど）
- **CSSを増やすissueで気づける**ようになっている。

## やらないこと

- **見た目を変えること。** 減らすなら、描画結果が変わらない範囲で行う
  （`verify-ui.mjs` の429件とスクリーンショットで確かめられる）。
- **CSSの分割**（遅延読み込み）。0024で初期チャンクとの分け方は決めてあり、
  ここを動かすと0024の判断ごとやり直しになる。
- **読み込み時間の基準を変えること。** いまどれも満たしている。

## メモ

- `src/index.css` はいま**1行ずつ手で書いたもの**で、プリプロセッサもフレームワークもない
  （CLAUDE.mdの「状態管理ライブラリもUIフレームワークも入れない」の方針）。
  **減らすなら手で読んで削る**ことになる。行数は起票の時点で確認すること。
- 基準を上げる場合、**何を根拠に上げるのかを仕様に書く**こと。
  0024は「初期チャンクを小さく保つ」ためにこの線を引いた。
  gzip後2.76 kBという数字のほうが実態に近いなら、そう書き換える手もある。
- **`measure-load.mjs` を流す機会を増やす案**は [0025](0025-ci.md)（CI）と重なる。
  このissueで仕組みを作るなら、0025の範囲を先に決めること。
- 同種の「手で流すものが落ちたまま残る」問題として
  [0069](0069-flaky-timing-mark.md)（フレークの印）がある。
