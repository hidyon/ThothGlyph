# 0017: 検証スクリプトが育ちすぎている

- 状態: open
- 起票日: 2026-09-19

## 背景

`scripts/verify-ui.mjs` は377行・38チェック・実行21秒になった。
「前回までのチェックを消さない」というルールの帰結で、ルール自体は正しい
（0002の変更で既存23件が壊れていないことを確認できた）。

ただし1つのissueを検証するたびに全部を流すことになり、開発中の往復が重い。
このまま増えると、検証を省くほうへ流れてしまう。

## やりたいこと

- 検証したい区分だけを選んで流せる（例: テーマだけ、自動保存だけ）。
- 何も指定しなければ全件を流す（回帰の確認はこれまで通り）。
- チェックが増えても、どの区分に足すかが迷わない構造になっている。
- 実行時間が短くなる（とくに性能の検証は400節の文書を作るので重い）。

## やらないこと

- テストランナー（Playwright Test など）の導入。依存が増える。
  まず今のスクリプトの中で分けられるか見る。
- 検証の削除。通っているチェックを消して速くするのは本末転倒。

## メモ

- 区分の候補: 初期表示 / 自動保存 / コード内の`$` / 性能 / テーマ / レイアウト。
- 引数で選ぶ（`node scripts/verify-ui.mjs theme`）か、環境変数か。
- ブラウザの起動は1回で済ませ、区分ごとに状態を初期化する形が要りそう。
  いまは前の区分の副作用（localStorageの破壊、テーマの変更）が次に漏れている
  箇所があり、実行順に依存している。ここは分割の前に直すべきかもしれない。
- 性能の検証だけは時間がかかるので、既定から外す案もある。ただし外すと
  誰も流さなくなる恐れがある。仕様で判断する。
