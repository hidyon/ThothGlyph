# 0009: 選択範囲があるときの挿入の扱いを揃える

- 状態: open
- 起票日: 2026-09-19
- 更新日: 2026-09-19（[0014](0014-unit-tests.md) の作業中に前提の誤りが判明したため書き直した）

## 背景

起票時は「選択範囲がパレットの挿入で消える」と書いたが、誤りだった。
`insertSnippet.ts` は既に、スニペットに `%CURSOR%` が含まれていれば選択範囲を
その位置に包む（`x + 1` を選んで `\sqrt` → `\sqrt{x + 1}`）。この挙動は
[0014](0014-unit-tests.md) でテストとして固定した。

残っている問題は**挙動が記号によって割れる**こと。`palette.ts` の62件のうち
38件は `%CURSOR%` を持たない（`\alpha`、`\pi`、`\times` などの単体記号）。
これらを選択範囲がある状態で押すと、選択したテキストが記号に置き換わって消える。
記号を選んだつもりで書いた式が消えるのは、取り返しがつきにくい。

## やりたいこと

- 選択範囲があるとき、どの記号を押しても結果が予想できる。
  包める記号は包み、包めない単体記号では選択を失わない。
- 何が起きたかが取り消せる（Undoで戻せる、あるいは選択が保たれる）。

## やらないこと

- 複数の選択範囲（マルチカーソル）。textareaでは扱えない。
- 記号ごとに「どこに包むか」を利用者が設定できるようにすること。

## メモ

- 単体記号での候補: (a) 選択の直後に挿入して選択は消さない、(b) 選択を置き換える
  現在の挙動のままにする、(c) 単体記号にも包む場所を定義する（`\alpha` に
  包む意味はないので不自然）。仕様で決める。
- textareaの値をJSから書き換えるとブラウザのUndo履歴が切れる。Undoで戻せることを
  受け入れ基準に入れるなら、`document.execCommand('insertText')` などの
  代替手段を検討する必要がある（非推奨APIなので、採るかは仕様で判断する）。
- `insertSnippet` は純粋関数でテスト済みなので、変更の検証は `npm test` で足りる。
