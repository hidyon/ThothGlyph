# 0082: 持ち出した文書では式の番号が合っていない

- 状態: open
- 起票日: 2026-09-22

## 背景

式の自動採番（[0044](0044-equation-numbers.md)）は**このエディタの中だけ**で
効いている。ソースを持ち出すと次のようになる。

| ソース | このエディタ | 持ち出した先（GitHubなど） |
|---|---|---|
| `\tag{密度}` | 式の右に `(1)` | 式の右に **`(密度)`** |
| `式 [(1)](#eq-密度)` | 式 (1)（押すと飛ぶ） | **書いた数字のまま**（飛べない） |

`\tag` は本来「この文字列を出す」命令で、採番はしない。参照のほうも、
リンク文字列に書いた数字が描画のたびに現在の番号で上書きされる仕組みなので、
**上書きが効かない場所では、書いた数字がそのまま出る**。式を足し引きした
あとに持ち出すと、番号も参照もずれたまま配られる。

さらに**この `[(1)]` という書き方自体が誤解を招く**。`[(5)](#eq-mean)` と
書いても表示は `(2)` になる（現在の番号で上書きされるため）が、これは
「書いた数字に意味がある」ように読める。機能仕様の表もこの順で書いてあり、
読んだ人から**分かりづらい**という指摘が出た。

現状の `[(数字)]` の書き方は、**サンプル文書に4か所**（`sampleDocument.ts`、
日英それぞれ2か所）、**算式記載ガイドの第1部12項に4か所**（`guideDocument.ts`、
日英それぞれ2か所）ある。手本はこの2つしかない。

## やりたいこと

1. **書き出すときに番号を焼き込む。** `ファイルに保存` と `Markdownをコピー` で
   出るソースでは、`\tag{ラベル}` を `\tag{現在の番号}` に、参照を現在の番号の
   文字列に置き換える。持ち出した先でも番号が正しく読める状態にする。
2. **参照の書き方を、誤解しない形に変える。** `[(1)]` `[(5)]` のように
   「書いた数字に意味がありそうに見える」形をやめる。候補は下のメモ。
   **いま書かれている `[(数字)]` の文書も、引き続き読めること。**
3. **持ち出した先でのリンクは要らない。** 飛べないリンク（`#eq-1` は
   GitHubでは存在しないアンカー）を残すより、番号の文字だけにする。
4. **READMEに自動採番を載せる。** いまREADMEの「できること」に式の番号の
   行がなく、0044の存在が外から見えない。

## やらないこと

- 描画された形での書き出し。それは [0050](0050-html-export.md)（HTML書き出し）。
  番号もリンクも保たれるが、相手が編集できるMarkdownではなくなる。
- 章ごとの番号（`(2.1)`）と定理・図表の番号。[0041](0041-theorem-blocks.md)。
- 見出しへのリンク（`#見出し`）が飛べない件。[0042](0042-outline.md) と
  [0051](0051-undocumented-syntax.md) の範囲。

## メモ

- **焼き込みは一方通行**になる。`\tag{密度}` → `\tag{1}` でラベルが消えるので、
  書き出したファイルを読み込み直すと、そこから先は自動採番が効かない。
  「持ち出し用の写し」と割り切るのか、保存のときだけ焼くのか、別の導線
  （`番号を確定して書き出す`）にするのかは仕様で決める。
  **編集中の文書（localStorage）は焼かない**ことだけは先に決めておきたい。
- 書き出しの出口は2か所しかない（`lib/downloadName.ts` の `contentFor` と
  `Toolbar.tsx` の `clipboard.writeText`）。焼き込みは純粋関数1つで足りる。
  ラベル→番号の対応は `renderMarkdown` が既に持っている。
- 参照の書き方の候補（仕様で例を3件ずつ並べて決める）:
  - `[(#)](#eq-密度)` — `#` は番号の慣用記号。**数字を書かない**ので誤解がない。
  - `[(密度)](#eq-密度)` — ラベルをそのまま書く。ソースだけで「どの式か」が
    読め、焼かずに持ち出しても `(密度)` と意味が通る。いまは数字に
    置き換わらない（`(数字)` のときだけ置換する規則のため）ので規則を足すことになる。
  - `[式](#eq-密度)` — 番号を出さない既存の書き方。番号で指したい用途には足りない。
- **未確認**: GitHubが本文中の `id` を落とすこと、見出しからしか
  アンカーを作らないことは、手元で確かめていない（`<a id="…">` がこの
  エディタでは効くことは実測した）。仕様を書く前にGitHubで実際に確かめる。
