# 0035: READMEが開発者向けで、使う人に何ができるか伝わらない

- 状態: open
- 起票日: 2026-09-20

## 背景

[README.md](../../README.md) は28行で、内訳は
**見出し＋紹介4行／使い方4行／開発17行**。分量の大半が開発の手順で、
「このアプリで何ができるか」は冒頭の4行しかない。

そのうえ、書いてある内容が現在の姿と食い違っている。

| READMEの記述 | 現在の姿 |
|---|---|
| 「書いたソースはクリップボードにコピーして持ち出す」 | `.md` の書き出し（[0034](0034-file-save.md)）と読み込み（[0012](0012-file-io.md)）がある |
| 記号パレットの説明は「ボタンを押すと挿入」だけ | 記号7グループ88件（`src/lib/palette.ts` を数えた）に加え、公式12分類60件の挿入（[0018](0018-formula-library.md)・[0030](0030-formula-library-more.md)）と横断検索（[0011](0011-palette-search.md)）がある |
| （記載なし） | 自動保存（[0001](0001-autosave.md)）、ダークモード（[0002](0002-dark-mode.md)）、英語表示（[0031](0031-english-ui.md)） |
| コマンド表に4件（dev / build / lint / verify-ui） | 単体テスト `npm test`（[0014](0014-unit-tests.md)）が漏れている |

つまり**READMEだけを読んだ人は、保存されることも、ファイルを開けることも、
公式を検索して入れられることも分からない**。

## やりたいこと

- READMEの主役を「使う人」にする。開いて何ができて、どう書き始めるかが
  先に来るようにする。
- 現在の機能をもれなく、事実どおりに書く（上の表の食い違いを全部なくす）。
- 開発の手順は残す。このリポジトリで開発する人も読むため。ただし
  READMEでは入口までにして、詳しくは既存の文書（[CLAUDE.md](../../CLAUDE.md)、
  [docs/](../)）へ送る。

## やらないこと

- 画面のスクリーンショットをリポジトリに置くこと。置くと画面を変えるたびに
  撮り直しが要る（別issueで判断する）。
- 英語版のREADME。画面は英語に対応済み（0031）だが、リポジトリの文書は
  日本語で書く方針（CLAUDE.md「言語」）。
- `docs/` の4文書の内容をREADMEへ写すこと。二重管理になる。

## メモ

- 機能の一覧は [docs/functional-spec.md](../functional-spec.md) が正。
  READMEはその要約であり、詳細は書かない。
- リンクはリポジトリ内の相対パスで書く（GitHubでもVSCodeでも辿れる）。
- 件数は実データを数えた: **記号7グループ88件・公式12分類60件**（パレットのタブは
  記号7つ＋`公式` で8つ）。起票の初版に「8タブ・記号122件」と書いたのは推測で、
  数えて直した（CLAUDE.md「推測で書かず実際にファイルや画面を見てから書く」）。
