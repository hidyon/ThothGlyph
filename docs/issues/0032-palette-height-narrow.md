# 0032: 狭い画面でパレットが画面の3割を占める

- 状態: open
- 起票日: 2026-09-19

## 背景

[0030](0030-formula-library-more.md) の検証で、幅600px・高さ900pxの画面を
実測した結果:

| 要素 | 高さ |
|---|---|
| パレット（公式タブ・ベクトル分類） | **279px** |
| うち1段目のタブ | 2行 |
| うち2段目のタブ（12分類） | 2行 |

画面の高さの **31%** をパレットが占める。ツールバーも合わせると、
ソースとプレビューに使える領域は残り6割ほどになる。

高さ667pxのスマートフォンなら **42%** になる計算で、
[0022](0022-narrow-pane-switch.md)（狭い画面で上下2分割になり数行しか見えない）を
さらに悪くする。

増えた経緯は記録に残っている。[0018](0018-formula-library.md) で公式タブを入れた
時点で幅600pxのパレットは207px、[0029](0029-greek-complete.md) でタブが1つ増え、
0030で2段目が6→12分類になって2行に折り返した。**1件ずつは小さいが、
足すたびに高くなる。**

## やりたいこと

- 狭い画面で、パレットが編集領域を圧迫しない。
- パレットを使いたいときには使える（隠して終わりにしない）。
- 記号や公式をこれ以上足しても、高さが際限なく伸びない構造になっている。

## やらないこと

- 記号や公式を減らすこと。[0029](0029-greek-complete.md)・0030 で足したばかりで、
  減らすのは本末転倒。
- 広い画面での見せ方を変えること。幅1440pxでは136〜148pxで収まっており、
  困っていない。

## メモ

- 案の候補:
  - 狭い画面ではパレットを**折りたたむ**（見出しだけ出して、押すと開く）
  - タブを折り返さず**横スクロール**にする（0030の仕様では折り返しを選んだが、
    2行になるなら前提が変わる）
  - パレット自体を縦スクロールにして高さの上限を決める
- [0022](0022-narrow-pane-switch.md)（狭い画面でのペイン切り替え）と
  同じ画面の話なので、**一緒に考えるほうがよい**可能性がある。
  0022を先にやってから測り直すと、本当に困る高さか分かる。
- [0011](0011-palette-search.md)（検索）が入ると、タブを辿らずに目的の記号へ
  行けるようになる。そうなればタブの行数の重みは下がる。
  **0011が先なら、このissueは小さくなるかもしれない。**
- 広い画面（1440px）での実測: ギリシャ小文字136px、ギリシャ大文字94px、
  公式148px。狭い画面だけの問題である。
