# 0010: スクロール同期と編集位置の復元

- 状態: open
- 起票日: 2026-09-19

## 背景

左右のペインのスクロールが独立している。長い文書では、編集している段落が
プレビューのどこにあるのか探すことになる。

また [0001](0001-autosave.md) で内容は復元されるようになったが、スクロール位置と
カーソル位置は先頭に戻る。長い文書では「どこまで書いたか」を毎回探し直す。

## やりたいこと

- エディタをスクロールすると、プレビューの対応する位置が一緒に動く。
- **プレビューをスクロールすると、エディタの対応する位置も動く**（双方向。
  2026-09-20に追加）。
- リロードしても、直前に見ていた位置と編集していたカーソル位置から再開できる。

## やらないこと

- （2026-09-20に変更）**双方向を範囲に入れた。** もともとは「プレビュー側から
  エディタへの逆方向の同期」をやらないことにしていたが、読み返しながら直す
  使い方では逆方向のほうが要る場面が多いため、両方向を範囲にする。
  片方向で始めるかどうかは仕様で決める（下書きの仕様は片方向で書いてある）。

## メモ

- **下書きの仕様（[docs/specs/0010-scroll-sync.md](../specs/0010-scroll-sync.md)）は
  片方向で書いてある。** 双方向にするには、`data-line` の対応づけを逆に引く
  （プレビューの見えている先頭要素の `data-line` からソースの行へ）ことと、
  **同期のループを止める仕組み**（動かされた側が動かし返さない）が要る。
  承認を取り直すときに、ここを仕様へ足すこと。

- 行と出力の対応づけが要る。割合（スクロール量の比）で合わせる簡易版と、
  markedのトークンに行番号を持たせて要素へ埋める方式がある。前者は数式や
  表で大きくずれる。仕様でどちらを採るか決める。
- カーソル位置の保存先は0001の `matheditor:document:v1` を拡張するのが自然。
  `version` を上げるか、後方互換に足すかを仕様で決めること。
