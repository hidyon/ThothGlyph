# 0086: 幅に関わる検証を1つの区分にまとめ、既定では流さない

- 状態: closed
- 起票日: 2026-09-22

## 背景

**画面の寸法は個々のissueで測らず、機能をいくつか作ってから調整のissueでまとめて
合わせる**方針になった（2026-09-22、ユーザー。[振り返り](../retrospectives/2026-09-22.md)）。

ところが実機検証には**幅を指定したチェックが各区分に散らばっている**。
要素を1つ足して狭い幅で溢れた瞬間にそれらが落ち、`verify-ui.mjs` は
**終了コード1**で終わる。調整を後回しにする間、全区分がずっと赤になり、
**本物の回帰が埋もれる**（0083でフレークと回帰の区別に全区分を5回流した）。

散らばり方の実測（2026-09-22、ラベルに幅の数値を含むチェックを数えた）:

| 区分 | `setViewportSize` の回数 | 幅を含むチェック |
|---|---|---|
| placement | 5 | 18 |
| palette-height | 5 | 14 |
| guide | 8 | 11 |
| layout | 4 | 8 |
| palette-stats | 4 | 8 |
| palette-decor | 7 | 8 |
| search | 5 | 6 |
| eq-number | 4 | 5 |
| tab-icon | 3 | 5 |
| panes / scroll / name / initial / greek / icon ほか | 各2〜4 | 各1〜4 |
| **合計（22区分）** | **83** | **106** |

全チェックは511件（`check(` の数）なので、**およそ5分の1が幅に依存**している。

## やりたいこと

- **幅に関わるチェックを1つの区分に集める**（名前は仕様で決める）。
- その区分は**引数なしの実行では流さない**。名前を指定したときだけ流す。
  いまは「引数なしなら全区分」なので、**既定では流さない区分**という概念を
  `verify-ui.mjs` に足すことになる。
- 集めた後も、**チェックの判定と文言は変えない**（0027の約束。印や実行の仕方を
  変えるだけで、判定は緩めない）。

## やらないこと

- 幅のチェックを**消すこと**。回帰に気づける状態は保つ（調整のissueで流す）。
- 要求仕様のN5/N9/N11（狭い画面での保証）の削除。**満たす時期が変わるだけ**で、
  要求そのものは残る。文言は仕様で調整する。
- レイアウトの調整そのもの。それは別issue（この区分が赤くなったときに立てる）。

## メモ

- **区分をまたいで移すと、その区分の文脈（文書の用意・言語の切り替え）も一緒に
  要る**。たとえば `palette-height` の幅のチェックは、公式タブを開いた状態が前提。
  **機械的な移動では済まない**ので、仕様で移す単位を決めること。
- `docs/test-spec.md` の区分表と件数、CLAUDE.mdの「幅に関わる検証も既定では
  流さない」の参照先もこのissueで揃える。
- 0079で足した `guide` 区分は、31件中11件が幅に依存している（いちばん新しい例）。
