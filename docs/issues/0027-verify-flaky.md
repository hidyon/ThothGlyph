# 0027: 検証スクリプトの結果が再現しないことがある

- 状態: open
- 起票日: 2026-09-19

## 背景

[0026](0026-typescript-strict.md) をマージした直後、`node scripts/verify-ui.mjs` が
**1回だけ 42/43 で落ちた**。直前と直後は 43/43 で通っている。

**どのチェックが落ちたかは分かっていない。** 実行時に出力を `tail -2` で
切っていたため、`NG` の行を取り逃がした。その後、単独で5回・`npm run build` と
同時に7回、合わせて12回流したが再現していない。

0026の変更は `tsconfig` 2ファイルと文書だけで `src/` に触れていないため、
この失敗が0026によるものとは考えにくいが、**証拠がないので断定できない**。

問題は落ちたこと自体ではなく、**落ちたときに何も残らないこと**である。
いまの出力は「n/m 件 OK」と各行の `OK` / `NG` を流すだけなので、
画面を閉じれば失われる。件数だけを見て通したことにすると、フレークと
本物の回帰を区別できない。

## やりたいこと

- 検証が落ちたとき、**どのチェックがどんな値で落ちたかが後から読める**形で残る。
- タイミングに依存するチェックがどれかが、スクリプトを読めば分かる。
- 同じ検証を繰り返して揺れの有無を確かめる手段がある。
- 揺れているチェックを「たまに落ちるもの」として放置しない
  （直すか、判定の仕方を変えるかを選べる状態にする）。

## やらないこと

- 落ちたチェックを自動で再試行して成功扱いにすること。揺れを隠すだけで、
  本物の回帰を見逃す側に倒れる。
- 閾値をゆるめて通るようにすること。[0007](0007-preview-performance.md) で
  決めた数値（1文字あたり50ms、追いつき1.5秒）は要求そのものなので、
  再現しない失敗を理由に動かさない。
- 検証の削除。[0017](0017-verify-script-structure.md) と同じ方針。

## メモ

- **タイミングに依存するチェックの候補**（`scripts/verify-ui.mjs` を読んで拾った）:

  | 行 | チェック | 依存しているもの |
  |---|---|---|
  | 96 | 入力直後は保存中と出る | デバウンスより先に読めるか |
  | 128 | 即リロード前は未保存（保存中） | 同上 |
  | 244 | 長文での入力反映が1文字あたり50ms以内 | マシンの負荷 |
  | 253 | 入力を止めてから1.5秒以内に追いつく | 同上 |
  | 264 | 短い文書では更新中が残らない | `waitForTimeout(300)` の固定待ち |
  | 341/357 | 初期表示のちらつき | 16ms間隔で12回読む取りこぼし |

  このうちどれが実際に揺れるかは**測っていない**。繰り返し実行で確かめること。
- [0017](0017-verify-script-structure.md)（区分けして速くする）と同じファイルを触るが、
  目的が違う。0017は「速く・選んで流す」、こちらは「結果を信じられるようにする」。
  どちらを先にやるかは仕様で相談する。同時にやるほうが手戻りが少ない可能性もある。
- 残し方の候補: 結果をJSONで `tmp/` に書き出す、`NG` の行だけ最後にまとめて
  再掲する、終了時に落ちたチェックの実測値を一覧にする。
- 0025（CI）を入れるなら、CIで落ちたときにこそこの記録が要る。
  手元と違ってその場で再実行できないため。
- 起票のきっかけになった失敗そのものは、**再現しないまま記録だけ残している**。
  このissueで仕組みを入れたあと、また落ちたときに初めて中身が分かる。
