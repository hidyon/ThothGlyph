# 0025: CIがない

- 状態: open
- 起票日: 2026-09-19

## 背景

リポジトリに `.github/` がない。`npm test`・`npm run build`・`npm run lint`・
`node scripts/verify-ui.mjs` は、すべて**手で流している**。

CLAUDE.mdは「受け入れ基準を実際に動かして確認する」と決めていて、いままでは
守られている。ただし守られていることを保証しているのは手順の記憶だけで、
流し忘れても誰も気づかない。issueが増えるほど、また
[0017](0017-verify-script-structure.md) で検証を区分けして部分実行できるように
するほど、「全部は流さなかった」が起きやすくなる。

## やりたいこと

- プッシュ（あるいはマージ）のたびに、単体テスト・型チェック・Lintが自動で流れる。
- 実機検証も自動で流れる（開発サーバの起動を含む）。
- 落ちたことが、マージする前に分かる。
- ローカルで流すのと同じコマンド・同じ結果になる（二重管理にしない）。

## やらないこと

- デプロイ。このアプリはまだ配布先を決めていない。
- カバレッジの計測と閾値。[テスト仕様](../test-spec.md)は「件数ではなく
  この関数が壊れたら気づけるか」で判断すると決めている。数値目標は入れない。

## メモ

- 実機検証はChromiumと開発サーバが要る。devcontainerの構成
  （`.devcontainer/`）とCIの環境をどう揃えるかが要点。同じDockerfileを
  使い回せるかは**未確認**。
- `scripts/verify-ui.mjs` は `VERIFY_URL` を環境変数で受けるので、
  CIからは別ポートでも流せるはず。**未確認。**
- 検証は起票時点で21秒（[0017](0017-verify-script-structure.md) の実測）。
  CIで毎回流して許容できる長さかを仕様で判断すること。
- スクリーンショットをCIの成果物として残すかどうかも決める。
  「スクリーンショットを実際に見る」というCLAUDE.mdの約束は人間がやることなので、
  CIが代わりに見てくれるわけではない。
