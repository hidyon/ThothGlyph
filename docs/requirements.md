# 要求仕様

> **更新のタイミング**: 道具の目的や対象読者が変わったとき。機能を1つ足すたびには
> 更新しない（それは [機能仕様](functional-spec.md)）。

現在の実装を正として書く。未実装のものは「今はない」とissue番号を添える。

## 1. 誰のための道具か

**この道具の名前は `ThothGlyph`（トトグリフ）。** 文字を発明した書記の神
トトと、刻まれた記号を意味する glyph を合わせた名前。書くことと数えることの
両方を指している。由来は [README](../README.md#名前) に書いた。

**表記は `ThothGlyph`。T と G を大文字にし、他は小文字。** 日本語表記は
「トトグリフ」だが、**画面にはラテン文字の `ThothGlyph` だけを出す**
（固有名詞なので翻訳しない）。ただし **npm のパッケージ名と localStorage の
キーは小文字の `thothglyph`**（npmが大文字を許さないため）。
「数式エディタ」「matheditor」は種別の説明であって名前ではない
（[0065](issues/0065-app-name.md)）。

**数式を含むMarkdownを書く人**のための、ブラウザで動くエディタ。想定しているのは
講義ノート、技術メモ、解説記事を書く場面で、LaTeXの数式が文章に混ざるもの。

書いた成果物は**このアプリの外へ持ち出して使う**。アプリは編集と確認の場であって、
文書の最終的な置き場所ではない。

## 2. 満たすべき要求

### R1. 書いた数式がその場で見える

LaTeXは書いただけでは読めない。入力と並べて、描画された数式を見せる。
**入力途中の壊れた数式でプレビューが消えてはならない。** 書いている最中の数式は
ほとんどの時間が「壊れている」状態であり、そこで表示が消えると編集できない。

### R2. 数式のコマンドを覚えていなくても書ける

`\int` や `\alpha` を覚えていない人でも、記号を選んで挿入できる。
挿入後は続きを書くべき位置にカーソルがある。
**式のかたまり（解の公式、余弦定理など）も名前で選んで挿入できる**
（[0018](specs/0018-formula-library.md)）。記号を1つずつ組み立てられない人ほど
必要になるため。
**記号を挿入しても、選択していたテキストが失われてはならない。**
記号を選んだつもりで書いた式が消えるのは取り返しがつきにくい
（[0009](specs/0009-wrap-selection.md)）。
**直したい式は、ソースから探さずに指せる。** 描画された数式をクリックすると
ソースのその中身が選ばれ、そのままパレットで編集できる
（[0020](specs/0020-preview-click-to-edit.md)）。長い文書ほど、目で探して
カーソルを移す往復が重い。
**パレットに無いものは、書きながら調べられる。** パレットで入るのは用意した
記号と公式だけで、そこから外れると手が止まる。書ける記法の早見とKaTeXの
対応コマンドの一覧を、編集を中断せずに開けるようにする
（[0079](specs/0079-notation-guide.md)）。

### R3. 書いたものが消えない

タブを閉じる、リロードする、ブラウザが落ちる、のいずれでも内容が残る。
保存のための操作を求めない。保存されたことが利用者に見える。

保存はブラウザ内（localStorage）で完結する。サーバもアカウントも持たない。

### R4. 書いたものを持ち出せる・持ち込める

Markdownソースをクリップボードにコピーできる。
手元の `.md` ファイルは、ボタンかドラッグ＆ドロップで開ける
（`.md` / `.markdown` / `.txt`、1MBまで、一度に1件。
[0012](specs/0012-file-load.md)）。置き換える前に確認が出る。
編集中の内容は `.md` ファイルとして書き出せる（名前は先頭の見出しから作る。
[0034](specs/0034-file-save.md)）。書き出したファイルはそのまま開き直せる。
数式の画像書き出しも今はない（[0003](issues/0003-image-export.md)）。

### R5. 長時間見ても目が疲れない

OSのテーマ設定に従い、暗い環境では暗い配色で表示する。手動でも選べ、選択は
次回訪問時にも保たれる。ダークでも数式・コード・引用・表が読める
（本文と背景のコントラスト比4.5:1以上）。

### R6. 日本語が読めなくても使える

画面の文字を日本語と英語で切り替えられる。選択は次回訪問時にも保たれる。
初回訪問ではブラウザの言語設定から選ぶ。`<html lang>` が表示中の言語と一致する。
**利用者が書いた文書は翻訳しない**（言語を切り替えても編集中の内容は変わらない）。

### R7. Markdownとして正しく扱える

数式記法（`$`）とMarkdown記法が互いを壊さない。とくに:

- LaTeXの `_` `*` `\` がMarkdownの強調として解釈されない。
- コードブロックの中の `$` は数式にならない（LaTeXの書き方を説明できる）。
- `$100` のような通貨表記が数式にならない。

**Markdownの書式に従わない独自記法は、原則として採用しない。**
書いたものは[外へ持ち出して使う](#r4-書いたものを持ち出せる持ち込める)ので、
独自記法は持ち出した先で「読めないゴミ」になる。機能を足すときは、
**Markdownに既にある入れ物を借りる**か、借りられないなら諦める。

判断の順序:

1. Markdownの標準的な記法で書けないか（見出し、引用、表、コードブロック、生のHTML）。
2. 書けないなら、標準の入れ物に中身を載せられないか。
   グラフ（[0037](specs/0037-graph.md)）は**コードブロックの言語名**という
   標準の場所を借りている。持ち出した先ではグラフにならないが、
   コードブロックとして式が読める形で残る。
2.5. それも無理なら、**同じことをする既存の方言に綴りを合わせられないか**
   （[0083](specs/0083-crossref-dialect.md)）。**記法は発明しない。**
   合わせた先（Quarto・Pandoc）では実際に動き、そうでない場所でも
   「何の記法か」を調べられる。**持ち出した先での劣化**
   （`{#eq-density}` や `@eq-density` が文字として出る）は承知のうえで採る。
   完全な形で渡す道は [0050](issues/0050-html-export.md)（HTML書き出し）に置く。
3. どれも無理なら、その機能は入れない（または記法を伴わない形に作り替える）。

この方針は既存のissueにも効く。記法を伴う提案（[0041](issues/0041-theorem-blocks.md)
定理の囲み、[0048](issues/0048-geometry-figures.md) 幾何の図）は、仕様の時点で
**上の1と2を通ったことを書く**こと。

**式の番号と参照はこの順序を通した例。** [0044](specs/0044-equation-numbers.md) では
LaTeXの `\tag{名前}` とMarkdownのリンク `[(1)](#eq-名前)` という標準の道具を
2つ借りた（1と2）。だが**リンク文字列の数字が描画のたびに上書きされる**ため、
「書いた数字に意味がある」と読めてしまい、分かりづらかった。
[0083](specs/0083-crossref-dialect.md) で 2.5 へ進み、Quartoの綴り
（`$$ … $$ {#eq-ラベル}` と `@eq-ラベル`）に合わせた。
**[0085](specs/0085-drop-old-equation-notation.md) で旧記法を落とし、記法は1通りにした**
（2通りを抱えると実装・テスト・検証・文書が二重になる）。

## 4. 扱わないこと

意図して持たない性質。issueとして起票していないものを含む。

- **サーバ、アカウント、同期。** 保存はブラウザ内で完結する。
- **共同編集。** 1人が1つのブラウザで書く。
- **WYSIWYG編集。** ソースを書く道具であり、プレビューは読み取り専用。
- **Markdown以外の入力形式**（Word、HTMLからの取り込みなど）。
- **PWA（オフライン動作）。** アイコンとmanifestは置くが、Service Workerは持たない。
- **数式記法の独自拡張。** KaTeXが解釈するLaTeXの範囲に従う。
- **Markdownの独自拡張。** 上のR7を見よ。標準の入れ物を借りるか、入れない。
